# План исправления T3Float.FromDouble()

## Проблема

[`T3Float.FromDouble()`](src/TritTypes/T3Float.cs:51) выбирает exponent так, что `|mantissa| ≈ 1`.
Это не использует 12 тритов мантиссы, давая огромную ошибку для нецелых значений.

**Пример для 3.14:**
- Текущее: `exp=1, mant=1 → 3.0` (ошибка **0.14**)
- Оптимальное: `exp=-10, mant=185414 → 3.14000237` (ошибка **0.000002**)

## Формат T3Float

```
Word18 (18 тритов, balanced ternary):
  Позиции 12-17: exponent (6 тритов, balanced, bias=182)
  Позиции 0-11:  mantissa (12 тритов, balanced)
  Кодирование: word18 = exponent * 3^12 + mantissa (линейное)
  Значение: mantissa * 3^(exponent - 182)
```

**Диапазоны:**
- `exponent`: 6 тритов, `[-364, +364]`, bias=182 → `[-182, +182]`
- `mantissa`: 12 тритов, `[-265720, +265720]`
- `3^12 = 531441`

## План изменений

### 1. T3Float.FromDouble() — новая нормализация

```csharp
public static T3Float FromDouble(double value)
{
    if (value == 0) return new T3Float(182, 0);
    
    double absVal = Math.Abs(value);
    int sign = value < 0 ? -1 : 1;
    
    // Найти минимальный exponent, при котором |mant| ≤ 265720
    // exp = floor(log3(|value| / 265720))
    double log3val = Math.Log(absVal, 3);
    double log3maxMant = Math.Log(265720, 3); // ≈ 11.34
    int exp = (int)Math.Floor(log3val - log3maxMant);
    
    // Ограничить exponent диапазоном 6 тритов [-182, +182]
    if (exp < -182) exp = -182;
    if (exp > 182) exp = 182;
    
    // Вычислить мантиссу с максимальной точностью
    long mantissa = (long)Math.Round(absVal / Math.Pow(3, exp));
    
    // Ограничить мантиссу диапазоном 12 тритов
    if (mantissa > 265720) { mantissa = 265720; }
    if (mantissa < -265720) { mantissa = -265720; }
    
    // Применить знак
    mantissa *= sign;
    
    return new T3Float(exp + 182, mantissa);
}
```

### 2. T3Double.FromDouble() — аналогичное исправление

Та же проблема, 28 тритов мантиссы (`maxMant ≈ 3^28 / 2`).

### 3. Тесты

Добавить проверку точности для ключевых значений:
- `3.14` → ошибка < 0.00001 (сейчас 0.14)
- `2.71` → ошибка < 0.00001 (сейчас 0.29)
- `0.1` → ошибка < 0.00001 (сейчас 0.011)
- Целые числа → без изменений (ошибка 0)

## Риски

1. **Регрессия в симуляторе** — тесты FPU могут ожидать старые значения.
2. **Совместимость с сохранёнными данными** — Word18-кодирование меняется для нецелых значений.
3. **Производительность** — дополнительный `Math.Log` и `Math.Pow` в `FromDouble()`.
