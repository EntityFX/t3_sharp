## 1. Введение

Процессор **T3** — семейство троичных вычислительных ядер с единой системой команд, работающих в сбалансированной троичной системе счисления.  
Поддерживаются две конфигурации разрядности (27 и 54 трита) и две микроархитектуры: простая последовательная (in‑order) и высокопроизводительная VLIW с предикацией, спекулятивным выполнением и SIMD.

Настоящий документ содержит полное описание архитектуры, системы команд, модели времени, подсистемы ввода‑вывода и программного интерфейса симуляторов на языке C#.

## 2. Базовые типы и форматы данных

### 2.1. Трит, трайт, слово
- **Трит** (`trit`) — минимальная единица информации, значения –1, 0, +1. Обозначается символами `-`, `0`, `+`.
- **Трайт** (`tryte`) — 6 тритов, минимальная адресуемая ячейка памяти. Диапазон: –364 … +364.
- **Слово**:
  - **T3‑27** — 27 тритов (адресация пословная).
  - **T3‑54** — 54 трита (9 трайтов). В VLIW‑режиме слово вмещает три 18‑тритных слота.

### 2.2. Представление чисел
Числа хранятся в сбалансированной троичной системе. Отрицательные значения — естественным образом (старший трит `-`).  
Диапазоны:
- T3‑27: ±(3²⁷−1)/2 ≈ ±3.8·10¹²
- T3‑54: ±(3⁵⁴−1)/2 ≈ ±2.9·10²⁵

## 3. Регистровая модель

### 3.1. Физические регистры
- **27 общих регистров** `R0 … R26` разрядностью в слово.
- **Специальные регистры:**
  - `SP` — указатель стека (слово)
  - `PC` — счётчик команд (слово)
  - `Cond` — флаг условия (1 трит, хранится в младшем трите специального регистра, остальные триты — 0)
  - `PR` — предикатный регистр (27 тритов), 9 флагов по 3 трита: `p0 … p8`. Каждый флаг принимает значения –1 (ложь), 0 (может), +1 (истина).

### 3.2. Регистровое окно и вызовы функций
Логические имена `A, B, C, D, E, F, G, H, I` отображаются на непрерывный блок из 9 физических регистров, начиная с `WP` (Window Pointer, 0…26).  
При вызове подпрограммы (`CALL`) процессор автоматически сдвигает окно:

1. Сохраняет в стеке текущие `PC` и `WP`:
   ```
   SP = SP - 2
   mem[SP] = PC_old
   mem[SP+1] = WP
   ```
2. Сдвигает окно: `WP = (WP + 4) mod 27`
3. Переходит по адресу, указанному в регистре.

После сдвига старые `A…D` становятся `E…H` вызываемой функции, обеспечивая передачу до 4 параметров без дополнительных копирований.  
Возврат (`RET`) восстанавливает `PC` и `WP` из стека:
```
PC = mem[SP]
WP = mem[SP+1]
SP = SP + 2
```

Глубина вложенности ограничена 6 вызовами при циклическом переиспользовании регистров. Для более глубокой вложенности необходимо программное сохранение окон.

## 4. Память и адресация

- Память адресуется словами. Объём физической памяти в симуляторе — 1М слов (1 048 576 слов).
- Стек растёт вниз, `SP` указывает на вершину. При старте `SP = MemSize - 1`.
- Режимы адресации:
  - **Регистровая** – `ADD A, B`
  - **Непосредственная** – `LI A, 100`
  - **Косвенная** – `LOAD A, B` (адрес в B)
  - **Длинная непосредственная** – `LIMM A, 1000000` (значение в следующем слове)

## 5. Система команд (ISA)

### 5.1. Формат инструкции
**Базовый формат (27‑тритное слово):**

| Поле      | Разрядность | Описание |
|-----------|-------------|----------|
| opcode    | 6 трит      | Код операции (0…44) + pred_index * 28 |
| pred      | (внутри opcode) | Индекс предиката: 0 – безусловно, 1…8 – флаги p1…p8 |
| operand1  | 9 трит      | Регистр (0…8 = A…I) или непосредственное значение |
| operand2  | 9 трит      | Аналогично |

**VLIW‑слот (18 трит, только T3‑54):**

| opcode (6 трит) | op1 (6 трит) | op2 (6 трит) |

### 5.2. Таблица опкодов

| Код | Мнемоника | Описание |
|-----|-----------|----------|
| 0 | `HALT` | Останов процессора |
| 1 | `LOAD` | `reg = mem[addr_reg]` |
| 2 | `STORE` | `mem[addr_reg] = reg` |
| 3 | `MOV` | `reg1 = reg2` |
| 4 | `LI` | `reg = imm9` (или imm6 в VLIW) |
| 5 | `LIMM` | `reg = mem[PC]`, PC+=1 (следующее слово) |
| 6 | `ADD` | `reg1 += reg2` |
| 7 | `SUB` | `reg1 -= reg2` |
| 8 | `MUL` | Умножение |
| 9 | `DIV` | Деление, округление к –∞ |
| 10 | `MOD` | Остаток |
| 11 | `NEG` | `reg = -reg` |
| 12 | `TRITAND` | Потритовый минимум |
| 13 | `TRITOR` | Потритовый максимум |
| 14 | `TRITXOR` | Потритовая сумма по модулю 3 |
| 15 | `SHL` | Сдвиг влево (умножение на 3^op2) |
| 16 | `SHR` | Арифметический сдвиг вправо |
| 17 | `CMP` | `Cond = sign(reg1 - reg2)` |
| 18 | `JMP` | `PC = reg` |
| 19 | `JE` | Переход, если `Cond == 0` |
| 20 | `JNE` | `Cond != 0` |
| 21 | `JL` | `Cond < 0` |
| 22 | `JG` | `Cond > 0` |
| 23 | `JM` | Переход по maybe (`Cond == 0`) |
| 24 | `CALL` | Вызов подпрограммы |
| 25 | `RET` | Возврат |
| 26 | `PUSH` | Положить регистр в стек |
| 27 | `POP` | Извлечь из стека в регистр |
| 28 | `SPEK` | Начать спекулятивный блок (только VLIW) |
| 29 | `COMMIT` | Подтвердить спекуляцию |
| 30 | `ROLLBACK` | Откатить спекуляцию |
| 31 | `VADD3` | Векторное сложение трёх полей |
| 32 | `VSUB3` | Векторное вычитание |
| 33 | `VMUL3` | Векторное умножение |
| 34 | `VDOT3` | Скалярное произведение трёх пар |
| 35 | `VCMP` | Векторное сравнение → PR |
| 36 | `VTRITAND3` | Векторный потритовый минимум |
| 37 | `VTRITOR3` | Векторный максимум |
| 38 | `VTRITXOR3` | Векторный XOR |
| 39 | `VSHL3` | Векторный сдвиг влево |
| 40 | `VSHR3` | Векторный сдвиг вправо |
| 41 | `IN` | `reg = port[reg_port]` |
| 42 | `OUT` | `port[reg_port] = reg` |
| 43 | `INI` | `reg = port[imm9]` |
| 44 | `OUTI` | `port[imm9] = reg` |

Предикат вычисляется как `pred_index = opcode / 28`, базовый код = `opcode % 28`. Если pred_index ≠ 0 и флаг `PR[pred_index-1]` не равен +1, инструкция не выполняется (NOP).

### 5.3. Векторные операции (SIMD)
В T3‑27 слово делится на 3×9 трит, в T3‑54 — на 3×18 трит. Операции обрабатывают поля независимо. `VDOT3` даёт сумму произведений полей в одно слово. `VCMP` записывает 9 трит результата в младшие разряды `PR`.

## 6. Микроархитектуры

### 6.1. In‑order (T3‑27 и T3‑54)
- Одно универсальное АЛУ, последовательное исполнение.
- Нет конвейера, спекуляции, SIMD.
- Предикация эмулируется.
- Инструкции 28–44 вызывают исключение недопустимой операции.

**Задержки инструкций (такты):**

| Инструкция | T3‑27 | T3‑54 |
|------------|-------|-------|
| HALT, MOV, LI, NEG, TRITAND, TRITOR, TRITXOR, CMP | 1 | 1 |
| LOAD, STORE | 2 | 2 |
| ADD, SUB, SHL, SHR | 1 | 1 |
| MUL | 5 | 8 |
| DIV, MOD | 10 | 15 |
| JMP | 1 | 1 |
| JE, JNE, JL, JG, JM | 1 (не перех.) / 2 (перех.) | 1/2 |
| CALL, RET | 2 | 2 |
| PUSH, POP | 2 | 2 |
| LIMM | 2 | 2 |
| IN, OUT, INI, OUTI | 2 | 2 |

### 6.2. VLIW (только T3‑54)
- Три идентичных АЛУ.
- Бандл из трёх слотов (18 трит каждый) в одном 54‑тритном слове.
- Параллельное выполнение с ограничениями:
  - Конфликт по регистрам: недопустим (два слота не могут писать в один регистр).
  - Конфликт по памяти: одновременно выполняется не более одного обращения. Приоритет: слот 0 > 1 > 2. Остальные ждут 1 такт.
  - Переходы: только один, приоритет как у памяти.
- Предикация: послотная.
- Спекуляция: `SPEK` сохраняет теневые регистры и включает буфер отложенных записей. `COMMIT` применяет, `ROLLBACK` откатывает.
- SIMD: все векторные инструкции доступны на любом АЛУ за 1 такт.

## 7. Модель времени и аппаратные счётчики

- Частота: 1 ГГц (1 такт = 1 нс). В симуляторе — только `cycle_count`.
- Счётчики отображаются на MMIO‑адреса:
  - `0xFFFFFF00` – `CYCLE_LOW`
  - `0xFFFFFF01` – `CYCLE_HIGH` (только T3‑27)
  - `0xFFFFFF02` – `INST_COUNT`
  - `0xFFFFFF03` – `STALL_COUNT`
  - `0xFFFFFF10` – `TIMER_CTRL`
  - `0xFFFFFF11` – `TIMER_CMP`
- Запись в `CYCLE_LOW` сбрасывает все счётчики.
- Таймер: при совпадении `CYCLE_LOW == TIMER_CMP` и бите разрешения взводится флаг прерывания (бит 1 `TIMER_CTRL`). Программная проверка флага.

## 8. Подсистема ввода‑вывода

- Адресное пространство портов (до 2²⁷).
- Зарезервированные порты:
  - 0 – stdout
  - 1 – stdin
  - 2 – stderr
  - 3…7 – свободные
  - 0x10…0x1F – управление таймерами/MMIO.
- Устройства реализуют интерфейс `IDevice` с методами `Read`, `Write`, `DataReady`.
- При отсутствии готовности инструкция `IN` вызывает останов (stall) до появления данных.

## 9. Симулятор на C#: архитектура и API

Решение включает проекты:
- `TritTypes` – базовые троичные типы.
- `T3Simulator.Common` – `IT3Processor`, `ProcessorBase`.
- `T3Simulator.InOrder` – in‑order (T3‑27, T3‑54).
- `T3Simulator.VLIW` – VLIW (T3‑54).
- `T3Assembler`, `T3Compiler`, `Benchmarks`.

**Интерфейс процессора:**
```csharp
public interface IT3Processor
{
    void LoadProgram(List<Word> code);
    void Reset();
    bool Step();
    void Run();

    long CycleCount { get; }
    long InstructionCount { get; }
    long StallCount { get; }

    void SetInputDevice(long port, IDevice dev);
    void SetOutputDevice(long port, IDevice dev);

    ProcessorState GetState();
}
```

## 10. Верификация и тестирование

### 10.1. Модульные тесты
Каждая инструкция проверяется изолированно: загружается тестовая последовательность, выполняется, сравниваются значения регистров/памяти/счётчиков.

Пример для `ADD`:
```csharp
[Fact]
public void ADD_Test()
{
    var proc = new T3InOrderProcessor(T3Config.T3_27);
    var code = new List<Word27>();
    code.Add(Encode(Opcode.LI, 0, 0, 10));  // A=10
    code.Add(Encode(Opcode.LI, 0, 1, 20));  // B=20
    code.Add(Encode(Opcode.ADD, 0, 0, 1));  // A+=B
    code.Add(Encode(Opcode.HALT));
    proc.LoadProgram(code);
    proc.Run();
    Assert.Equal(30, proc.GetLogicalReg(0));
}
```

### 10.2. Тесты регистрового окна
Проверяют, что после `CALL` старые `A` видны как `E`, а новый `A` сброшен. После `RET` окно восстанавливается.

### 10.3. Тесты предикации и SIMD
Устанавливают флаги PR, выполняют инструкции с предикатами, проверяют избирательное исполнение. Векторные операции проверяются позлементным сравнением.

### 10.4. Тесты спекуляции (VLIW)
Проверяют, что после `SPEK` изменения не видны снаружи, `COMMIT` применяет, `ROLLBACK` отменяет.

### 10.5. Интеграционные тесты
Запуск коротких программ: факториал, векторизованное сложение, цепочка вызовов.

## 11. Примеры кода

**Факториал с регистровым окном:**
```asm
fact:
    CMP E, 0
    JE base
    LI A, 1
    SUB E, A          ; E = n-1
    MOV A, E
    CALL fact
    MUL A, E
    RET
base:
    LI A, 1
    RET

main:
    LI A, 5
    CALL fact
    OUTI 0, A
    HALT
```

**VLIW с предикацией:**
```asm
    LI A, 10
    LI B, 20
    ; (p1) ADD A, B   — выполнится только если p1 = +1
    HALT
```

**SIMD сложение:**
```asm
    LIMM A, 0xVector1
    LIMM B, 0xVector2
    VADD3 A, A, B
    HALT
```
