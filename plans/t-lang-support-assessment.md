# Оценка поддержки языка T-lang

**Дата:** 2026-07-01  
**Автор:** Architect Mode  
**Метод:** Анализ spec.md, EBNF, кода интерпретатора, компилятора, тестов, отчётов

---

## Общая оценка: **6.5 / 10**

### Расшифровка шкалы:
| Балл | Значение |
|------|----------|
| 0-2 | Минимальная поддержка, язык практически не работает |
| 3-4 | Базовая поддержка скалярного подмножества |
| 5-6 | Средняя поддержка: циклы, функции, массивы, структуры |
| 7-8 | Хорошая поддержка: большинство фич spec работают |
| 9-10 | Полная поддержка: все фичи spec реализованы и протестированы |

## 1. Типы данных — **7/10**

| Фича | Spec | Интерпретатор | Компилятор | Статус |
|------|------|---------------|------------|--------|
| `trit` | ✅ | ✅ | ✅ | Supported |
| `tryte` | ✅ | ✅ | ✅ | Supported |
| `tshort` | ✅ | ✅ | ✅ | Supported |
| `tint` | ✅ | ✅ | ✅ | Supported |
| `tlong` | ✅ | ⚠️ (через AsInt) | ⚠️ (через R2) | Partial |
| `tlong long` | ✅ | ❌ | ❌ | Not implemented |
| `tfloat` | ✅ | ✅ (double) | ⚠️ (FTOI/ITOF) | Partial |
| `tdouble` | ✅ | ⚠️ (как double) | ❌ | Partial |
| `tril` | ✅ | ⚠️ (как bool) | ⚠️ | Partial |
| `void` | ✅ | ✅ | ✅ | Supported |
| `enum` | ✅ | ✅ | ✅ | Supported |
| `struct` | ✅ | ✅ | ✅ | Supported |
| `union` | ✅ | ❌ | ❌ | Not implemented |
| `typedef` | ✅ | ❌ (парсер) | ✅ (компилятор) | Partial |
| `const`/`volatile` | ✅ | ❌ | ❌ | Not implemented |
| Указатели `*` | ✅ | ⚠️ (no-op) | ⚠️ (частично) | Partial |

### Проблемы:
- `tlong` (36 тритов) и `tlong long` (54 трита) не имеют полноценной поддержки в интерпретаторе — всё приводится к `long` (64-bit)
- `tdouble` в интерпретаторе хранится как `double` (64-bit IEEE), а не как T3Double (36 тритов)
- `union` не реализован нигде
- Указатели в интерпретаторе — no-op (`*` и `&` возвращают то же значение)

## 3. Выражения и операторы — **7/10**

| Фича | Spec | Интерпретатор | Компилятор | Статус |
|------|------|---------------|------------|--------|
| `+ - * / %` | ✅ | ✅ | ✅ | Supported |
| `== != < > <= >=` | ✅ | ⚠️ (AsInt) | ✅ | Partial |
| `& \| ^` (потритовые) | ✅ | ✅ | ✅ | Supported |
| `&& \|\|` (логические) | ✅ | ✅ | ✅ | Supported |
| `! ~ -` (унарные) | ✅ | ✅ | ✅ | Supported |
| `<< >>` (сдвиги) | ✅ | ✅ | ✅ | Supported |
| `++ --` (пре/постфикс) | ✅ | ✅ | ✅ | Supported |
| `sizeof` | ✅ | ✅ | ✅ | Supported |
| Тринарный `?? :? :!` | ✅ | ✅ | ✅ | Supported |
| Каст `(type)expr` | ✅ | ✅ (no-op) | ✅ | Partial |
| `& *` (адрес/разымен.) | ✅ | ⚠️ (no-op) | ⚠️ | Partial |
| Присваивание `=` | ✅ | ✅ | ✅ | Supported |
| Составные `+= -=` и т.д. | ✅ | ✅ | ✅ | Supported |

### Проблемы:
- Сравнения (`==`, `!=`, `<`, `>`, `<=`, `>=`) в интерпретаторе всегда используют `AsInt()`, что даёт неверные результаты для float и tlong
- Касты типов — no-op в интерпретаторе (нет проверки совместимости)
- Указатели не работают полноценно

## 10. Критические проблемы (блокирующие)

| # | Проблема | Где | Влияние |
|---|----------|-----|---------|
| 1 | **Nested calls теряют регистры** | Компилятор | Блокирует любую нетривиальную программу с функциями |
| 2 | **Frame pointer (RZ) не инициализируется** | Симулятор | `LOADI/STOREI` с RZ дают отрицательные адреса |
| 3 | **Сравнения float через AsInt()** | Интерпретатор | Неверные результаты для float-сравнений |
| 4 | **tlong/tlong long как long** | Интерпретатор | Потеря точности для 36+ тритов |
| 5 | **tdouble как double** | Интерпретатор | Не соответствует T3Double формату |

## Рекомендации по улучшению

### Priority 1 (Critical — блокирует использование):
1. Починить nested function calls в компиляторе (ABI v4 register save/restore)
2. Починить инициализацию Frame Pointer (RZ) в симуляторе
3. Добавить float-сравнения в интерпретаторе (через AsFloat, а не AsInt)

### Priority 2 (High — важные фичи):
4. Реализовать `typedef` в парсере/интерпретаторе
5. Реализовать символьные литералы `'A'`
6. Добавить поддержку `union`
7. Реализовать `tlong` (36 тритов) как отдельный тип в интерпретаторе

### Priority 3 (Medium — расширение):
8. Реализовать стандартную библиотеку (`<tio.h>`, `<tmath.h>`, `<tstring.h>`)
9. Добавить `const`/`volatile` квалификаторы
10. Реализовать vararg-функции
11. Добавить `inline` для функций

### Priority 4 (Low — полировка):
12. Сбалансированные троичные float-литералы
13. `#line` и `#pragma` в препроцессоре
14. Улучшить обработку ошибок с номерами строк
