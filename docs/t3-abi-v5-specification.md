## 1. Регистровая модель

### 1.1 GP-регистры (RegGroup = 0)

```
┌────────┬──────┬──────────────────────────────────┬──────────────┐
│ Имя    │ Ind  │ Назначение                       │ Сохраняется  │
├────────┼──────┼──────────────────────────────────┼──────────────┤
│ RW     │  0   │ arg0 / scratch                   │ Caller       │
│ RX     │  1   │ arg1 / scratch                   │ Caller       │
│ RY     │  2   │ arg2 / scratch                   │ Caller       │
│ RZ     │  3   │ Frame Pointer (тень FP)          │ Callee       │
│ R0     │  4   │ arg3 / scratch                   │ Caller       │
│ R1     │  5   │ Call target (CALLREG)             │ Caller       │
│ R2     │  6   │ Return value (RETREG)             │ Caller       │
│ R3     │  7   │ Зарезервирован (исключён из аллокатора) │ —      │
│ R4     │  8   │ Адресный регистр (ADDRREG)       │ —            │
└────────┴──────┴──────────────────────────────────┴──────────────┘
```

**Источник:** `CodeGenerator.cs:1476` (`RegName`), `:39-41` (константы).

- `RZ` (индекс 3) — **callee-saved**. Сохраняется в прологе (`PUSH RZ`) и восстанавливается в эпилоге (`POP RZ`). В теле функции используется как неизменяемая база кадра, равная `FP` на момент входа.
- `R1` (индекс 5) — **caller-saved**. Перезаписывается `LIMM R1, <target>` перед каждым `CALL`.
- `R2` (индекс 6) — **caller-saved**. Содержит возвращаемое значение после `CALL`.
- `R3` (индекс 7) — **исключён из аллокатора** (`AllocR` и `FreeR` фильтруют `r != 7`). Используется **только в прологе** как временный регистр для `LIMM R3, stackSize`.
- `R4` (индекс 8) — **исключён из аллокатора** (`ADDRREG`). Используется как временный адресный регистр в `LoadV`, `StoreV`, `LabelAddr`, `EmitArrAccess`.

### 1.2 FPU-регистры (RegGroup = -1)

```
┌────────┬──────┬──────────────────────────────────┬──────────────┐
│ Имя    │ Ind  │ Назначение                       │ Сохраняется  │
├────────┼──────┼──────────────────────────────────┼──────────────┤
│ FW     │  0   │ scratch                          │ Caller*      │
│ FX     │  1   │ scratch                          │ Caller*      │
│ FY     │  2   │ scratch                          │ Caller*      │
│ FZ     │  3   │ scratch                          │ Caller*      │
│ F0     │  4   │ scratch                          │ Caller*      │
│ F1     │  5   │ scratch                          │ Caller*      │
│ F2     │  6   │ scratch                          │ Caller*      │
│ F3     │  7   │ scratch                          │ Caller*      │
│ F4     │  8   │ scratch                          │ Caller*      │
└────────┴──────┴──────────────────────────────────┴──────────────┘
```

\* FPU-регистры сохраняются/восстанавливаются вызывающим кодом **только если флаг `_fpuLive == true`**. Сохранение выполняется через `FTI R0, Fx; PUSH R0`; восстановление — через `POP R0; ITF Fx, R0`. Это bit-preserving round-trip.

**Источник:** `T3InOrderProcessor.cs:149-150` (FTI → Word18); `CodeGenerator.cs:1055-1073` (сохранение FPU перед CALL).

### 1.3 Special-регистры (RegGroup = +1)

```
┌────────┬──────┬──────────────────────────────────┬──────────────┐
│ Имя    │ Raw  │ Назначение                       │ Доступ       │
├────────┼──────┼──────────────────────────────────┼──────────────┤
│ FP     │ -4   │ Frame Pointer (аппаратный)       │ R/W          │
│ HP     │ -3   │ Heap Pointer                     │ R/W          │
│ SP     │ -2   │ Stack Pointer                    │ R/W          │
│ CD     │ -1   │ Condition flag (-1/0/+1)         │ R/W          │
│ PR     │  0   │ Predicate Register (18 тритов)    │ R/W          │
│ WD     │ +1   │ Window Pointer                   │ R/W          │
└────────┴──────┴──────────────────────────────────┴──────────────┘
```

Специальные регистры адресуются **балансными селекторами** (`T3InOrderProcessor.cs:177-187`).

**Источник:** `T3InOrderProcessor.cs:177-187` (GetSpecialReg), `:191-216` (SetSpecialReg).

## 2. Соглашение о вызовах

### 2.1 Аргументы

| Позиция | Регистр | Индекс |
|---------|---------|--------|
| arg0    | RW      | 0      |
| arg1    | RX      | 1      |
| arg2    | RY      | 2      |
| arg3    | R0      | 4      |
| arg4+   | Стек    | —      |

Аргументы 0–3 передаются в регистрах. Аргументы 4+ размещаются вызывающим кодом на стеке через `PUSH` в обратном порядке и доступны вызываемому через `LD Rt, RZ, offset`.

**Источник:** `CodeGenerator.cs:1046` (`argRegs = {0,1,2,4}`), `:1076-1077` (PUSH arg4+), `:187` (доступ callee к arg4+).

### 2.2 Возврат значения

- **Целочисленный / указатель:** `R2` (индекс 6, `RETREG`)
- **Float:** `F2` (не реализовано в текущем кодогенераторе)

После CALL результат немедленно копируется в свободный регистр: `MOV Rt, R2`.

**Источник:** `CodeGenerator.cs:40` (`RETREG = 6`), `:1136-1137` (MOV Rt, R2).

### 2.3 Сохраняемые регистры

| Категория | Регистры |
|-----------|----------|
| **Caller-saved** (сохраняются вызывающим) | RW, RX, RY, R0, R1 (+ FPU при `_fpuLive`) |
| **Callee-saved** (сохраняются вызываемым) | RZ |
| **Исключены из аллокатора** | R3, R4 |

**Источник:** `CodeGenerator.cs:1050-1054` (PUSH caller-saved), `:1055-1075` (FPU), `:1131-1135` (POP caller-saved), `:165,214` (PUSH/POP RZ в прологе/эпилоге).

### 2.4 Временные регистры (scratch pool)

Аллокатор `AllocR` (`CodeGenerator.cs:1411-1440`) выдаёт регистры из пула, исключая:

- `CALLREG` (5, R1)
- `RETREG` (6, R2)
- `ADDRREG` (8, R4)
- Индекс 7 (R3)
- `RESERVED_RZ` (3)

**Фактический пул временных регистров: `{RW(0), RX(1), RY(2), R0(4)}` — всего 4 регистра.**

## 3. Стековый фрейм

### 3.1 Семантика CALL/RET (аппаратная)

Инструкция `CALL R1` выполняет (`T3InOrderProcessor.cs:361-371`):

```
SP -= 2
[SP+1] ← FP      // сохранить FP вызывающего
[SP]   ← PC + 1  // сохранить адрес возврата
FP ← SP          // новый кадр
PC ← R1          // переход
```

Инструкция `RET` выполняет:

```
PC ← [SP]        // восстановить адрес возврата
FP ← [SP+1]      // восстановить FP вызывающего
SP += 2
```

### 3.2 Разметка кадра (программная)

Поскольку `CALL` перезаписывает `FP`, кодогенератор поддерживает **теневую базу кадра `RZ`**, устойчивую к вложенным вызовам (callee-saved).

```
Высокие адреса (SP уменьшается вниз)
┌──────────────────────────────────────┐ ← SP при входе
│  Return Address (сохранён CALL)       │   [SP]
│  Saved FP (сохранён CALL)             │   [SP+1]
├──────────────────────────────────────┤ ← FP после CALL (= SP)
│  PUSH RZ (callee-saved)              │
├──────────────────────────────────────┤
│  Локальные переменные                │   Адресуются через RZ
│  var_0: слот 0                       │   LD Rx, RZ, offset
│  var_1: слот 1                       │
│  ...                                 │
├──────────────────────────────────────┤
│  Call save area (50 слов)            │   Резерв под PUSH-глубину
├──────────────────────────────────────┤ ← SP после S.SUB
│  Свободное пространство              │
└──────────────────────────────────────┘
Низкие адреса
```

Размер фрейма: `localSize + callSaveArea` (50), где `localSize` — сумма размеров всех локальных переменных (по 1 слову на скаляр).

**Источник:** `CodeGenerator.cs:165-184` (пролог: `PUSH RZ`, `S.SUB SP, SP, R3`, `S.PUSH FP; POP RZ`), `:170-171` (callSaveArea = 50).

### 3.3 Доступ к локальным переменным

Все локальные переменные адресуются относительно `RZ`:

```
ST  Rx, RZ, offset    ; запись
LD  Rx, RZ, offset    ; чтение
```

где `offset = slotIndex - localVarSize - 1`. Для небольших смещений (±13) используется непосредственная форма `LD/ST`; для больших — вычисление адреса через `ADD RZ, offset` + `LD/ST Rx, Rt, 0`.

**Источник:** `CodeGenerator.cs:1246-1280` (LabelAddr), `:1352-1376` (LoadV/StoreV).

## 4. Пролог и эпилог

### 4.1 Пролог (точный код)

```asm
func_name:
    PUSH RZ                    ; callee-save RZ
    LIMM R3, <frameSize>       ; размер фрейма (localSize + 50)
    S.SUB SP, SP, R3           ; аллокация фрейма
    S.PUSH FP                  ; сохранить FP в стек (кросс-групповой PUSH)
    POP RZ                     ; RZ = FP (теневая база кадра)
    ; ... сохранение аргументов в слоты ...
```

**Источник:** `CodeGenerator.cs:165-184`.

### 4.2 Эпилог (точный код)

```asm
epilogue_N:
    LIMM Rt, <frameSize>
    S.ADD SP, SP, Rt           ; освобождение фрейма
    POP RZ                     ; восстановление RZ
    RET
```

Функция завершается либо явным `RET`, либо переходом на `epilogue_N` (для ранних `return` с очисткой стека).

**Источник:** `CodeGenerator.cs:206-215`.

## 5. Передача аргументов

### 5.1 Со стороны вызывающего (caller)

```asm
; Аргументы 0..3 — в регистрах:
MOV RW, <arg0>     ; или результат GenExpr
MOV RX, <arg1>
MOV RY, <arg2>
MOV R0, <arg3>

; Сохранение caller-saved:
PUSH RW
PUSH RX
PUSH RY
PUSH R0
PUSH R1

; Аргументы 4+ — на стек (в обратном порядке):
PUSH <argN>
...
PUSH <arg4>

; Вызов:
LIMM R1, <target>
CALL R1

; Очистка стековых аргументов 4+:
S.ADD SP, SP, <nArgs - 4>

; Восстановление caller-saved (в обратном порядке):
POP R1
POP R0
POP RY
POP RX
POP RW

; Чтение результата:
MOV Rt, R2
```

**Источник:** `CodeGenerator.cs:1045-1140` (EmitCall).

### 5.2 Со стороны вызываемого (callee)

Аргументы 0–3 читаются из регистров в прологе и сохраняются в слоты:

```asm
ST RW, RZ, offset_arg0
ST RX, RZ, offset_arg1
ST RY, RZ, offset_arg2
ST R0, RZ, offset_arg3
```

Аргументы 4+ читаются из стека со смещением `(i-4)+2` относительно `RZ` (2 слота заняты адресом возврата и сохранённым FP от CALL).

**Источник:** `CodeGenerator.cs:179-191`.

## 7. FPU ABI

FPU-регистры сохраняются вызывающим кодом **только если в функции используются float-переменные** (флаг `_fpuLive`).

### Сохранение перед CALL:

```asm
FTI R0, F4    ; F4 → целое в R0
PUSH R0
FTI R0, F3
PUSH R0
...           ; все 9 FPU-регистров
FTI R0, FW
PUSH R0
```

### Восстановление после CALL (в обратном порядке):

```asm
POP R0
ITF FW, R0
POP R0
ITF FX, R0
...
POP R0
ITF F4, R0
```

**Источник:** `CodeGenerator.cs:1055-1073` (сохранение), `:1110-1130` (восстановление). `T3InOrderProcessor.cs:149-150` (FTI/ITF как bit-preserving round-trip через `Word18`).

## 8. Регистровый аллокатор

### 8.1 Алгоритм

`AllocR` (`CodeGenerator.cs:1411-1440`):

1. Если стек `_freeRegs` не пуст — вернуть освобождённый регистр, исключая запрещённые
2. Иначе — выдать следующий по циклу регистр из `{0,1,2,4}` (RW, RX, RY, R0), пропуская запрещённые

`FreeR` (`CodeGenerator.cs:1444-1456`) возвращает регистр в стек, если он не запрещён.

### 8.2 Запрещённые регистры (не участвуют в аллокации)

| Индекс | Имя | Причина |
|--------|-----|---------|
| 3 | RZ | `RESERVED_RZ` — база кадра |
| 5 | R1 | `CALLREG` — цель CALL |
| 6 | R2 | `RETREG` — возврат значения |
| 7 | R3 | Исключён явно (`fr != 7`) |
| 8 | R4 | `ADDRREG` — адресный регистр |

### 8.3 Ограничение

**Пул временных регистров — ровно 4: `{RW, RX, RY, R0}`.** При исчерпании (например, два вложенных вызова в одном выражении) возможна потеря значения. Компилятор использует спилл через слоты (PUSH/POP в `GenBin`, `StoreV`/`LoadV`) для смягчения, но структурно пул не расширяется.

## 9. Модель памяти

### 9.1 Инициализация

```
SP = 1048575    (2^20 - 1, вершина стека)
HP = 699050     (≈ 2/3 × 2^20, начало кучи)
FP = SP
```

**Источник:** `T3InOrderProcessor.cs:53-55` (конструктор), `CodeGenerator.cs:74-75` (entry-код: `S.LIMM SP,1048575; S.LIMM HP,699050`).

### 9.2 Направления роста

- **Стек:** растёт **вниз** (SP уменьшается)
- **Куча:** растёт **вверх** (HP увеличивается)

Куча реализована как bump-аллокатор: `malloc(size)` → `S.PUSH HP; POP Rt; S.ADD HP, HP, sizeR`. `free()` — no-op.

**Источник:** `CodeGenerator.cs:1036-1043` (EmitCall для malloc).

## 10. Nanolib (StdLib) ABI

Встроенная библиотека (nanolib) реализована в `NanolibCodeGen.cs` и **не зависит от ABI основного кода**. Её функции (`strlen`, `putchar`, `abs`, `min`, `max`, `t_strcmp`, `t_strcpy` и др.) следуют упрощённому соглашению:

- Аргумент передаётся в **RW** (индекс 0)
- Второй аргумент (если есть) — в **RX** (индекс 1)
- Возврат значения — в **R2** (индекс 6)
- Сохраняемые: R3, R4 (PUSH в прологе, POP в эпилоге)
- Переходы — через паттерн `LIMM R0, label; JMP R0` (Jcc аналогично)

Ассемблер (`T3InOrderAssembler.AssembleCore:548-553`) разворачивает переходы на метку в 3-словную последовательность `LIMM R1, tgt; Jcc R1`.

**Источник:** `NanolibCodeGen.cs:12-25` (strlen), `:27-37` (putchar), `T3InOrderAssembler.cs:548-553` (jump expansion).

## 11. Отличия от ABI v4

| Элемент | ABI v4 | ABI v5 |
|---------|--------|--------|
| **FP** | GP-регистр (индекс 3) | Special-регистр (RegGroup=+1, raw=-4) |
| **CALL/RET** | Явный PUSH FP/retaddr | Аппаратный: CALL автосохраняет FP и retaddr |
| **База кадра** | `RZ` как FP (`MOV RZ, SP`) | `RZ` как тень FP (`S.PUSH FP; POP RZ`) |
| **Пролог** | `PUSH RZ; MOV RZ, SP; SUBI SP, ...` | `PUSH RZ; LIMM R3,sz; S.SUB SP,SP,R3; S.PUSH FP; POP RZ` |
| **R3** | callee-saved, доступен | Исключён из аллокатора (временный в прологе) |
| **R4** | callee-saved, адресный | Исключён из аллокатора (ADDRREG) |
| **Стек** | Растёт вверх | Растёт вниз |
| **Стек аргументов** | Адресуется через FP+offset | Адресуется через RZ+offset |
| **FPU сохранение** | Всегда | Только при `_fpuLive == true` |
