## 1. Введение в сбалансированную троичную систему

### 1.1. Трит как фундаментальная единица информации

В отличие от классической двоичной логики, оперирующей битами со значениями {0, 1}, сбалансированная троичная система использует **трит** (ternary digit) — единицу информации, принимающую одно из трёх значений: {-1, 0, +1}. Эти значения обозначаются символами `-`, `0`, `+` соответственно.

Математически, сбалансированная троичная система представляет целое число N как:

```
N = Σ(k=0 to n-1) t_k * 3^k, где t_k ∈ {-1, 0, +1}
```

В отличие от несбалансированной троичной системы (где цифры {0, 1, 2}), сбалансированная система симметрична относительно нуля: для любого числа существует единственное представление без знакового бита. Отрицательные числа представляются естественным образом — инвертированием знака каждого трита (операция `NEG`).

### 1.2. Трайт — минимальная адресуемая единица

В архитектуре T3 минимальной адресуемой ячейкой памяти является **трайт** (tryte) — группа из 6 тритов. Выбор размера трайта в 6 тритов обусловлен следующими соображениями:

- **Информационная ёмкость:** 3^6 = 729 возможных значений, что превышает 2^8 = 256 (байт) и 2^9 = 512
- **Адресация символов:** 729 значений достаточно для кодирования расширенного набора символов (T-SCII), включающего CP1251 и дополнительные математические символы
- **Выравнивание с 18-тритным словом:** 18 = 3 * 6, что даёт естественное трёхтрайтовое слово

### 1.3. Преимущества перед двоичной системой

Сбалансированная троичная система обладает рядом теоретических преимуществ:

1. **Симметричное представление отрицательных чисел:** Операция смены знака тривиальна — инвертирование каждого трита (NEG). Не требуется дополнительный код (two's complement).

2. **Естественная трёхзначная логика:** Помимо привычных `true` и `false`, появляется третье состояние `maybe` (неопределённость), что открывает новые возможности в логических вычислениях и искусственном интеллекте.

3. **Оптимальная информационная плотность:** С точки зрения теории информации, основание e ≈ 2.718 является оптимальным. Основание 3 ближе к e, чем 2, что делает троичную систему теоретически более эффективной для представления информации.

4. **Упрощение арифметических операций:** Сложение в сбалансированной троичной системе требует меньше переносов, чем в двоичной, так как знак уже встроен в представление.

### 1.4. Исторический контекст

Первая и наиболее известная троичная вычислительная машина — **«Сетунь»**, разработанная в 1958 году в МГУ под руководством Н.П. Брусенцова. Сетунь использовала сбалансированную троичную систему с 18-тритным словом, феррит-диодные ячейки памяти и магнитный барабан. Было выпущено около 50 экземпляров машины, которые успешно эксплуатировались в СССР до начала 1970-х годов.

Проект T3Sharp является современной программной реконструкцией и развитием идей троичной архитектуры на платформе .NET, с акцентом на исследовательское моделирование, компиляцию и симуляцию.

### 1.5. Троичная арифметика

Операции над тритами определяются следующими таблицами:

**Сложение (+):**

| A \ B | - | 0 | + |
|-------|---|---|---|
| **-** | + | - | 0 |
| **0** | - | 0 | + |
| **+** | 0 | + | - |

С переносом:
- (-) + (-) = (+) с переносом (-)
- (+) + (+) = (-) с переносом (+)

**Умножение (*):**

| A \ B | - | 0 | + |
|-------|---|---|---|
| **-** | + | 0 | - |
| **0** | 0 | 0 | 0 |
| **+** | - | 0 | + |

**Поразрядные операции:**

**Минимум (AND):** `min(a, b)` — результат равен минимальному из двух тритов.

| A \ B | - | 0 | + |
|-------|---|---|---|
| **-** | - | - | - |
| **0** | - | 0 | 0 |
| **+** | - | 0 | + |

**Максимум (OR):** `max(a, b)` — результат равен максимальному из двух тритов.

| A \ B | - | 0 | + |
|-------|---|---|---|
| **-** | - | 0 | + |
| **0** | 0 | 0 | + |
| **+** | + | + | + |

**Сумма по модулю 3 (XOR):** `(a + b) mod 3` с отображением {0, 1, 2} → {-1, 0, +1}.

| A \ B | - | 0 | + |
|-------|---|---|---|
| **-** | + | - | 0 |
| **0** | - | 0 | + |
| **+** | 0 | + | - |

## 2. Архитектура процессора T3

### 2.1. Модель памяти

Процессор T3 имеет **word-addressable память** объёмом 1M слов (1 048 576). Каждое слово — 18 тритов. Память линеарна: адреса от 0 до 1 048 575.

Память разделена на логические области:
- **Код программы:** начиная с адреса 0
- **Данные:** после кода (автоматически размещаются компилятором)
- **Стек:** растёт вниз от адреса 1 048 575 (MemSize - 1)
- **MMIO:** адреса 0xFFFFFF00-0xFFFFFF03 (cycle counters, instruction count)

### 2.2. Регистровый файл

Процессор имеет 9 регистров общего назначения (GP) и 9 регистров с плавающей точкой (FPU). Регистры адресуются по тритовому индексу от -4 до +4, физический индекс = trit_value + 4.

**Регистры общего назначения:**

| Имя | Трит | Phys | Назначение в ABI |
|-----|------|------|-----------------|
| RW  | -4   | 0    | Caller-saved, рабочий |
| RX  | -3   | 1    | Caller-saved, рабочий |
| RY  | -2   | 2    | Caller-saved, рабочий |
| RZ  | -1   | 3    | **Frame Pointer (ABI v4)** |
| R0  | 0    | 4    | Caller-saved, рабочий |
| R1  | +1   | 5    | Временный для CALL (адрес) |
| R2  | +2   | 6    | **Return value** (не сохраняется) |
| R3  | +3   | 7    | Caller-saved, рабочий |
| R4  | +4   | 8    | Address register (для LOAD/STORE) |

**Регистры с плавающей точкой:**

| Имя | Трит | Phys | Назначение |
|-----|------|------|-----------|
| FW  | -4   | 0    | FPU general |
| FX  | -3   | 1    | FPU general |
| FY  | -2   | 2    | FPU general |
| FZ  | -1   | 3    | FPU general |
| F0  | 0    | 4    | FPU general |
| F1  | +1   | 5    | FPU general |
| F2  | +2   | 6    | FPU general |
| F3  | +3   | 7    | FPU general |
| F4  | +4   | 8    | FPU general |

### 2.3. Специальные регистры

| Регистр | Размерность | Описание |
|---------|------------|----------|
| **PC** | 20 бит (адрес) | Program Counter — указывает на текущую инструкцию |
| **SP** | 20 бит | Stack Pointer — вершина стека, растёт вниз |
| **WP** | 3 бита | Window Pointer — для register windowing (запланировано) |
| **Cond** | 1 трит | Condition flag: -1 (less), 0 (equal), +1 (greater) |
| **PR** | 9 тритов (3×3) | Predicate Register: 3 флага по 3 трита каждый |

### 2.4. Форматы данных

#### 2.4.1. Троичное представление целых чисел (Word18 и Word54)

Троичное машинное слово принципиально отличается от двоичного. В двоичной системе каждый бит принимает значения {0, 1}, а вес позиции равен 2^k. В сбалансированной троичной системе каждый трит принимает значения {-1, 0, +1}, а вес позиции равен 3^k.

**Word18 (18 тритов):**

18-тритное слово является стандартным размером машинного слова в архитектуре T3-18. Физически хранится в 32-битном целом числе (`int`), но старшие 14 бит не используются.

Представление числа N в Word18:

```
N = t_0 × 3^0 + t_1 × 3^1 + t_2 × 3^2 + ... + t_17 × 3^17

где t_k ∈ {-1, 0, +1}
```

Диапазон представимых значений:

```
N_min = -(3^18 - 1) / 2 = -(387,420,489 - 1) / 2 = -193,710,244
N_max = +(3^18 - 1) / 2 = +193,710,244
```

Примеры 18-тритных чисел:

```
0t+-- (троичная запись от старшего к младшему):
  = +1×3^2 + (-1)×3^1 + (-1)×3^0
  = +1×9  + (-1)×3   + (-1)×1
  = 9 - 3 - 1 = 5

0t---+0-0++++++---:
  (каждый трит на своей позиции, вес = 3^позиция)
```

Важное свойство: отрицание числа тривиально — каждый трит инвертируется:
```
NEG(0t+0-) = 0t-0+   (инвертировали +→-, 0→0, -→+)
```

Это свойство делает операцию изменения знака (NEG) O(1) по времени и логическим элементам.

**Word54 (54 трита):**

Расширенное 54-тритное слово для повышенной точности. Диапазон:

```
N_min = -(3^54 - 1) / 2 ≈ -2.9 × 10^25
N_max = +(3^54 - 1) / 2 ≈ +2.9 × 10^25
```

Кодируется в Int128. Используется для T3Double (float двойной точности) и VLIW-инструкций (запланировано).

**Сравнение с двоичным представлением:**

| Свойство | Двоичное (32-bit signed) | Троичное (18-trit Word18) |
|----------|--------------------------|---------------------------|
| Диапазон | -2,147,483,648 … +2,147,483,647 | -193,710,244 … +193,710,244 |
| Представление -1 | 0xFFFFFFFF (two's complement) | 0t------------------ (все триты -1) |
| Смена знака | Инвертировать биты + 1 | Инвертировать триты (NEG) |
| Асимметрия | -2^31 vs +(2^31-1) | Симметрично |

Хотя 18-тритное слово имеет меньший диапазон, чем 32-битное, его симметричность упрощает арифметику и устраняет проблему «-0» (в отличие от one's complement в двоичной системе).

#### 2.4.2. Троичное представление с плавающей точкой (T3Float)

T3Float — троичный аналог IEEE 754, адаптированный для сбалансированной системы. Если IEEE 754 использует двоичную мантиссу и степень двойки для экспоненты, то T3Float использует троичную мантиссу и степень тройки.

**Формат (18 тритов):**

```
[T_17 ... T_12] [T_11 ... T_0]
  экспонента (6)   мантисса (12)
```

- Экспонента E: 6 тритов (signed balanced), диапазон -364…+364
- Мантисса M: 12 тритов (signed balanced), диапазон -88,573…+88,573
- bias = 182 = (3^6 - 1) / 2

Значение числа: `value = M × 3^(E - 182)`

**Примеры значений T3Float:**

```
T3Float(0t000000, 0t++++++++++++)  — максимальное положительное:
  E = 0 (с учётом bias: фактическая экспонента = -182)
  M = +(3^12 - 1)/2 = +88,573
  value = 88,573 × 3^(-182) ≈ крайне малое число

T3Float(0t++++++, 0t++++++++++++)  — максимальное:
  E = +364, M = +88,573
  value = 88,573 × 3^(364 - 182) = 88,573 × 3^182 ≈ колоссальное

T3Float(0t000000, 0t000000000000)  — ноль:
  E = 0 (bias = -182), M = 0
  value = 0 × 3^(-182) = 0
```

**Сравнение с IEEE 754 binary32 (float):**

| Свойство | IEEE 754 binary32 | T3Float |
|----------|-------------------|---------|
| Биты/триты | 32 бита (1+8+23) | 18 тритов (6+12) |
| Основание | 2 | 3 |
| Диапазон экспоненты | -126…+127 | -364…+364 |
| Точность мантиссы | ~7 десятичных цифр | ~6 десятичных цифр |
| bias | 127 | 182 |
| Специальные значения | ±0, ±∞, NaN (тихий/сигнальный) | ±0, ±∞, NaN, Maybe-NaN |
| Скрытый бит/трит | 1 (всегда) | ±1 |

В T3Float скрытый трит всегда ±1 (нормализованное представление), в отличие от IEEE 754 где скрытый бит всегда 1. Это даёт симметричный диапазон положительных и отрицательных чисел.

**Специальные значения T3Float:**

| Значение | Экспонента (E) | Мантисса (M) | Пояснение |
|----------|----------------|--------------|-----------|
| +0 | min (-364) | 0 | Положительный ноль |
| -0 | min (-364) | 0 | Отрицательный ноль (симметричен) |
| +∞ | max (+364) | 0 | Положительная бесконечность |
| -∞ | max (+364) | 0 | Отрицательная бесконечность |
| NaN | max (+364) | ≠ 0, старший трит ≠ 0 | Не-число |
| Maybe-NaN | max (+364) | ≠ 0, старший трит = 0 | Неопределённое не-число |

Maybe-NaN — уникальное троичное понятие, не имеющее аналога в IEEE 754. Оно представляет «неизвестную ошибку» — результат, который может быть как NaN, так и обычным числом, но точное значение не определено.

**Кодирование в Word18:**

```
word18_value = E × 3^12 + M
```

Это линейное кодирование — прямое умножение экспоненты на 3^12 (531 441) и сложение с мантиссой. Поскольку диапазон мантиссы (±88 573) меньше 3^12, поля не перекрываются, и декодирование однозначно:

```
E = word18_value / 3^12    (целочисленное деление)
M = word18_value % 3^12    (остаток)
```

**Нормализация:**

После каждой арифметической операции с T3Float мантисса сдвигается так, чтобы старший хранимый трит был ненулевым, с соответствующей коррекцией экспоненты. Например:

```
Ненормализованное: E=5, M=0t00+0-  (старший трит = 0)
Нормализованное:   E=3, M=0t+0-    (сдвиг на 2 позиции влево)
```

Это гарантирует максимальную точность представления и единственность представления каждого числа.

**T3Double (36 тритов):**

Расширенный формат двойной точности:
- Экспонента: 8 тритов (диапазон -3,280…+3,280)
- Мантисса: 28 тритов
- bias = 3,280 = (3^8 - 1) / 2

В настоящий момент T3Double не полностью интегрирован в конвейер процессора; его поддержка запланирована на Phase 15.

### 2.5. Модель исполнения

Процессор T3 работает как **in-order интерпретатор** с циклом Fetch-Decode-Execute:

1. **Fetch:** `instruction = Memory[PC]`
2. **Decode:** `(pred, opcode, op1, op2, op3, imm) = Decode(instruction)`
3. **Predicate check:** если `pred > 0`, инструкция выполняется только при `PR[pred-1] == +1`
4. **Execute:** switch(opcode) → выполнение операции
5. **PC update:** `PC++` (или прыжок для control flow)

Подсчитываются циклы (cycle count), количество инструкций (instruction count) и stalls.

## 3. Система команд (ISA)

### 3.1. Категории инструкций

Инструкции разделены на следующие категории:

**Системные (0-1):**
- `HALT` (0) — останов процессора
- `NOP` (1) — пустая операция

**Пересылка данных (2-5):**
- `MOV` (2) — копирование регистр-регистр
- `MOVI` (3) — загрузка непосредственного значения
- `LI` (4) — загрузка непосредственного значения (псевдоним MOVI)
- `LIMM` (5) — загрузка большого непосредственного (2 слова)

**Арифметика (10-15, 20-25):**
- `ADD/SUB/MUL/DIV/MOD/NEG` (R-type) и `ADDI/SUBI/MULI/DIVI/MODI/NEGI` (I-type)

**Логические (30-35):**
- `AND/OR/XOR` (R-type) и `ANDI/ORI/XORI` (I-type)
- Потритовые: минимум, максимум, сумма по модулю 3

**Сдвиги (40-43):**
- `SHL/SHR` (R-type) — умножение/деление на 3^k
- `SHLI/SHRI` (I-type)

**Память и стек (50-55):**
- `LOAD/STORE` — доступ к памяти по адресу в регистре
- `LOADI/STOREI` — доступ с непосредственным смещением
- `PUSH/POP` — стековые операции

**Управление (60-71):**
- `CMP/CMPI` (60-61) — сравнение, устанавливает Cond
- `JMP` (62) — безусловный переход
- `JE/JNE/JL/JG/JM` (63-67) — условные переходы
- `JLE/JGE` (68-69) — условные переходы (≤, ≥)
- `CALL` (70) — вызов подпрограммы
- `RET` (71) — возврат из подпрограммы

**Ввод-вывод (80-83):**
- `IN/OUT` (80-81) — портовый ввод-вывод по адресу в регистре
- `INI/OUTI` (82-83) — портовый ввод-вывод с непосредственным портом

**FPU (100-116):**
- `FADD/FSUB/FMUL/FDIV/FSQRT` (100-104) — арифметика
- `FABS/FNEG/FCMP` (105-107) — унарные операции и сравнение
- `FTOI/ITOF/FTOF` (108-110) — конвертация типов
- `FLW/FSW` (111-112) — загрузка/сохранение float
- `FMOV/FCLASS/FSWAP` (113-115) — движение и классификация
- `FZERO` (116) — установка в 0.0

## 4. Кодирование инструкций

### 4.1. Формат инструкции (18 тритов)

Каждая инструкция кодируется в одно 18-тритное слово по схеме:

```
[Predicate (3)] [Opcode (6)] [Arguments (9)]
```

Поле Predicate — беззнаковое целое (raw unsigned), диапазон 0-26. Значение 0 означает безусловное выполнение. Значения 1-3 выбирают один из трёх предикатных флагов.

Поле Opcode — беззнаковое целое (raw unsigned), диапазон 0-728. Всего доступно 729 опкодов, из которых определено около 70.

Поле Arguments — 9 тритов, интерпретируемых в зависимости от типа инструкции.

### 4.2. R-type (Register)

```
[Pred(3)] [Opcode(6)] [Op1(3)] [Op2(3)] [Op3(3)]
```

Три регистровых операнда. Каждый кодируется как signed balanced ternary со смещением: `unsigned = value + 13`, где 13 = (27-1)/2.

Диапазон каждого операнда: -13...+13 в unsigned представлении, но реально используется только -4...+4 (9 регистров).

Декодирование: `signed = unsigned - 13`.

### 4.3. I-type (Immediate)

```
[Pred(3)] [Opcode(6)] [Op1(3)] [Immediate(6)]
```

Один регистровый операнд (3 трита) и непосредственное значение (6 тритов). Immediate кодируется как signed balanced ternary со смещением 364: `unsigned = value + 364`.

Диапазон immediate: -364...+364. Этого достаточно для адресации в пределах ±364 слов от PC или для загрузки большинства литеральных значений.

Декодирование: `imm_signed = imm_unsigned - 364`.

### 4.4. J-type (Jump)

```
[Pred(3)] [Opcode(6)] [Register(3)] [Padding(6)]
```

Один регистр (3 трита), содержащий адрес перехода. Младшие 6 тритов — padding, всегда равны 0 в encoded представлении (что соответствует значению 0 после вычитания смещения).

Для переходов по меткам ассемблер генерирует 3-словную последовательность:
```
LIMM R1, target_address    ; загрузка абсолютного адреса
Jxx R1                      ; регистрово-косвенный переход
```

### 4.5. LIMM (Large Immediate)

Двухсловная инструкция для загрузки значений, не помещающихся в 6-тритное immediate поле:

```
Слово 1: LIMM(5) [Reg(3)]
Слово 2: [данные (18 тритов)]
```

Процессор при выполнении LIMM читает следующее слово из памяти (PC+1) и загружает его в регистр. PC увеличивается на 2.

### 4.6. Сбалансированное кодирование со смещением

Ключевая идея энкодера/декодера T3 — использование беззнакового представления для хранения знаковых сбалансированных значений.

Пусть поле имеет ширину w тритов. Тогда:
- Диапазон сбалансированных значений: `[-(3^w-1)/2, +(3^w-1)/2]`
- Смещение: `offset = (3^w - 1) / 2`
- Беззнаковое представление: `unsigned = signed + offset`

Пример для w=3:
- offset = (27-1)/2 = 13
- signed -4 → unsigned 9
- signed 0 → unsigned 13
- signed +4 → unsigned 17

Пример для w=6:
- offset = (729-1)/2 = 364
- signed -364 → unsigned 0
- signed 0 → unsigned 364
- signed +364 → unsigned 728

Это кодирование гарантирует, что поля не «кровоточат» (не влияют на соседние поля), так как все значения в памяти неотрицательны.

## 5. Семантика инструкций

### 5.1. HALT (0)

```
Останавливает процессор. IsHalted = true.
Cycles: 1
```

### 5.2. NOP (1)

```
Пустая операция. PC++.
Cycles: 1
```

### 5.3. MOV (2)

```
Reg[op1] = Reg[op2]
Cycles: 1
```

Копирует значение из регистра-источника в регистр-назначения.

### 5.4. MOVI / LI (3, 4)

```
Reg[op1] = imm
Cycles: 1
```

Загружает непосредственное значение в регистр. MOVI и LI — псевдонимы.

### 5.5. LIMM (5)

```
Reg[op1] = Mem[PC + 1]
PC = PC + 2
Cycles: 2
```

Двухсловная загрузка. Читает следующее слово памяти как данные.

### 5.6. ADD / SUB / MUL / DIV / MOD / NEG (10-15)

```
ADD:  Reg[op1] = Reg[op2] + Reg[op3]
SUB:  Reg[op1] = Reg[op2] - Reg[op3]
MUL:  Reg[op1] = Reg[op2] * Reg[op3]
DIV:  Reg[op1] = Reg[op2] / Reg[op3]  (к -∞)
MOD:  Reg[op1] = Reg[op2] % Reg[op3]  (a = (a/b)*b + a%b)
NEG:  Reg[op1] = -Reg[op2]
```

Деление и остаток округляются к -∞ (floor division). Это гарантирует выполнение тождества `(a/b)*b + a%b == a`.

Cycles: ADD/SUB 1, MUL 5/8, DIV/MOD 10/15 (зависит от T3-18/T3-54)

### 5.7. AND / OR / XOR (30-32)

```
AND:  Reg[op1] = min(Reg[op2], Reg[op3])  (потритовый минимум)
OR:   Reg[op1] = max(Reg[op2], Reg[op3])  (потритовый максимум)
XOR:  Reg[op1] = (Reg[op2] + Reg[op3]) mod 3, без переноса
```

Операции выполняются над каждым тритом независимо. Cycles: 1.

### 5.8. SHL / SHR (40-41)

```
SHL: Reg[op1] = Reg[op2] * 3^op3  (сдвиг влево на op3 позиций)
SHR: Reg[op1] = Reg[op2] / 3^op3  (арифметический сдвиг вправо)
```

Сдвиг влево эквивалентен умножению на степень тройки, сдвиг вправо — делению с округлением к -∞. Cycles: 1.

### 5.9. LOAD / STORE (50-52)

```
LOAD:  Reg[op1] = Mem[Reg[op2]]
STORE: Mem[Reg[op2]] = Reg[op1]
Cycles: 2
```

Доступ к памяти по абсолютному адресу, хранящемуся в регистре.

### 5.10. LOADI / STOREI (51-53)

```
LOADI:  Reg[op1] = Mem[Reg[op2] + imm]
STOREI: Mem[Reg[op2] + imm] = Reg[op1]
Cycles: 2
```

Доступ к памяти с непосредственным смещением ±364.

### 5.11. PUSH / POP (54-55)

```
PUSH: SP = SP - 1; Mem[SP] = Reg[op1]
POP:  Reg[op1] = Mem[SP]; SP = SP + 1
Cycles: 2
```

Стек растёт вниз. PUSH декрементирует SP и записывает значение. POP читает значение и инкрементирует SP.

### 5.12. CMP / CMPI (60-61)

```
CMP:  Cond = sign(Reg[op1] - Reg[op2])
CMPI: Cond = sign(Reg[op1] - imm)
Cycles: 1
```

Устанавливает флаг Cond: -1 если меньше, 0 если равно, +1 если больше.

### 5.13. JMP / JE / JNE / JL / JG / JLE / JGE (62-69)

```
JMP:  PC = Reg[op1]  (безусловный)
JE:   if Cond == 0:  PC = Reg[op1]
JNE:  if Cond != 0:  PC = Reg[op1]
JL:   if Cond < 0:   PC = Reg[op1]
JG:   if Cond > 0:   PC = Reg[op1]
JLE:  if Cond <= 0:  PC = Reg[op1]
JGE:  if Cond >= 0:  PC = Reg[op1]
JM:   if Cond == 0:  PC = Reg[op1]  (alias for JE)
Cycles: 1 (not taken), 2 (taken)
```

Все переходы — регистрово-косвенные. Адрес перехода хранится в регистре. Для переходов по меткам ассемблер генерирует LIMM+Jxx.

### 5.14. CALL / RET (70-71)

```
CALL: SP = SP - 1; Mem[SP] = PC + 1; PC = Reg[op1]
RET:  PC = Mem[SP]; SP = SP + 1
Cycles: 2
```

CALL сохраняет адрес возврата (PC+1) на стеке и переходит по адресу в регистре. RET восстанавливает PC из стека.

### 5.15. IN / OUT / INI / OUTI (80-83)

```
IN:   Reg[op1] = Device[Reg[op2]]    (чтение из порта)
OUT:  Device[Reg[op2]] = Reg[op1]    (запись в порт)
INI:  Reg[op1] = Device[imm]         (чтение с непосредственным портом)
OUTI: Device[imm] = Reg[op1]         (запись с непосредственным портом)
Cycles: 2
```

Портовый ввод-вывод. Порты идентифицируются 6-тритным (или 18-тритным в регистровом режиме) номером. Порты:
- 0: T-SCII Output (консоль)
- 1: T-SCII Input (запланировано)

### 5.16. FPU инструкции (100-116)

**FADD / FSUB / FMUL / FDIV (100-103):**
```
FADD: F[op1] = F[op2] + F[op3]
FSUB: F[op1] = F[op2] - F[op3]
FMUL: F[op1] = F[op2] * F[op3]
FDIV: F[op1] = F[op2] / F[op3]
```

**FSQRT (104):** `F[op1] = sqrt(F[op2])`

**FABS / FNEG (105-106):** `F[op1] = |F[op2]|`, `F[op1] = -F[op2]`

**FCMP (107):** `Cond = sign(F[op1] - F[op2])`

**FTOI / ITOF (108-109):** Конвертация float ↔ int. Bit-preserving: значение переинтерпретируется без арифметического преобразования. Это критически важно для сохранения FPU на стеке через PUSH/POP.

**FLW / FSW (111-112):**
```
FLW: F[op1] = T3Float(Mem[Reg[op2] + op3])
FSW: Mem[Reg[op2] + op3] = F[op1].toWord18()
```

**FMOV (113):** Многофункциональная пересылка:
- func=0: F[op1] = F[op2] (F→F)
- func=1: F[op1] = float(Reg[op2]) (R→F)
- func=2: Reg[op1] = int(F[op2]) (F→R)

**FZERO (116):** `F[op1] = 0.0`

## 6. Предикация

### 6.1. Модель предикации

Предикация в T3 — трёхзначная. Каждая инструкция может быть обусловлена одним из трёх предикатных флагов, хранящихся в регистре PR (Predicate Register).

PR — 9-тритный регистр, логически разделённый на 3 группы по 3 трита:
- Триты 0-2: Predicate group 0 (p0)
- Триты 3-5: Predicate group 1 (p1)
- Триты 6-8: Predicate group 2 (p2)

Поле Pred в инструкции (3 трита) указывает номер предикатного флага (1-3) или 0 для безусловного выполнения.

### 6.2. Вычисление предиката

```
if pred == 0: execute unconditionally
else:
    flag = PR.GetTrit(pred - 1)  // читает трит pred-1 из PR
    if flag == +1: execute
    else: skip (PC++)
```

Флаг `+1` означает истину (`true`), `0` — неопределённость (`maybe`), `-1` — ложь (`false`). Инструкция выполняется только при `true`.

### 6.3. Установка PR

PR — LSB-first регистр (младший трит — позиция 0):

- Predicate 1 (trit 0): `PR = FromLong(1)` (3^0)
- Predicate 2 (trit 1): `PR = FromLong(3)` (3^1)
- Predicate 3 (trit 2): `PR = FromLong(9)` (3^2)

Для комбинаций флагов значения складываются: `PR = FromLong(1 + 3 + 9)` = все три флага true.

## 7. Арифметика с плавающей точкой (FPU)

### 7.1. Формат T3Float

T3Float — 18-тритный формат с плавающей точкой:

```
[Exponent (6 trits, signed)] [Mantissa (12 trits, signed)]
```

Значение: `value = mantissa × 3^(exponent - bias)`, где bias = 182.

Диапазон:
- Экспонента: -364…+364
- Мантисса: -88,573…+88,573
- Минимальное нормализованное: 3^(-546)
- Максимальное: ~ 3^545

### 7.2. Нормализация

Скрытый трит: старший трит мантиссы не хранится (подразумевается ±1). После каждой операции мантисса сдвигается так, чтобы старший хранимый трит был ненулевым, с соответствующей коррекцией экспоненты.

### 7.3. Специальные значения

| Значение | Экспонента | Мантисса |
|----------|-----------|----------|
| +0 | min (-364) | 0 |
| -0 | min (-364) | 0 (отрицательный ноль — симметричен) |
| +∞ | max (+364) | 0 |
| -∞ | max (+364) | 0 (отрицательная бесконечность) |
| NaN | max (+364) | ≠ 0 |
| Maybe-NaN | max (+364) | старший трит = 0 |

### 7.4. Кодирование в Word18

T3Float кодируется в Word18 линейно:

```
encoded = exponent × 3^12 + mantissa
```

Это даёт однозначное соответствие между T3Float и Word18 благодаря математическим свойствам сбалансированной троичной системы: `3^12 = 531,441`, что больше диапазона мантиссы (±88,573), поэтому поля не перекрываются.

### 7.5. FTOI / ITOF — bit-preserving round-trip

Операции FTOI (float-to-int) и ITOF (int-to-float) реализованы как битовое копирование без арифметического преобразования:

```
FTOI: int_value = float_value.toWord18().toLong()
ITOF: float_value = T3Float.fromWord18(Word18.fromLong(int_value))
```

Это гарантирует, что последовательность `FTOI → PUSH → POP → ITOF` восстанавливает точное исходное значение T3Float, что критически важно для сохранения FPU-регистров на стеке в ABI.

### 7.6. Округление

По умолчанию — к ближайшему, с правилом чётного младшего трита (round to nearest, ties to even). В текущей реализации используется один режим округления.

## 8. Ассемблер T3

### 8.1. Двухпроходный алгоритм

Ассемблер T3 работает в два прохода:

**Первый проход (разрешение меток):**
1. Сканирование всех строк исходного кода
2. Вычисление размера каждой инструкции (1 слово для большинства, 2 для LIMM, 3 для CALL/JMP с меткой)
3. Построение таблицы меток: `label_name → address`
4. Обработка директив `.equ` (константы) и `.string`/`.word` (данные)

**Второй проход (генерация бинарного кода):**
1. Построчное ассемблирование с использованием разрешённых меток и констант
2. Кодирование инструкций через `InstructionEncoder`
3. Формирование выходного списка `List<Int128>` (18-тритные слова)

### 8.2. Expression Evaluator

Ассемблер поддерживает вычисление выражений в операндах:

```
LI R0, myLabel + 4          ; адрес myLabel + 4
LI R1, (BASE + OFFSET) / 2  ; арифметика с константами
```

Поддерживаемые операции: `+`, `-`, `*`, `/`. Операндами могут быть: целые числа, метки, `.equ`-константы, троичные литералы (`0t`, `0y`, `0n`).

### 8.3. Кодирование переходов

Для переходов по меткам ассемблер генерирует 3-словную последовательность:

```
; JMP target
LIMM R1, target      ; слово 1: LIMM + операнд R1
target_address       ; слово 2: абсолютный адрес метки
JMP R1               ; слово 3: регистрово-косвенный переход

; CALL target
LIMM R1, target      ; слово 1: загрузка адреса
target_address       ; слово 2: данные адреса
CALL R1              ; слово 3: вызов
```

Для переходов по регистру — одно слово (J-type encoding).

### 8.4. Директивы

| Директива | Описание | Пример |
|-----------|----------|--------|
| `.equ` | Определение константы | `BUFSIZE equ 256` |
| `.word` | Резервирование слова данных | `myVar: .word 42` |
| `.string` | Строковая константа (null-terminated) | `.string msg "Hello"` |
| `;` | Комментарий до конца строки | `; это комментарий` |
| `label:` | Метка (точка входа) | `loop:` |

## 9. Линкер T3

### 9.1. Архитектура линкера

Линкер T3 объединяет несколько объектных файлов (результатов ассемблирования) в единый исполняемый образ. Процесс линковки включает:

1. **Сбор секций:** объединение `.text`, `.data`, `.bss` из всех объектных файлов
2. **Разрешение символов:** связывание внешних ссылок с определениями
3. **Relocation:** патчинг адресов в LIMM-операндах

### 9.2. Таблица символов

Каждый объектный файл содержит:
- **Экспортируемые символы** (`.global`): доступны другим модулям
- **Импортируемые символы** (`.extern`): должны быть разрешены линкером
- **Локальные символы**: видны только внутри модуля

### 9.3. Секции

| Секция | Назначение | Атрибуты |
|--------|-----------|----------|
| `.text` | Исполняемый код | Read + Execute |
| `.data` | Инициализированные данные | Read + Write |
| `.bss` | Неинициализированные данные (нули) | Read + Write |
| `.rodata` | Константы (строки, float) | Read-only |

### 9.4. Процесс relocation

Для каждого relocation-входа (LIMM-операнд, ссылающийся на внешний символ) линкер:
1. Определяет итоговый адрес символа после объединения секций
2. Патчит 18-тритное слово данных, следующее за LIMM

## 10. Язык T-lang: лексика и синтаксис

### 10.1. Философия языка

T-lang — низкоуровневый язык системного программирования для троичной архитектуры T3, наследующий синтаксис и семантику C, но адаптированный для сбалансированной троичной логики. Ключевые отличия от C:

1. **Троичная логика:** три значения истинности (true/maybe/false) вместо двух
2. **Тринарный оператор:** три ветви (положительная/нулевая/отрицательная)
3. **Троичные литералы:** `0t+-0`, `0yNN`, `0nW04`
4. **Билингвальность:** все ключевые слова имеют русские и английские варианты
5. **Типы, кратные трайту:** tryte (6 тритов), tshort (12), tint (18), tlong (36), tlong long (54)

### 10.2. EBNF грамматика (ключевые правила)

```
(* Лексика *)
trit_digit = "-" | "0" | "+" .
identifier = (letter | "_") { letter | digit | "_" } .
decimal_literal = ["+" | "-"] digit {digit} ("y" | "s" | "t" | "tl" | "tll") .
balanced_literal = "0t" trit_digit {trit_digit} ["_" trit_digit] .
tryx_literal = "0y" tryx_digit {tryx_digit} .  (* 27-ричный *)
nine_literal = "0n" nine_digit {nine_digit} .  (* 9-ричный *)
string_literal = '"' {char} '"' .

(* Типы *)
type_specifier = "void" | "trit" | "tril" | "tryte" | "tshort"
               | "tint" | "tlong" | "tlong long"
               | "tfloat" | "tdouble"
               | struct_or_union_specifier | enum_specifier .

(* Выражения *)
expression = assignment_expr .
assignment_expr = ternary_expr
                | unary_expr assignment_operator assignment_expr .
ternary_expr = logical_or_expr "??" expr ":?" expr ":!" expr .

(* Приоритеты операторов (от высшего к низшему) *)
(* 1: () [] . -> ++ --
   2: ! ~ - + * & sizeof (префиксные)
   3: * / %
   4: + -
   5: << >>
   6: < > <= >=
   7: == !=
   8: & (потритовый минимум)
   9: ^ (потритовая сумма)
   10: | (потритовый максимум)
   11: &&
   12: ||
   13: ?? :? :! (тринарный)
   14: = += -= *= /= %= <<= >>= &= |= ^=
*)

(* Операторы *)
statement = expression_stmt | compound_stmt | selection_stmt
          | switch_stmt | iteration_stmt | jump_stmt
          | labeled_stmt | goto_stmt .

selection_stmt = "if" "(" expr ")" stmt
                ["maybe" stmt] ["else" stmt] .

iteration_stmt = "while" "(" expr ")" stmt
               | "do" stmt "while" "(" expr ")" ";"
               | "for" "(" [expr] ";" [expr] ";" [expr] ")" stmt .

jump_stmt = "return" [expr] ";"
          | "break" ";" | "continue" ";"
          | "goto" identifier ";" .

(* Объявления *)
function_definition = type_specifier declarator compound_stmt .
declaration = type_specifier init_declarator_list ";" .
```

### 10.3. Типы данных

| Тип | Трайтов | Тритов | Диапазон |
|-----|---------|--------|----------|
| `trit` | — | 1 | -1, 0, +1 |
| `tril` | — | 1 | логический трит |
| `tryte` | 1 | 6 | -364 … +364 |
| `tshort` | 2 | 12 | -265 720 … +265 720 |
| `tint` | 3 | 18 | -193 710 244 … +193 710 244 |
| `tlong` | 6 | 36 | -7.6×10^16 … +7.6×10^16 |
| `tlong long` | 9 | 54 | -2.0×10^25 … +2.0×10^25 |
| `tfloat` | 3 | 18 | float (6+12) |
| `tdouble` | 6 | 36 | double (8+28) |

### 10.4. Управляющие конструкции

**Условный оператор (трёхветвевой):**
```
if (условие) действие_истина
maybe действие_может
else действие_ложь
```

Ветви `maybe` и `else` опциональны и могут следовать в любом порядке.

**Тринарный оператор:**
```
условие ?? выраж_истина :? выраж_может :! выраж_ложь
```

Все три выражения вычисляются всегда (нет short-circuit).

**Циклы:**
- `while (условие)` — предусловие
- `do ... while (условие)` — постусловие
- `for (init; condition; step)` — с инициализацией

**Переходы:**
- `break` — выход из цикла/switch
- `continue` — следующая итерация
- `return [expr]` — возврат из функции
- `goto label` — безусловный переход

## 11. T-lang: семантика и ABI

### 11.1. Calling Convention (ABI v4)

**Caller (перед CALL):**
1. Вычисление аргументов (могут содержать вложенные вызовы)
2. Spill всех live локальных переменных на стек: `LOAD [slot]; PUSH`
3. Spill всех FPU-регистров: `FTOI R0, Fx; PUSH R0` (9 регистров × 2 инструкции)
4. Сохранение caller-saved GP-регистров: `PUSH RW..R4` (8 регистров)
5. PUSH аргументов в обратном порядке
6. `LIMM R1, function; CALL R1`

**Callee (пролог):**
1. `POP R2` — сохранение адреса возврата
2. `POP R0; STORE` — извлечение параметров в локальные переменные
3. `PUSH R2` — восстановление адреса возврата
4. `PUSH RW; PUSH RX; ...; PUSH R4` — сохранение callee-saved (8 регистров)

**Callee (тело):**
Выполнение кода функции. Локальные переменные доступны через абсолютную адресацию от `_nextAddr`.

**Callee (эпилог):**
1. `POP R4; POP R1; ...; POP RW` — восстановление callee-saved
2. `RET`

**Caller (после CALL):**
1. `POP R4..RW` — восстановление caller-saved GP
2. `POP R0; ITOF Fx, R0` — восстановление FPU (9 × 2)
3. `POP R0; STORE` — восстановление live локальных переменных
4. `MOV result, R2` — копирование возвращаемого значения

### 11.2. Стековый кадр

```
Перед CALL (стек растёт вниз):
┌─────────────────────┐ ← начальный SP
│  [callee frame]     │
├─────────────────────┤
│  spilled local [0]  │ ← PUSH перед CALL
│  spilled local [1]  │
│  ...                │
│  FTOI F4 → PUSH     │ ← spill FPU
│  FTOI F3 → PUSH     │
│  ...                │
│  FTOI FW → PUSH     │
│  PUSH RW            │ ← caller-saved GP
│  PUSH RX            │
│  ...                │
│  PUSH R4            │
│  PUSH arg[N-1]      │ ← аргументы
│  ...                │
│  PUSH arg[0]        │
├─────────────────────┤ ← CALL ↓
│  return address     │ ← CALL instruction
│  callee PUSH RW..R4 │
│  [callee body]      │
│  callee POP R4..RW  │
│  RET                │
├─────────────────────┤
│  POP R4..RW         │ ← restore caller GP
│  POP+ItoF Fx ...    │ ← restore FPU
│  POP+Store locals   │ ← restore spilled vars
│  MOV result, R2     │
└─────────────────────┘
```

### 11.3. Передача аргументов

- Аргументы передаются через стек (push в обратном порядке)
- Callee извлекает их в прологе и сохраняет в локальные переменные
- Return value: через R2 (не сохраняется/восстанавливается)
- FPU: через FTOI/PUSH + POP/ITOF (bit-preserving round-trip)

### 11.4. Рекурсия

Благодаря spill всех live-переменных перед CALL, рекурсивные функции любой глубины работают корректно. Размер стека 1M слов позволяет ~30,000+ уровней рекурсии с типичными аргументами.

## 12. Стандартная библиотека

### 12.1. tio — Ввод-вывод

**`putchar(char)`:** Выводит один символ через порт 0 (T-SCII Output).
- Реализация: `OUTI R0, 0; RET`

**`printstring(string*)`:** Выводит null-terminated строку.
- Цикл: `LOAD R1, R0; CMPI R1, 0; JE end; CALL putchar; ADDI R0, 1; JMP loop`

**`printint(int)`:** Выводит целое число в десятичном формате.
- Алгоритм: деление на 10 (DIV/MOD), цифры сохраняются на стеке (reverse order), выводятся через putchar
- Отрицательные числа: вывод '-', затем NEG, затем цифры

**`printfloat(float)`:** Выводит float с 6 знаками после запятой.
- Целая часть: FTOI + printint
- Дробная часть: 6 итераций FMUL×10, FTOI, вывод цифры

### 12.2. tmath — Математика

**`tabs(x)`:** Абсолютное значение. `CMPI x, 0; JGE done; NEG; RET`

**`tmin(a,b)` / `tmax(a,b)`:** Минимум/максимум через CMP + условный MOV.

**`tpow(base, exp)`:** Возведение в степень через цикл.

**`tfact(n)`:** Факториал через рекурсивный вызов или цикл.

### 12.3. tstring — Строки

**`tstrlen(s)`:** Длина строки. Цикл: `LOAD R1, R0; CMPI R1, 0; JE end; ADDI R2, 1; ADDI R0, 1; JMP loop`

**`tstrcpy(dst, src)`:** Копирование строки побайтово до null.

**`tstrcmp(a, b)`:** Лексикографическое сравнение. Возвращает Cond.

**`tstrcat(dst, src)`:** Конкатенация: поиск конца dst, затем копирование src.

### 12.4. tstdlib — Общие утилиты

**`tmalloc(size)`:** Простой bump-аллокатор. Выделяет `size` слов из heap.
- Heap начинается после секции данных
- Указатель heap инкрементируется на size

**`tfree(ptr)`:** Заглушка (освобождение не реализовано в bump-аллокаторе).

**`texit(code)`:** HALT с кодом возврата.

## 13. Дальнейшие направления

### 13.1. Ближайшие (Phase 14)

- **Оптимизация FPU spill:** не сохранять FPU если не используются float-переменные
- **Better register allocator:** linear scan вместо round-robin
- **Constant folding:** вычисление константных выражений на этапе компиляции
- **Stack overflow detection:** проверка SP при CALL/PUSH

### 13.2. Среднесрочные (Phase 15-16)

- **T3-54 (Word54) процессор:** 54-тритные инструкции, расширенная точность
- **Pipeline simulation:** cycle-accurate симуляция микроархитектуры
- **Register windowing:** 27 физических регистров с WP-маппингом
- **Debug information:** `.loc`/`.file` директивы, source mapping

### 13.3. Долгосрочные (Phase 17+)

- **VLIW/SIMD:** пакетная обработка в 54-тритных словах
- **MMU / virtual memory:** страничная адресация
- **Interrupt controller:** векторы прерываний, обработка исключений
- **Multicore:** многопоточное исполнение
