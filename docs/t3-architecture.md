# Архитектура процессора T3 (v5) — Техническое руководство

## 1. Введение

**T3** — это исследовательский прототип процессора, базирующийся на **сбалансированной троичной системе счисления (Balanced Ternary)**. В отличие от традиционных двоичных систем, T3 оперирует тремя состояниями трита: $\{-1, 0, +1\}$.

Основной целью архитектуры является исследование эффективности троичных вычислений и реализация максимально ортогональной системы команд. Ключевой инновацией T3 является механизм **RegGroup**, который позволяет одной и той же инструкции работать с разными наборами регистров (целочисленными, вещественными или системными) без изменения опкода.

---

## 2. Представление данных

### 2.1. Сбалансированная троичная система
Все данные представлены в сбалансированном виде. Это обеспечивает:
- **Эффективный знак**: Отрицание числа выполняется простой инверсией всех тритов.
- **Симметрию**: Диапазоны чисел центрированы относительно нуля.

### 2.2. Типы данных
| Тип | Размер | Описание | Применение |
| :--- | :--- | :--- | :--- |
| **Word18** | 18 тритов | $\pm 193,710,244$ | Базовое слово, адреса, целые числа (`tint`) |
| **Tlong** | 36 тритов | $\pm 3.7 \times 10^{11}$ | Расширенные целые числа |
| **Tlong long** | 54 трита | $\pm 6.8 \times 10^{17}$ | Сверхвысокая точность |
| **T3Float** | 18 тритов | 6 тритов эксп. / 12 тритов мант. | Числа с плавающей точкой (одинарная точность) |
| **T3Double** | 36 тритов | 8 тритов эксп. / 28 тритов мант. | Числа с плавающей точкой (двойная точность) |

### 2.3. Формат T3Float
Для обеспечения высокой плотности данных используется специфическая модель:
- **Экспонента**: Смещение (bias) = 182.
- **Мантисса**: Нормализованное значение в диапазоне $\pm (3^{12}-1)/2$.
- **Представление**: $\text{value} = \text{exponent} \cdot 3^{12} + \text{mantissa}$.

## 3. Организация памяти

Процессор использует линейную модель адресации объемом **1 МБ** ($1,048,576$ слов по 18 тритов).

### 3.1. Карта памяти
| Сегмент | Диапазон адресов | Рост | Назначение |
| :--- | :--- | :---: | :--- |
| **Код** | $0 \dots 299$ | $\rightarrow$ | Исполняемые инструкции |
| **Данные** | $300 \dots 699,049$ | $\rightarrow$ | Глобальные переменные и статические данные |
| **Куча (Heap)** | $699,050 \dots$ | $\rightarrow$ | Динамическая память (база $\rightarrow$ `S.HP`) |
| **Стек (Stack)** | $\dots 1,048,575$ | $\leftarrow$ | Кадры вызовов и локальные переменные (база $\rightarrow$ `S.SP`) |

## 4. Регистровая архитектура и RegGroup

Центральный элемент T3 — система **RegGroup**. Она позволяет разделять физические регистровые файлы, используя один и тот же индекс в инструкции.

### 4.1. Регистровые группы
Поле `RegGroup` (1 трит) в инструкции определяет контекст доступа:

| Значение | Группа | Префикс | Регистры | Назначение |
| :---: | :--- | :---: | :--- | :--- |
| $0$ | **General Purpose (GP)** | (нет) | RW, RX, RY, RZ, R0..R4 | Целые числа, адресация, логика |
| $-1$ | **Floating Point (FPU)** | `F.` | FW, FX, FY, FZ, F0..F4 | Вещественные вычисления |
| $+1$ | **Special (SP)** | `S.` | FP, HP, SP, CD, PR, WD | Управление системой, стек, куча |

### 4.2. Маппинг индексов
Все индексы регистров в инструкциях задаются в сбалансированном виде (от $-4$ до $+4$) и мапятся на физические индексы $0 \dots 8$ через смещение $+4$.

## 5. Система команд (ISA v5)

### 5.1. Структура инструкции
Инструкция имеет фиксированную длину **18 тритов**:
`[ Pred(3) ] [ RegGroup(1) ] [ Fmt(1) ] [ Opcode(4) ] [ Args(9) ]`

- **Pred (Предикация)**: Команда выполняется только если соответствующий флаг в `S.PR` истинен.
- **RegGroup**: Выбор активного регистрового файла (GP, FPU, Special).
- **Fmt (Формат)**: Определяет интерпретацию поля Args (R, S, I, J).
- **Opcode**: Идентификатор операции (поддержка до 81 опкода).

### 5.2. Типы аргументов
- **R-type**: `[Reg1][Reg2][Reg3]` — три регистра.
- **S-type**: `[Reg1][Reg2][Imm(3)]` — два регистра и короткое смещение ($\pm 13$).
- **I-type**: `[Reg1][Imm(6)]` — один регистр и константа ($\pm 364$).
- **J-type**: `[Target/Reg][Padding]` — адрес или регистр для перехода.

### 5.3. Ортогональность
Благодаря RegGroup, ALU-операции работают идентично для разных групп. Например:
- `ADD R0, R1, R2` $\rightarrow$ целочисленное сложение в GP.
- `F.ADD F0, F1, F2` $\rightarrow$ вещественное сложение в FPU.
- `S.ADD SP, SP, #1` $\rightarrow$ изменение указателя стека в Special.

Перенос данных между группами осуществляется через кросс-групповые команды: `FTI` (Float $\rightarrow$ Int) и `ITF` (Int $\rightarrow$ Float).

## 6. Модель вызовов и ABI v4

### 6.1. Передача параметров и возврат
Используется гибридная модель "Регистры $\rightarrow$ Стек":
- **Аргументы**: Первые 4 передаются в регистрах (`RW, RX, RY, R0` для целых; `FW, FX, FY, FZ` для вещественных). Остальные — через стек.
- **Возврат**: Результаты помещаются в `R2` (целые) или `F2` (вещественные). Для `Tlong` используется пара `R2:R3`.

### 6.2. Аппаратная поддержка кадров (S.FP)
Инструкции `CALL` и `RET` реализуют автоматическое управление Frame Pointer (`S.FP`):
- **CALL**:
    1. Сохраняет текущий `S.FP` и адрес возврата (`PC+1`) в стек.
    2. Устанавливает `S.FP = S.SP`.
    3. Переходит по адресу целевой функции.
- **RET**:
    1. Восстанавливает `S.FP` и возвращает управление по адресу из стека.
    2. Освобождает стек от записи кадра.

### 6.3. Структура стекового фрейма
Локальные переменные и сохраненные регистры адресуются относительно `S.FP` (отрицательные смещения):
`[ Аргументы 4..N ]` $\rightarrow$ `[ Saved FP ]` $\rightarrow$ `[ Return Addr ]` $\rightarrow$ **`S.FP`** $\rightarrow$ `[ Saved Regs ]` $\rightarrow$ `[ Locals ]` $\rightarrow$ **`S.SP`**

## 7. Конвейер исполнения

Процесс обработки инструкции:
1. **Fetch**: Извлечение слова из памяти по адресу `PC`.
2. **Decode**: Разбор полей (Pred, RegGroup, Fmt, Opcode).
3. **Predicate Check**: Проверка условия выполнения через `S.PR`.
4. **Route**: Направление операции в ALU, FPU или Special-блок на основе `RegGroup`.
5. **Execute**: Выполнение операции.
6. **Write-back**: Запись результата в целевой регистр или память.

---

## 8. Программный стек (Toolchain)

Для работы с архитектурой T3 разработан полный набор инструментов:
- **T3Assembler**: Компиляция ASM в бинарный код с жесткой валидацией `RegGroup`.
- **T3Compiler**: Компиляция высокоуровневого языка `T-lang` в ASM.
- **T3Simulator**: Высокоточный эмулятор для анализа состояния системы.
- **T3Interpreter**: Референсная модель ISA для верификации корректности вычислений.
