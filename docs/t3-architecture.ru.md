# Архитектура процессора T3 — v5 (Исследовательский прототип)

## Типы слов

- **Word18**: 18 тритов, хранится как `long` (64 бита). Диапазон: ±193 710 244
- **Word54**: 54 трита, хранится как `Int128`. Диапазон: ±2.9×10²⁵
- **T3Float**: 18-тритный float (6 порядок + 12 мантисса). Смещение (bias) = 182. Линейное кодирование: `значение = порядок * 3^12 + мантисса`
- **T3Double**: 36-тритный float (8 порядок + 28 мантисса). Смещение (bias) = 3280.

## Регистровый файл

**GP Регистры (Общего назначения):**
| Имя | Трит | Phys | Назначение | Сохраняется Caller-ом |
|------|------|------|-----------|-------------------|
| RW | -4 | 0 | Временный | Да |
| RX | -3 | 1 | Временный | Да |
| RY | -2 | 2 | Временный | Да |
| RZ | -1 | 3 | **База кадра (FP)** / Временный | Да |
| R0 | 0 | 4 | Временный | Да |
| R1 | +1 | 5 | Вспомогательный (вызов) | Да |
| R2 | +2 | 6 | Возвращаемое значение | Нет |
| R3 | +3 | 7 | Сохраняется Callee | Да |
| R4 | +4 | 8 | Регистр адреса | Да |

**Регистры FPU (F.):** `FW, FX, FY, FZ, F0, F1, F2, F3, F4` (отдельный регистровый файл, отображается на те же физические индексы 0..8).

**Специальные регистры (S.):** `FP` (указатель кадра), `HP` (указатель кучи), `SP` (указатель стека), `CD` (флаг условия), `PR` (предикаты), `WD` (указатель окна).

*Примечание: механизм оконных регистров запланирован, но ещё не интегрирован в модель исполнения.*

## Формат инструкции

```
[Pred (3)] [Opcode (6)] [Args (9)]
```

- R-тип: Args = `[Op1(3)] [Op2(3)] [Op3(3)]`
- I-тип: Args = `[Op1(3)] [Imm(6)]`
- J-тип: Args = `[Reg(3)] [000000]`

Регистры кодируются тритовым значением (-4..+4). Физический индекс = trit + 4.

### Детали кодирования

**Поле Pred** (позиции 15-17, LSB-first): raw unsigned, 0..13. Если pred > 0, инструкция выполняется только если PR[pred-1] == +1.

**Поле Opcode** (позиции 9-14): raw unsigned, 0..364.

**Поле Args** (позиции 0-8): raw unsigned, затем подполя извлекаются и конвертируются в сбалансированные путем вычитания смещения:
- 3-тритное подполе: смещение = 13, диапазон ±13
- 6-тритное подполе (Imm в I-типе): смещение = 364, диапазон ±364 (включая LI)

**J-тип**: Регистр в позиции Op1 (3 трита). Op2 и Op3 — заполнение (6 тритов, всегда 0). Imm явно устанавливается в 0 декодером.

**LOADI/STOREI**: Используют S-тип кодирования через `EncodeS(pred, opcode, op1, op2, imm3)` с 3-тритным immediate полем (±13 диапазон). Декодер обрабатывает их как специальный I-тип с 3-тритным imm.

### Кодировщик (InstructionEncoder)

```csharp
long EncodeR(int pred, int opcode, int op1, int op2, int op3)
long EncodeI(int pred, int opcode, int op1, long imm)
long EncodeJ(int pred, int opcode, int reg)
long EncodeS(int pred, int opcode, int op1, int op2, long imm3)  // LOADI/STOREI
```

Все знаковые операнды конвертируются в беззнаковые через `ToUnsignedField(value, range, offset)`:
- `unsigned = value + offset`, где `offset = (3^width - 1) / 2`

### Декодер (InstructionDecoder)

```csharp
DecodedInstruction Decode(Word18 word)
DecodedInstruction Decode(Word54 word)  // использует Word18.FromWrappedLong()
```

Процесс декодирования:
1. Извлечение Pred: `ExtractRawField(word, 15, 3)` — raw unsigned
2. Извлечение Opcode: `ExtractRawField(word, 9, 6)` — raw unsigned
3. Извлечение Args: `ExtractRawField(word, 0, 9)` — raw unsigned
4. В зависимости от типа (R/I/J):
    - R-тип: извлечение Op1/Op2/Op3 из Args (по 3 трита), конвертация в сбалансированные: `value - 13`
    - I-тип: извлечение Op1 (3 трита) и Imm (6 тритов) из Args, конвертация в сбалансированные: Op1 -= 13, Imm -= 364
    - J-тип: извлечение Reg (3 трита) из Args, конвертация в сбалансированные: Reg -= 13. Imm = 0
    - LOADI/STOREI: извлечение Op1 (3 трита), Op2 (3 трита), Imm (3 трита), конвертация в сбалансированные

## Память

- 1M слов (1 048 576) типа Word18/Word54.
- Стек растёт вниз, SP начинается с MemSize-1.
- PUSH: `SP--; Memory[SP] = value`
- POP: `value = Memory[SP]; SP++`
- CALL: `SP--; Memory[SP] = PC + 1; PC = target`
- RET: `PC = Memory[SP]; SP++`
- MMIO: CYCLE_LOW, CYCLE_HIGH, INST_COUNT, STALL_COUNT.

## Модель исполнения (In-Order Прототип)

Текущая реализация является функциональным интерпретатором.

1. **Fetch**: `word = Memory[PC]`
2. **Decode**: извлечение Pred, Opcode, Args через `InstructionDecoder.Decode()`
3. **Predicate**: пропуск, если условие предиката не выполнено (проверка тритов PR)
4. **Execute**: выполнение через `T3Alu` (целые) или `T3Fpu` (плавающая точка)
5. **PC advance**: продвижение PC (если нет перехода/прыжка)

### Детали предикации

- `GetPredicateFlag(predIndex)` читает `PR.GetTrit(predIndex - 1)`:
  - predIndex=1 → PR.GetTrit(0) (LSB, 3^0)
  - predIndex=2 → PR.GetTrit(1) (3^1)
  - predIndex=3 → PR.GetTrit(2) (3^2)
- Если значение трита == +1, предикат истинен, инструкция выполняется.
- Если значение трита == 0 или -1, инструкция пропускается (PC просто увеличивается).

**Установка PR**:
- Предикат 1 = true → `PR = Word18.FromLong(1)` (3^0)
- Предикат 2 = true → `PR = Word18.FromLong(3)` (3^1)
- Предикат 3 = true → `PR = Word18.FromLong(9)` (3^2)

## Формат T3Float

**Структура**: 6 тритов порядка (смещение 182) + 12 тритов мантиссы = 18 тритов.

- Диапазон порядка: ±364 (signed balanced)
- Диапазон мантиссы: ±88 573 (signed balanced)
- Значение: `мантисса * 3^(порядок - 182)`
- Кодирование: `значение = порядок * 3^12 + мантисса` (прямая линейная арифметика)

**ToWord18()**:
```csharp
long encoded = Exponent * (long)TernaryMath.Pow3(12) + Mantissa;
return Word18.FromLong(encoded);
```

**FromWord18()**:
```csharp
long pow12 = (long)TernaryMath.Pow3(12);
long raw = word.ToLong();
long exponent = raw / pow12;
long mantissa = raw % pow12;
return new T3Float(exponent, mantissa);
```

**КРИТИЧЕСКИ ВАЖНО**: НЕ используйте строковую конвертацию (`ToTritString()`/`FromTritString()`) для кодирования T3Float. Функция `ExtractBalancedTrit`, используемая в `ToTritString()`, имеет фундаментальную проблему с переносом разрядов между полями порядка и мантиссы. Линейное арифметическое кодирование корректно, так как деление и остаток работают с целыми числами, и переносы в сбалансированном троичном представлении не влияют на целочисленное деление.

## Операции FPU

FPU регистры (FW..F4) используют те же физические слоты, что и целочисленные регистры (RW..R4), но хранят значения `T3Float`.

| Опкод | Мнемоника | Описание |
|-------|------------|-----------|
| 100 | FADD | Fop1 = Fop2 + Fop3 |
| 101 | FSUB | Fop1 = Fop2 - Fop3 |
| 102 | FMUL | Fop1 = Fop2 * Fop3 |
| 103 | FDIV | Fop1 = Fop2 / Fop3 |
| 104 | FSQRT | Fop1 = sqrt(Fop2) |
| 105 | FABS | Fop1 = abs(Fop2) |
| 106 | FNEG | Fop1 = -Fop2 |
| 107 | FCMP | Cond = sign(Fop1 - Fop2) |
| 108 | FTOI | Rop1 = int(Fop2) |
| 109 | ITOF | Fop1 = float(Rop2) |
| 110 | FTOF | tfloat ↔ tdouble |
| 111 | FLW | Fop1 = mem[Rop2 + op3] |
| 112 | FSW | mem[Rop2 + op3] = Fop1 |
| 113 | FMOV | func:0=F→F, 1=R→F, 2=F→R |
| 114 | FCLASS | Классифицировать Fop2 |
| 115 | FSWAP | Обмен Fop1↔Fop2 |
| 116 | FZERO | Fop1 = 0.0 |

## LIMM (Large Immediate)

2-словная инструкция для загрузки значений вне диапазона ±364.

```
Слово 1: [Pred(3)] [Opcode=LIMM(5)] [Reg(3)] [000000]
Слово 2: [данные (18 тритов)]
```

Процессор: `Register[reg] = Memory[PC]; PC++`

## ABI Компилятора v4 (T-lang)

### Модель регистров

| Регистр | Phys | Назначение |
|---------|------|-----------|
| RW (0) | 0 | Временный, аргумент 0 |
| RX (1) | 1 | Временный, аргумент 1 |
| RY (2) | 2 | Временный, аргумент 2 |
| RZ (3) | 3 | **Указатель фрейма** (FP) |
| R0 (4) | 4 | Временный, аргумент 3 |
| R1 (5) | 5 | Вспомогательный регистр вызова |
| R2 (6) | 6 | Возвращаемое значение (НЕ сохраняется) |
| R3 (7) | 7 | Сохраняется Callee |
| R4 (8) | 8 | Регистр адреса (сохраняется Callee) |

### Пролог

```asm
PUSH RZ          ; сохранить старый FP
PUSH R3          ; callee-saved
PUSH R4          ; callee-saved
MOV RZ, SP       ; RZ = FP
SUBI SP, SP, N   ; выделить локальный фрейм (N слов)
```

### Эпилог

```asm
ADDI SP, SP, N   ; освободить локальный фрейм
POP R4
POP R3
POP RZ
RET
```

### Соглашение о вызовах

1. Вызывающий помещает аргументы в стек
2. `LIMM R1, функция` + `CALL R1`
3. Вызываемый (пролог): PUSH RZ/R3/R4, установить FP, выделить локальные
4. Вызываемый сохраняет регистровые аргументы 0..3 в локальные слоты
5. Тело функции
6. Возвращаемое значение в R2
7. Вызываемый (эпилог): освободить локальные, POP R4/R3/RZ, RET

### Распределение регистров

Round-robin аллокатор `AllocR()` / `FreeR()` с зарезервированными регистрами:
- R1 (phys 5) — адрес цели вызова
- R2 (phys 6) — возвращаемое значение
- R4 (phys 8) — регистр адреса
- RZ (phys 3) — указатель фрейма

Доступные временные регистры: RW(0), RX(1), RY(2), R0(4), R3(7). С 5-ю временными регистрами сложные выражения используют **PUSH/POP в стек** для защиты живых значений от переиспользования регистров.

### FlatIdx — Индексация многомерных массивов

Для массивов `tint a[D1][D2]...[Dn]`:

```
FlatIdx(строка, столбец, ...) = (...строки) * D2 * D3 * ... * Dn + столбец * D3 * ... * Dn + ...
```

Генерируемый код использует PUSH/POP для сохранения аккумулятора при умножениях на размерности.

### Защита регистров от перезаписи

Методы `EmitArrStore`, `EmitArrAccess`, `EmitMemStore` и `EmitMemAccess` используют **PUSH/POP** для защиты регистров значений/индексов от перезаписи аллокатором регистров при вычислении адреса (вызовы FlatIdx, LabelAddr, Imm).

### Расположение в памяти

```
Стек (растёт вниз, SP начинается с MemSize-1):
┌─────────────────────┐ ← начальный SP (1048575)
│   ...               │
├─────────────────────┤
│  сохранённый R4     │ ← RZ (FP указывает сюда после MOV RZ, SP)
├─────────────────────┤
│  сохранённый R3     │
├─────────────────────┤
│  сохранённый RZ     │
├─────────────────────┤
│  адрес возврата     │
├─────────────────────┤
│  аргументы стека    │
├─────────────────────┤
│  локальные переменные│ ← SP после аллокации фрейма
└─────────────────────┘

Секция данных начинается с адреса 300.
Секция кода начинается с адреса 0.
```

## Инфраструктура отладки

### Конфигурация отладочных дампов

`CompilerDebugConfig.EnableDumps` (в `src/T3Compiler/CompilerDebugConfig.cs`) управляет генерацией дампов:

- **AST дамп** (`.ast.txt`): Сериализованное AST-дерево через `AstDumper.Dump()`
- **ASM дамп** (`.asm`): Сгенерированный ассемблерный код
- **Бинарный дамп** (`.bin.txt`): Троичное бинарное представление (строки из 18 тритов на слово)
- **Дамп финального состояния** (`.final.state.txt`): Состояние регистров и памяти после выполнения
- **Дамп состояния при падении** (`.crash.state.txt`): Состояние при исключении
- **Трассировка** (`.trace.txt`): Пошаговый лог выполнения инструкций

Дампы записываются в директорию `test_results/`.
