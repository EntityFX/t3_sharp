# Троичный процессор T3 — Справочник по архитектуре

## 1. Введение

Семейство процессоров **T3** — это набор троичных вычислительных ядер с единой системой команд (ISA), работающих в **сбалансированной троичной системе счисления**. Каждый разряд (**трит**) принимает одно из трёх значений: **−1**, **0** или **+1**, обозначаемых символами `-`, `0` и `+`.

Архитектура поддерживает две конфигурации разрядности:

| Конфигурация | Разрядность слова | VLIW | Применение |
|--------------|-------------------|------|------------|
| **T3‑18** | 18 тритов (3 трайта) | Нет | Обучение, встраиваемые системы |
| **T3‑54** | 54 трита (9 трайтов) | Да | Высокопроизводительные вычисления |

T3‑54 включает VLIW‑микроархитектуру с предикацией, спекулятивным выполнением и SIMD‑операциями — три 18‑тритных слота в одном 54‑тритном слове.

---

## 2. Типы данных и форматы

### 2.1. Трит, трайт, слово

| Единица | Разрядность | Диапазон | Хранение (C#) |
|---------|-------------|----------|----------------|
| **Трит** | 1 | −1, 0, +1 | `sbyte` |
| **Трайт** | 6 тритов | −364 … +364 | `short` (9 бит) |
| **Word18** | 18 тритов | ±193 710 244 | `long` / `int` |
| **Word54** | 54 трита | ±2,9 × 10²⁵ | `BigInteger` / `Int128` |

### 2.2. Представление чисел

Числа хранятся в сбалансированной троичной системе. Отрицательные значения представляются естественным образом — старший трит равен `-`.  
Например, десятичное значение −5 в 6‑тритном представлении: `- + 0 -` (так как −9 + 3 + 0 + 1 = −5).

## 3. Регистровая модель

### 3.1. Регистры общего назначения

Девять логических регистров: **RW, RX, RY, RZ, R0, R1, R2, R3, R4** (индексы 0–8).

| Индекс | Имя | Назначение |
|--------|-----|------------|
| 0 | RW | Общего назначения / рабочая переменная |
| 1 | RX | Общего назначения |
| 2 | RY | Общего назначения |
| 3 | RZ | Общего назначения |
| 4 | R0 | Общего назначения |
| 5 | R1 | Общего назначения |
| 6 | R2 | Общего назначения |
| 7 | R3 | Общего назначения |
| 8 | R4 | Общего назначения |

Разрядность каждого регистра соответствует разрядности слова конфигурации (18 тритов в T3‑18, 54 трита в T3‑54).

### 3.2. Специальные регистры

| Регистр | Разрядность | Описание |
|---------|-------------|----------|
| **SP** | Слово | Указатель стека. Указывает на вершину стека. Начальное значение: `MemSize − 1`. |
| **PC** | Слово | Счётчик команд. Указывает на следующую выполняемую инструкцию. |
| **Cond** | 1 трит | Флаг условия. Устанавливается командами `CMP`, `FCMP`. Значения: `-` (меньше), `0` (равно), `+` (больше). |
| **PR** | 9 / 27 тритов | Предикатный регистр. T3‑18: 3 флага × 3 трита (p0, p1, p2). T3‑54: 9 флагов. |

### 3.3. Регистровое окно (расширение T3‑54)

В конфигурации T3‑54 VLIW процессор может использовать механизм **регистрового окна** с 27 физическими регистрами и указателем окна `WP` (Window Pointer). `CALL` уменьшает `WP` на 4, предоставляя вызываемой функции свежие регистры; `RET` восстанавливает предыдущее окно.

## 4. Память и адресация

### 4.1. Карта памяти

| Диапазон адресов | Содержимое |
|------------------|------------|
| `0x00000` – `0xFFFFE` | Память программ и данных (1М слов) |
| `0x3FFFF00` | `CYCLE_LOW` — счётчик тактов (чтение/запись; запись сбрасывает все счётчики) |
| `0x3FFFF01` | `INST_COUNT` — количество выполненных инструкций/бандлов |
| `0x3FFFF02` | `STALL_COUNT` — количество тактов остановов |
| `0x3FFFF10` | `TIMER_CTRL` — управление таймером |
| `0x3FFFF11` | `TIMER_CMP` — значение сравнения таймера |

- Память адресуется **пословно**. Каждый адрес содержит одно слово (18 или 54 трита).
- Максимальный объём физической памяти в симуляторе: **1М слов** (1 048 576).
- Стек растёт **вниз**; `SP` указывает на верхний элемент.

### 4.2. Режимы адресации

| Режим | Пример синтаксиса | Описание |
|-------|-------------------|----------|
| **Регистровый** | `ADD RW, RX` | Операнды в регистрах |
| **Непосредственный** | `LI RW, 100t` | Малая константа в инструкции (I‑тип, imm6) |
| **Косвенный** | `LOAD RW, RX` | Адрес находится в регистре RX |
| **Длинный непосредственный** | `LIMM RW, 1000000t` | Значение в следующем слове памяти |

## 5. Форматы инструкций

Все инструкции занимают ровно **одно 18‑тритное слово**.

### 5.1. R‑тип (регистр–регистр)

```
[ opcode+pred (6) | op1 (3) | op2 (3) | op3 (3) | резерв/func (3) ]
```

| Поле | Разрядность | Описание |
|------|-------------|----------|
| `opcode+pred` | 6 тритов | `базовый_опкод + индекс_предиката × 28` |
| `op1` | 3 трита | Регистр назначения (0–8) |
| `op2` | 3 трита | Исходный регистр 1 (0–8) |
| `op3` | 3 трита | Исходный регистр 2 (0–8) |
| `резерв/func` | 3 трита | Зарезервировано (0) или код функции для FPU |

**Декодирование:**
```
индекс_предиката = (opcode+pred) / 28
базовый_опкод = (opcode+pred) % 28
```

### 5.2. I‑тип (регистр–непосредственное значение)

```
[ opcode+pred (6) | op1 (3) | op2 (3) | imm6 (6) ]
```

| Поле | Разрядность | Описание |
|------|-------------|----------|
| `opcode+pred` | 6 тритов | Та же кодировка, что и в R‑типе, но базовый опкод ≥ 64 для I‑вариантов |
| `op1` | 3 трита | Регистр назначения |
| `op2` | 3 трита | Исходный регистр (игнорируется для чистых непосредственных загрузок) |
| `imm6` | 6 тритов | Знаковое непосредственное значение: −364 … +364 |

### 5.3. Слот VLIW (только T3‑54)

Каждый слот внутри 54‑тритного VLIW‑бандла использует 18‑тритный формат:

```
[ opcode+pred (6) | op1 (6) | op2 (6) ]
```

- 6‑тритные операнды: значения 0–8 обозначают регистры; значения 9+ — непосредственные константы (−364…+364).

## 6. Микроархитектуры

### 6.1. Последовательный процессор (In‑Order, T3‑18 и T3‑54)

- **Одно АЛУ**, последовательное исполнение.
- Нет конвейера, спекуляции, SIMD.
- Предикация эмулируется (NOP при неудаче предиката).
- Инструкции с кодами 28–44 **недопустимы** в T3‑18.

**Задержки инструкций (такты):**

| Инструкция | T3‑18 | T3‑54 |
|------------|-------|-------|
| HALT, MOV, LI, NEG, TRITAND, TRITOR, TRITXOR, CMP | 1 | 1 |
| LOAD, STORE | 2 | 2 |
| ADD, SUB, SHL, SHR | 1 | 1 |
| MUL | 5 | 8 |
| DIV, MOD | 10 | 15 |
| JMP | 1 | 1 |
| JE, JNE, JL, JG, JM (не переход / переход) | 1 / 2 | 1 / 2 |
| CALL, RET | 2 | 2 |
| PUSH, POP | 2 | 2 |
| LIMM | 2 | 2 |
| IN, OUT, INI, OUTI | 2 | 2 |

### 6.2. VLIW процессор (только T3‑54)

- **Три идентичных АЛУ**.
- **Бандл** = три 18‑тритных слота в одном 54‑тритном слове.
- Параллельное выполнение с ограничениями по конфликтам.

**Правила VLIW:**
- Двум слотам запрещено писать в один и тот же регистр.
- Не более **одного обращения к памяти** на бандл (приоритет: слот 0 > 1 > 2).
- Не более **одного перехода** на бандл.
- **Спекуляция**: теневой регистровый файл + отложенный буфер записи с инструкциями `SPEK`/`COMMIT`/`ROLLBACK`.
- **SIMD** инструкции (VADD3, VSUB3, VMUL3 и др.) обрабатывают каждое 54‑тритное слово как три независимых 18‑тритных поля.

---

## 7. Механизм спекуляции (VLIW)

| Инструкция | Описание |
|------------|----------|
| **SPEK** | Начать спекулятивный участок: сохранить снимок регистров, перенаправить записи в буфер |
| **COMMIT** | Подтвердить спекуляцию: применить буферизованные записи, отбросить теневое состояние |
| **ROLLBACK** | Отменить спекуляцию: восстановить регистры из снимка, отбросить буферизованные записи |

Спекуляция позволяет процессору выполнять код до подтверждения предсказанного перехода. Если предсказание верно — результаты фиксируются; иначе — состояние откатывается.

---

## 8. SIMD‑операции (VLIW, T3‑54)

SIMD‑инструкции работают с тремя 18‑тритными подсловами, упакованными в 54‑тритное слово:

| Мнемоника | Описание |
|-----------|----------|
| VADD3 | Поэлементное сложение трёх 18‑тритных полей |
| VSUB3 | Поэлементное вычитание |
| VMUL3 | Поэлементное умножение |
| VDOT3 | Скалярное произведение трёхэлементных векторов |
| VCMP | Поэлементное сравнение |
| VTRITAND3 | Поэлементное потритовое И (минимум) |
| VTRITOR3 | Поэлементное потритовое ИЛИ (максимум) |
| VTRITXOR3 | Поэлементное потритовое исключающее ИЛИ (сумма по модулю 3) |
| VSHL3 | Поэлементный сдвиг влево |
| VSHR3 | Поэлементный сдвиг вправо |

## 9. FPU (сопроцессор плавающей точки)

### 9.1. Форматы

| Формат | Разрядность | Порядок | Мантисса | Смещение |
|--------|-------------|---------|----------|----------|
| **tfloat** | 18 тритов | 6 тритов | 12 тритов (скрытый трит) | 182 |
| **tdouble** | 36 тритов | 8 тритов | 28 тритов (скрытый трит) | 3280 |

Специальные значения: ноль, бесконечность (+∞, −∞), NaN, maybe‑NaN.

Округление по умолчанию: **к ближайшему, с правилом чётного младшего трита**.

### 9.2. Регистры FPU

Девять регистров данных: **FW, FX, FY, FZ, F0, F1, F2, F3, F4** (индексы 0–8).

- **Режим tfloat**: каждый регистр хранит 18 тритов.
- **Режим tdouble**: используются пары регистров — (FW, FX), (FY, FZ), (F0, F1), (F2, F3). F4 в парах не участвует.

**FSR** (регистр состояния FPU) доступен через порт `0x20`:

| Бит | Флаг | Описание |
|-----|------|----------|
| 0 | I (Invalid) | Недопустимая операция (например, sqrt отрицательного) |
| 1 | O (Overflow) | Переполнение (результат слишком велик) |
| 2 | U (Underflow) | Антипереполнение (результат слишком мал) |
| 3 | Z (DivZero) | Деление на ноль |
| 4 | M (Maybe‑NaN) | Результат — maybe‑NaN |

Исключения **не** вызывают прерываний; в регистр назначения записывается соответствующее специальное значение (∞, 0, NaN).

## 10. Подсистема ввода‑вывода

### 10.1. Адресное пространство портов

18‑тритное адресное пространство портов: до 262 144 портов.

| Порт | Устройство |
|------|------------|
| 0 | stdout |
| 1 | stdin |
| 2 | stderr |
| 3–7 | Свободные / пользовательские |
| 0x10–0x1F | Управление таймером / MMIO |
| 0x20 | Регистр состояния FPU (FSR) |

### 10.2. Инструкции ввода‑вывода

| Мнемоника | Тип | Описание |
|-----------|-----|----------|
| IN | R | `op1 = port[op2]` — чтение из порта (op2 — регистр с номером порта) |
| OUT | R | `port[op2] = op1` — запись в порт |
| INI | I | `op1 = port[imm6]` — чтение из порта с непосредственным номером |
| OUTI | I | `port[imm6] = op1` — запись в порт с непосредственным номером |

Если порт не готов, `IN` вызывает останов до появления данных.

## 11. Кодировка T‑SCII

T‑SCII (Ternary Standard Code for Information Interchange) — 6‑тритная (трайтовая) кодировка, совместимая с CP‑1251.

### 11.1. Диапазоны кодов

| Значение (V) | Беззнаковое (U) | Содержимое |
|--------------|-----------------|------------|
| −364 … −1 | 0 … 363 | Греческий алфавит, псевдографика, стрелки, математические символы |
| **0 … 255** | **364 … 619** | **Совместимость с CP‑1251 (ASCII + кириллица + спецсимволы)** |
| 256 … 364 | 620 … 728 | Математические и технические символы |

### 11.2. 9‑ричное представление (пары тритов)

| Пара | Символ | Пара | Символ | Пара | Символ |
|------|--------|------|--------|------|--------|
| `- -` | W | `0 -` | Z | `+ -` | 2 |
| `- 0` | X | `0 0` | 0 | `+ 0` | 3 |
| `- +` | Y | `0 +` | 1 | `+ +` | 4 |

Трайт представляется тремя 9‑ричными цифрами: префикс `0n` + 3 символа (например, `0n1Y2` для 'A').

### 11.3. 27‑ричное представление (тройки тритов)

| Тройка | Сим | Тройка | Сим | Тройка | Сим |
|--------|-----|--------|-----|--------|-----|
| `- - -` | N | `0 - -` | W | `+ - -` | 5 |
| `- - 0` | O | `0 - 0` | X | `+ - 0` | 6 |
| `- - +` | P | `0 - +` | Y | `+ - +` | 7 |
| `- 0 -` | Q | `0 0 -` | Z | `+ 0 -` | 8 |
| `- 0 0` | R | `0 0 0` | 0 | `+ 0 0` | 9 |
| `- 0 +` | S | `0 0 +` | 1 | `+ 0 +` | A |
| `- + -` | T | `0 + -` | 2 | `+ + -` | B |
| `- + 0` | U | `0 + 0` | 3 | `+ + 0` | C |
| `- + +` | V | `0 + +` | 4 | `+ + +` | D |

Трайт представляется двумя 27‑ричными цифрами: префикс `0y` + 2 символа (например, `0y2B` для 'A').

## 12. Модель времени

- **Тактовая частота**: 1 ГГц (1 такт = 1 нс).
- **Аппаратные счётчики** отображаются на адреса MMIO (см. §4.1).
- Запись в `CYCLE_LOW` сбрасывает все счётчики.
- В T3‑54 счётчики имеют разрядность 54 трита.

## 13. Обработка исключений

| Условие | Поведение |
|---------|-----------|
| Недопустимый опкод (28–44 в T3‑18) | Исключение процессора (останов с ошибкой) |
| Деление на ноль (целочисленное) | Исключение процессора |
| Исключения FPU | Установка флагов FSR, возврат специального значения (без прерывания) |
| Переполнение стека | Определяется реализацией (обычно циклический переход или останов) |
| Выход за границы памяти | Исключение процессора |
