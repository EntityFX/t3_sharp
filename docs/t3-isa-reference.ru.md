# T3 Система команд — Справочник

## 1. Обзор

Настоящий документ содержит полный справочник по системе команд троичного процессора T3. Все инструкции кодируются одним **18‑тритным словом**.

### 1.1. Имена регистров

| Индекс | Имя | Индекс | Имя | Индекс | Имя |
|--------|-----|--------|-----|--------|-----|
| 0 | RW | 3 | RZ | 6 | R2 |
| 1 | RX | 4 | R0 | 7 | R3 |
| 2 | RY | 5 | R1 | 8 | R4 |

### 1.2. Форматы инструкций

**R‑тип (регистр–регистр):**
```
[ opcode+pred (6) | op1 (3) | op2 (3) | op3 (3) | резерв/func (3) ]
```

**I‑тип (регистр–непосредственное значение):**
```
[ opcode+pred (6) | op1 (3) | op2 (3) | imm6 (6) ]
```

Где:
- `opcode+pred = базовый_опкод + индекс_предиката × 28`
- `индекс_предиката = (opcode+pred) / 28`
- `базовый_опкод = (opcode+pred) % 28`
- `op1, op2, op3` = индексы регистров (0–8)
- `imm6` = знаковое непосредственное значение, диапазон −364 … +364 (хранится как беззнаковое: `imm6 + 364`)

### 1.3. Предикация

Если `индекс_предиката ≠ 0`, инструкция выполняется только при `PR[индекс_предиката − 1] == +1`.  
При неудаче предиката инструкция становится **NOP** (состояние не меняется, PC продвигается).

## 2. Базовые инструкции (коды 0–27, R‑тип)

### 2.1. HALT — Останов процессора
| Поле | Значение |
|------|----------|
| **Опкод** | 0 |
| **Тип** | — |
| **Операнды** | Нет (все поля игнорируются) |
| **Задержка** | 1 |
| **Описание** | Останавливает процессор. `Step()` возвращает `false`. |

---

### 2.2. LOAD — Загрузка из памяти
| Поле | Значение |
|------|----------|
| **Опкод** | 1 |
| **Тип** | R |
| **Операнды** | `LOAD op1, op2` |
| **Задержка** | 2 |
| **Описание** | `op1 = mem[op2]` — загружает слово по адресу из `op2` в регистр `op1`. `op3` игнорируется. |

---

### 2.3. STORE — Сохранение в память
| Поле | Значение |
|------|----------|
| **Опкод** | 2 |
| **Тип** | R |
| **Операнды** | `STORE op1, op2` |
| **Задержка** | 2 |
| **Описание** | `mem[op2] = op1` — сохраняет регистр `op1` по адресу в `op2`. `op3` игнорируется. |

---

### 2.4. MOV — Пересылка регистра
| Поле | Значение |
|------|----------|
| **Опкод** | 3 |
| **Тип** | R |
| **Операнды** | `MOV op1, op2` |
| **Задержка** | 1 |
| **Описание** | `op1 = op2` — копирует регистр `op2` в `op1`. `op3` игнорируется. |

---

### 2.5. LI — Загрузка непосредственного значения
| Поле | Значение |
|------|----------|
| **Опкод** | 4 |
| **Тип** | I |
| **Операнды** | `LI op1, imm6` |
| **Задержка** | 1 |
| **Описание** | `op1 = imm6` — загружает 6‑тритное непосредственное значение в `op1`. Всегда I‑тип. |

**Пример кодирования:** `LI RW, 10`
- opcode+pred = 4, op1 = 0, imm6 = 10 → беззнаковое = 374 (10 + 364)
- Слово = `4 × 3¹² + 0 × 3⁹ + 0 × 3⁶ + 374`

---

### 2.6. LIMM — Загрузка непосредственного значения из памяти
| Поле | Значение |
|------|----------|
| **Опкод** | 5 |
| **Тип** | R |
| **Операнды** | `LIMM op1` |
| **Задержка** | 2 |
| **Описание** | `op1 = mem[PC]; PC += 1` — загружает следующее слово памяти в `op1`. `op2`, `op3` игнорируются. |

---

### 2.7. ADD — Сложение

### 2.9. MUL — Умножение

| **Задержка** | 10 (T3‑18) / 15 (T3‑54) |

### 2.12. NEG — Инвертирование знака
| Поле | Значение |
|------|----------|
| **Опкод** | 11 |
| **Тип** | R |
| **Операнды** | `NEG op1, op2` |
| **Задержка** | 1 |
| **Описание** | `op1 = −op2` — арифметическое отрицание (инверсия каждого трита: `-` ↔ `+`, `0` остаётся `0`). `op3` игнорируется. |

---

### 2.13. TRITAND — Потритовое И
| Поле | Значение |
|------|----------|
| **Опкод** | 12 |
| **Тип** | R |
| **Операнды** | `TRITAND op1, op2, op3` |
| **Задержка** | 1 |
| **Описание** | `op1 = op2 & op3` — потритовый минимум. Для каждой позиции: результат = min(трит_a, трит_b). |
| | Таблица истинности: `- & - = -`, `- & 0 = -`, `- & + = -`, `0 & 0 = 0`, `0 & + = 0`, `+ & + = +` |

---

### 2.14. TRITOR — Потритовое ИЛИ
| Поле | Значение |
|------|----------|
| **Опкод** | 13 |
| **Тип** | R |
| **Операнды** | `TRITOR op1, op2, op3` |
| **Задержка** | 1 |
| **Описание** | `op1 = op2 | op3` — потритовый максимум. Для каждой позиции: результат = max(трит_a, трит_b). |
| | Таблица истинности: `- \| - = -`, `- \| 0 = 0`, `- \| + = +`, `0 \| 0 = 0`, `0 \| + = +`, `+ \| + = +` |

---

### 2.15. TRITXOR — Потритовое исключающее ИЛИ
| Поле | Значение |
|------|----------|
| **Опкод** | 14 |

| **Операнды** | `TRITXOR op1, op2, op3` |

| **Описание** | `op1 = op2 ^ op3` — потритовая сумма по модулю 3. |
| | Таблица истинности: `a ^ b = (a + b) mod 3`, отображённое в {−1, 0, +1} |

### 2.16. SHL — Сдвиг влево

## 3. I‑варианты (коды 65–91)

I‑инструкции имеют `базовый_опкод = R_опкод + 64`. Используют I‑формат, где `imm6` заменяет `op3` и резервное поле.

| Код | Мнемоника | R‑база | Операция |
|-----|-----------|--------|----------|
| 65 | LOADI | LOAD (1) | `op1 = mem[op2 + imm6]` |
| 66 | STOREI | STORE (2) | `mem[op2 + imm6] = op1` |
| 67 | MOVI | MOV (3) | `op1 = imm6` (op2 игнорируется) |
| 70 | ADDI | ADD (6) | `op1 = op2 + imm6` |
| 71 | SUBI | SUB (7) | `op1 = op2 − imm6` |
| 72 | MULI | MUL (8) | `op1 = op2 × imm6` |
| 73 | DIVI | DIV (9) | `op1 = op2 / imm6` |
| 74 | MODI | MOD (10) | `op1 = op2 % imm6` |
| 75 | NEGI | NEG (11) | `op1 = −imm6` |
| 76 | TRITANDI | TRITAND (12) | `op1 = op2 & imm6` |
| 77 | TRITORI | TRITOR (13) | `op1 = op2 \| imm6` |
| 78 | TRITXORI | TRITXOR (14) | `op1 = op2 ^ imm6` |
| 79 | SHLI | SHL (15) | `op1 = op2 << imm6` |
| 80 | SHRI | SHR (16) | `op1 = op2 >> imm6` |
| 81 | CMPI | CMP (17) | `Cond = sign(op1 − imm6)` |

Коды 64, 69 и 82–91 зарезервированы для будущих расширений.

## 5. Инструкции FPU (коды 92–108)

FPU работает с регистрами **FW, FX, FY, FZ, F0, F1, F2, F3, F4** (индексы 0–8).  
Поле `func` (3 трита, занимает резервное поле в R‑типе) выбирает тип данных или подоперацию.

| Код | Мнемоника | Тип | Операция | Задержка |
|-----|-----------|-----|----------|----------|
| 92 | FADD | R | `Fop1 = Fop2 + Fop3` | 5 |
| 93 | FSUB | R | `Fop1 = Fop2 − Fop3` | 5 |
| 94 | FMUL | R | `Fop1 = Fop2 × Fop3` | 7 |
| 95 | FDIV | R | `Fop1 = Fop2 / Fop3` | 15 |
| 96 | FSQRT | R | `Fop1 = sqrt(Fop2)` (op3 игнорируется) | 20 |
| 97 | FABS | R | `Fop1 = abs(Fop2)` (op3 игнорируется) | 1 |
| 98 | FNEG | R | `Fop1 = −Fop2` (op3 игнорируется) | 1 |
| 99 | FCMP | R | `Cond = sign(Fop1 − Fop2)` (op3 игнорируется) | 1 |
| 100 | FTOI | R | `Rop1 = int(Fop2)`. `func`: 0 = 18‑тритное, 1 = 54‑тритное целое. Округление к нулю. | 3 |
| 101 | ITOF | R | `Fop1 = float(Rop2)`. `func` выбирает разрядность целого. | 3 |
| 102 | FTOF | R | Преобразование tfloat ↔ tdouble. `func`: 0 = tfloat→tdouble, 1 = tdouble→tfloat. | 2 |
| 103 | FLW | I | `Fop1 = mem[Rop2 + imm6]` — загрузка FPU из памяти. | 2 |
| 104 | FSW | I | `mem[Rop2 + imm6] = Fop1` — сохранение FPU в память. | 2 |
| 105 | FMOV | R | Пересылка: `func=0`: `Fop1 = Fop2`; `func=1`: `Rop1 = Fop2`; `func=2`: `Fop1 = Rop2`. | 1 |
| 106 | FCLASS | R | Классификация `Fop2` → `Fop1`: 0=ноль, 1=∞, 2=NaN, 3=maybe‑NaN, 4=нормальное. | 1 |
| 107 | FSWAP | R | Обмен `Fop1` и `Fop2`. | 1 |
| 108 | FZERO | R | `Fop1 = 0.0` | 1 |

Исключения FPU устанавливают флаги в **FSR** (порт 0x20) и записывают специальные значения (∞, 0, NaN) в приёмник. Прерывания не генерируются.

## 8. Примеры кодирования

### ADD R0, R1, R2 (R‑тип)
- `базовый_опкод = 6`, `индекс_предиката = 0` → `opcode+pred = 6`
- `op1 = 4` (R0), `op2 = 5` (R1), `op3 = 6` (R2), `резерв = 0`
- Слово = `6 × 3¹² + 4 × 3⁹ + 5 × 3⁶ + 6 × 3³ + 0`

### ADDI R0, R1, 100 (I‑тип)
- `базовый_опкод = 70`, `индекс_предиката = 0` → `opcode+pred = 70`
- `op1 = 4` (R0), `op2 = 5` (R1), `imm6 = 100` → беззнаковое = `464` (100 + 364)
- Слово = `70 × 3¹² + 4 × 3⁹ + 5 × 3⁶ + 464`

### LI RW, 10
- `базовый_опкод = 4`, `op1 = 0` (RW), `imm6 = 10` → беззнаковое = `374`
- Слово = `4 × 3¹² + 0 × 3⁹ + 0 × 3⁶ + 374`

### INI RW, 7
- `базовый_опкод = 43`, `op1 = 0` (RW), `imm6 = 7` → беззнаковое = `371`
- Слово = `43 × 3¹² + 0 × 3⁹ + 0 × 3⁶ + 371`

### FADD FW, FX, FY (tfloat)
- `базовый_опкод = 92`, `op1 = 0` (FW), `op2 = 1` (FX), `op3 = 2` (FY), `func = 0`
- Слово = `92 × 3¹² + 0 × 3⁹ + 1 × 3⁶ + 2 × 3³ + 0`

## 9. Кодирование предикации

Каждая инструкция может быть предицирована установкой `индекса_предиката` (0–9 для T3‑54, 0–3 для T3‑18):

| Индекс | Флаг предиката | Эффект |
|--------|----------------|--------|
| 0 | Нет | Выполнять всегда |
| 1 | PR[0] (p0) | Выполнять если `PR[0] == +1` |
| 2 | PR[1] (p1) | Выполнять если `PR[1] == +1` |
| 3 | PR[2] (p2) | Выполнять если `PR[2] == +1` |
| 4–9 | PR[3]–PR[8] | Только T3‑54 |

Флаги предикатов устанавливаются инструкциями сравнения (`CMP`, `FCMP`, `VCMP`) или прямой записью в регистр `PR`.

## 10. Синтаксис ассемблера

```
; Комментарии начинаются с точки с запятой

; Метки
main:
    LI RW, 10          ; Загрузка непосредственного значения
    LI RX, 20
    ADD RY, RW, RX     ; RY = RW + RX
    CMP RY, RW         ; Сравнение: Cond = sign(RY - RW)
    JG  greater        ; Переход если Cond > 0
    MOV RZ, RW         ; иначе: RZ = RW
    JMP done
greater:
    MOV RZ, RY         ; RZ = RY
done:
    HALT
```

### Синтаксис VLIW‑бандлов (T3‑54)

```
{ ADD R0, R1, R2 | MUL R3, R4, R5 | LOAD R6, R7 }
;                            ^                   ^
;     Слот 0                   Слот 1    Слот 2
```

Слоты разделяются символом `|`. Неиспользуемые слоты автоматически заполняются `NOP`.
