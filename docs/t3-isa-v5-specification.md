## 1. Формат инструкции

Каждая инструкция — **18 тритов** (1 слово):

```
┌──────────┬───────────┬───┬─────────┬─────────────────────────┐
│ Pred(3)  │ RegGroup  │ Fmt│ Opcode(4)│ Args(9)                 │
│  15..13  │    12     │ 13 │  12..9  │     8..0                │
└──────────┴───────────┴───┴─────────┴─────────────────────────┘
```

| Поле | Тритов | Позиция | Описание |
|------|--------|---------|----------|
| **Pred** | 3 | 15..13 | Предикат (0 = всегда) |
| **RegGroup** | 1 | 12 | Группа регистров: -1=FPU, 0=GP, +1=Special |
| **Fmt** | 1 | 11 | Формат инструкции (-1=J, 0=R/S, +1=I) |
| **Opcode** | 4 | 10..7 | Код операции (0..80) |
| **Args** | 9 | 6..0 | Операнды (формат зависит от типа инструкции) |

### Подформаты Args

```
R-type:  [Op1(3)][Op2(3)][Op3(3)]     — 3 регистра
S-type:  [Op1(3)][Op2(3)][Imm(3)]     — 2 регистра + immediate (LD/ST)
I-type:  [Op1(3)][Imm(6)]             — 1 регистр + immediate
J-type:  [Op1(3)][000000]             — 1 регистр (JMP, CALL, JE, ...)
```

Все поля регистров — **balanced ternary** (-4..+4), мапятся на индексы 0..8 через `+4 offset`.

Поле immediate — **balanced ternary**: 3 трита = -13..+13, 6 тритов = -364..+364.

## 2. RegGroup — группы регистров

Один трит определяет, с каким регистровым файлом работает инструкция:

| Значение | Префикс | Группа | Описание |
|----------|---------|--------|----------|
| **-1** (N) | `F.` | **FPU** | Floating-point регистры |
| **0** | (нет) | **GP** | General-purpose регистры |
| **+1** (P) | `S.` | **Special** | Специальные регистры (FP, HP, SP, CD, PR, WD) |

Одна и та же инструкция `ADD` работает ортогонально:

```asm
ADD  R0, R1, R2    ; RegGroup=0  → GP: R0 = R1 + R2
F.ADD F0, F1, F2   ; RegGroup=-1 → FPU: F0 = F1 + F2
S.ADD SP, SP, #16  ; RegGroup=+1 → Special: SP = SP + 16
```

## 3. Регистровые файлы

### 3.1 GP-регистры (RegGroup = 0, без префикса)

```
┌────────┬──────┬─────────────────────┬──────────────┐
│ Имя    │ Ind  │ Назначение (ABI)    │ Сохраняется  │
├────────┼──────┼─────────────────────┼──────────────┤
│ RW     │  0   │ arg0 / scratch      │ Caller       │
│ RX     │  1   │ arg1 / scratch      │ Caller       │
│ RY     │  2   │ arg2 / scratch      │ Caller       │
│ RZ     │  3   │ callee-saved GP     │ Callee       │
│ R0     │  4   │ arg3 / scratch      │ Caller       │
│ R1     │  5   │ call target addr    │ Caller       │
│ R2     │  6   │ return value        │ Caller       │
│ R3     │  7   │ callee-saved / ret hi│ Callee      │
│ R4     │  8   │ callee-saved / addr │ Callee       │
└────────┴──────┴─────────────────────┴──────────────┘
```

**RZ (3) и R3 (7) освобождены** — FP и HP вынесены в Special-регистры. Теперь RZ и R3 — обычные callee-saved GP-регистры.

### 3.2 FPU-регистры (RegGroup = -1, префикс `F.`)

```
┌────────┬──────┬─────────────────────┬──────────────┐
│ Имя    │ Ind  │ Назначение (ABI)    │ Сохраняется  │
├────────┼──────┼─────────────────────┼──────────────┤
│ FW     │  0   │ farg0 / scratch     │ Caller       │
│ FX     │  1   │ farg1 / scratch     │ Caller       │
│ FY     │  2   │ farg2 / scratch     │ Caller       │
│ FZ     │  3   │ farg3 / scratch     │ Caller       │
│ F0     │  4   │ scratch             │ Caller       │
│ F1     │  5   │ scratch             │ Caller       │
│ F2     │  6   │ return value        │ Caller       │
│ F3     │  7   │ callee-saved        │ Callee       │
│ F4     │  8   │ callee-saved        │ Callee       │
└────────┴──────┴─────────────────────┴──────────────┘
```

### 3.3 Special-регистры (RegGroup = +1, префикс `S.`)

```
┌────────┬──────┬─────────────────────┬──────────────┐
│ Имя    │ Ind  │ Назначение           │ Доступ       │
├────────┼──────┼─────────────────────┼──────────────┤
│ FP     │  0   │ Frame Pointer       │ R/W          │
│ HP     │  1   │ Heap Pointer        │ R/W          │
│ SP     │  2   │ Stack Pointer       │ R/W          │
│ CD     │  3   │ Condition (-1/0/+1) │ R/W          │
│ PR     │  4   │ Predicate (9 тритов)│ R/W          │
│ WD     │  5   │ Window Pointer      │ R/W          │
│ —      │ 6-8  │ зарезервировано      │ —            │
└────────┴──────┴─────────────────────┴──────────────┘
```

- **FP** — Frame Pointer, автоматически сохраняется/восстанавливается CALL/RET
- **HP** — Heap Pointer, инициализируется при старте (HeapStart = 699050)
- **SP** — Stack Pointer, инициализируется при старте (1048575)
- **CD** — Condition flag, устанавливается инструкцией CMP, читается условными переходами
- **PR** — Predicate Register, 9 тритов для предикации (PR[0..2] = predicate 1..3)
- **WD** — Window Pointer (бывший WP)

## 4. Система команд

```
┌────────┬──────────┬──────────┬──────────────────────────────────────────┐
│ Opcode │ Mnemonic │ Тип      │ Семантика                                │
├────────┼──────────┼──────────┼──────────────────────────────────────────┤
│   0    │ HALT     │ —        │ Останов процессора                       │
│   1    │ NOP      │ —        │ Нет операции                             │
│   2    │ MOV      │ R, I     │ Rd ← Rs  |  Rd ← #imm                   │
│   3    │ LIMM     │ Спец     │ Rd ← ##imm (2 слова, большой imm)       │
│   4    │ LD       │ R, S     │ Rd ← [Rs]  |  Rd ← [Rs + #off]          │
│   5    │ ST       │ R, S     │ [Rd] ← Rs  |  [Rd + #off] ← Rs          │
│   6    │ PUSH     │ R, I     │ push Rs  |  push #imm                   │
│   7    │ POP      │ R        │ Rd ← pop                                │
│   8    │ ADD      │ R, I     │ Rd ← Rs1 + Rs2  |  Rd ← Rs + #imm       │
│   9    │ SUB      │ R, I     │ Rd ← Rs1 - Rs2  |  Rd ← Rs - #imm       │
│  10    │ MUL      │ R, I     │ Rd ← Rs1 * Rs2  |  Rd ← Rs * #imm       │
│  11    │ DIV      │ R, I     │ Rd ← Rs1 / Rs2  |  Rd ← Rs / #imm       │
│  12    │ MOD      │ R, I     │ Rd ← Rs1 % Rs2  |  Rd ← Rs % #imm       │
│  13    │ NEG      │ R, I     │ Rd ← -Rs  |  Rd ← -#imm                 │
│  14    │ ABS      │ R        │ Rd ← |Rs|                                │
│  15    │ CMP      │ R, I     │ CD ← sign(Rs1 - Rs2  |  Rs - #imm)      │
│  16    │ AND      │ R, I     │ Rd ← Rs1 & Rs2  |  Rd ← Rs & #imm       │
│  17    │ OR       │ R, I     │ Rd ← Rs1 | Rs2  |  Rd ← Rs | #imm       │
│  18    │ XOR      │ R, I     │ Rd ← Rs1 ^ Rs2  |  Rd ← Rs ^ #imm       │
│  19    │ SHL      │ R, I     │ Rd ← Rs1 << Rs2  |  Rd ← Rs << #imm     │
│  20    │ SHR      │ R, I     │ Rd ← Rs1 >> Rs2  |  Rd ← Rs >> #imm     │
│  21    │ JMP      │ J        │ PC ← Rs  |  PC += #off                   │
│  22    │ JE       │ J        │ if CD == 0: PC ← Rs / PC += #off         │
│  23    │ JNE      │ J        │ if CD ≠ 0: PC ← Rs / PC += #off          │
│  24    │ JL       │ J        │ if CD < 0: PC ← Rs / PC += #off          │
│  25    │ JG       │ J        │ if CD > 0: PC ← Rs / PC += #off          │
│  26    │ JLE      │ J        │ if CD ≤ 0: PC ← Rs / PC += #off          │
│  27    │ JGE      │ J        │ if CD ≥ 0: PC ← Rs / PC += #off          │
│  28    │ JM       │ J        │ if CD == 0: PC ← Rs / PC += #off         │
│  29    │ CALL     │ J        │ push FP; push PC+1; FP←SP; PC←Rs / +=off│
│  30    │ RET      │ —        │ PC←[SP]; FP←[SP+1]; SP+=2               │
│  31    │ IN       │ R, I     │ Rd ← port[Rs]  |  Rd ← port[#port]       │
│  32    │ OUT      │ R, I     │ port[Rd] ← Rs  |  port[#port] ← Rs       │
│  33    │ SQRT     │ R        │ Fd ← sqrt(Fs)  (только F.SQRT)           │
│  34    │ FTI      │ R        │ Rd ← float_to_int(Fs)  (кросс-групп.)    │
│  35    │ ITF      │ R        │ Fd ← int_to_float(Rs)  (кросс-групп.)    │
│  36    │ CLASS    │ R        │ Fd ← classify(Fs)  (только F.CLASS)      │
│  37    │ SWAP     │ R        │ Rd ↔ Rs  (обмен значениями)              │
└────────┴──────────┴──────────┴──────────────────────────────────────────┘
```

**37 опкодов** из 243 возможных (5 тритов). Запас: **206 опкодов**.

## 5. Семантика инструкций

### 5.1. Выбор формата по типу последнего операнда

Ассемблер автоматически выбирает R-type или I-type:

```
ADD R0, R1, R2      → R-type (3 регистра)
ADD R0, R1, #5      → I-type (2 регистра + immediate)
```

Если в I-форме первый и второй операнд совпадают, используется I-форма с одним регистром:
```
ADD R0, #5          → эквивалентно ADD R0, R0, #5
```

### 5.2. Ограничения по RegGroup

| Операция | GP | FPU | Special |
|----------|:--:|:---:|:-------:|
| MOV, LD, ST, PUSH, POP | ✅ | ✅ | ✅ |
| ADD, SUB | ✅ | ✅ | ✅ |
| MUL, DIV | ✅ | ✅ | ❌ |
| MOD | ✅ | ❌ | ❌ |
| NEG, ABS | ✅ | ✅ | ❌ |
| CMP | ✅ | ✅ | ✅ |
| AND, OR, XOR | ✅ | ❌ | ❌ |
| SHL, SHR | ✅ | ❌ | ❌ |
| JMP, JE..JM, CALL | ❌ | ❌ | ❌ (без RegGroup) |
| RET, HALT, NOP | ❌ | ❌ | ❌ (без RegGroup) |
| IN, OUT | ✅ | ❌ | ❌ |
| SQRT | ❌ | ✅ | ❌ |
| FTI, ITF | кросс-групповая: GP↔FPU | | |
| CLASS | ❌ | ✅ | ❌ |
| SWAP | ✅ | ✅ | ❌ |

### 5.3. Кросс-групповые операции

**FTI** (Float To Int): операнд Op2 — FPU-регистр, результат Op1 — GP-регистр. RegGroup в инструкции = -1 (FPU), но результат пишется в GP.

**ITF** (Int To Float): операнд Op2 — GP-регистр, результат Op1 — FPU-регистр. RegGroup = 0 (GP), но результат пишется в FPU.

**F.LD** (Float Load): адресная база Op2 — GP-регистр (игнорирует RegGroup для адреса), данные загружаются в FPU-регистр Op1.

**F.ST** (Float Store): данные из FPU-регистра Op1, адресная база Op2 — GP-регистр.

## 6. CALL и RET с автосохранением FP

### CALL

```
Стек до:  [...]
           SP →

CALL:
1. SP -= 2
2. mem[SP+1] ← FP        ; сохранить FP вызывающей функции
3. mem[SP]   ← PC+1      ; сохранить адрес возврата
4. FP ← SP                ; новый FP = SP
5. PC ← target

Стек после: [ret addr]    ← SP (= FP)
            [saved FP]    ← SP+1
            [...]         ← старый стек
```

### RET

```
RET:
1. PC ← mem[SP]           ; адрес возврата
2. FP ← mem[SP+1]          ; восстановить FP вызывающей функции
3. SP += 2                 ; освободить 2 слота
```

**Преимущества:**
- FP всегда корректен — nested calls не могут потерять FP
- Пролог функции не требует `PUSH FP` / `MOV FP, SP`
- Эпилог не требует `POP FP`
- Отладка: раскрутка стека всегда возможна по цепочке saved FP

### Стековый фрейм после CALL

```
Высокие адреса (FP вызывающей функции)
┌──────────────────────────────────────┐
│  Аргументы 4..N (зона вызывающего)   │ ← params от caller
├──────────────────────────────────────┤
│  Saved FP (вызывающей функции)       │ ← FP+2
├──────────────────────────────────────┤
│  Return Address                      │ ← FP+1
├──────────────────────────────────────┤ ← FP (текущей функции)
│  Saved R3 (callee-saved)             │ ← FP-1 (если сохраняется)
├──────────────────────────────────────┤
│  Saved R4 (callee-saved)             │ ← FP-2 (если сохраняется)
├──────────────────────────────────────┤
│  Локальная переменная 0              │ ← FP-3
│  Локальная переменная 1              │ ← FP-4
│  ...                                 │
├──────────────────────────────────────┤
│  Spill-зона для callee               │
├──────────────────────────────────────┤ ← SP (после аллокации)
│  Свободное пространство стека        │
└──────────────────────────────────────┘
```

## 7. Синтаксис ассемблера

### 7.1. Префиксы групп

| Синтаксис | RegGroup | Пример |
|-----------|----------|--------|
| Без префикса | 0 (GP) | `ADD R0, R1, R2` |
| `F.` | -1 (FPU) | `F.ADD F0, F1, F2` |
| `S.` | +1 (Special) | `S.MOV FP, SP` |

### 7.2. Загрузки и сохранения

```asm
; Загрузка из памяти
LD  R0, [R1]           ; R0 ← mem[R1]
LD  R0, [R1 + #4]      ; R0 ← mem[R1 + 4]
F.LD F0, [R1]          ; F0 ← float(mem[R1])
F.LD F0, [R1 + #4]     ; F0 ← float(mem[R1 + 4])

; Сохранение в память
ST  [R1], R0           ; mem[R1] ← R0
ST  [R1 + #4], R0      ; mem[R1 + 4] ← R0
F.ST [R1], F0          ; mem[R1] ← float(F0)
F.ST [R1 + #4], F0     ; mem[R1 + 4] ← float(F0)
```

### 7.3. Immediate

```asm
MOV  R0, #42           ; малый immediate (-364..+364)
MOV  R0, ##699050      ; большой immediate (LIMM, 2 слова)
S.MOV HP, ##699050     ; Special-регистр, большой immediate
```

### 7.4. Стек

```asm
PUSH R0                ; сохранить R0 на стеке
PUSH #42               ; сохранить константу на стеке
POP  R0                ; восстановить R0 со стека
```

### 7.5. Переходы

```asm
JMP  R0                ; безусловный переход по адресу в R0
JMP  loop              ; переход на метку (ассемблер → LIMM + JMP)
JE   R0                ; переход если CD == 0
JL   exit              ; переход если CD < 0 (на метку)
```

### 7.6. Вызовы

```asm
MOV  R1, ##func        ; загрузить адрес функции
CALL R1                ; вызов

; Или через метку (ассемблер сам сгенерирует LIMM + MOV R1):
CALL func
```

## 8. Унификация: что убрано, что добавлено

### Убрано (21 опкод)

| Старый опкод | Причина |
|-------------|---------|
| `MOVI` | Унифицирован в `MOV` (I-type) |
| `ADDI, SUBI, MULI, DIVI, MODI` | Унифицированы в `ADD, SUB, MUL, DIV, MOD` (I-type) |
| `ANDI, ORI, XORI` | Унифицированы в `AND, OR, XOR` (I-type) |
| `SHLI, SHRI` | Унифицированы в `SHL, SHR` (I-type) |
| `NEGI` | Унифицирован в `NEG` (I-type) |
| `CMPI` | Унифицирован в `CMP` (I-type) |
| `INI, OUTI` | Унифицированы в `IN, OUT` (I-type) |
| `PUSHI, POPI` | Унифицированы в `PUSH, POP` (I-type) |
| `FADD, FSUB, FMUL, FDIV, FNEG, FABS, FCMP, FMOV` | → `F.ADD`, `F.SUB`, ... через RegGroup |
| `FLW, FSW` | → `F.LD`, `F.ST` |
| `FSWAP` | → `SWAP` (универсальный) |
| `FSQRT` (опкод 104) | → `SQRT` (опкод 33) |

### Добавлено (2 опкода)

| Опкод | Мнемоника | Описание |
|-------|-----------|----------|
| 14 | `ABS` | Абсолютное значение (был только FABS) |
| 37 | `SWAP` | Обмен регистров (был только FSWAP) |

### Переименовано

| Было | Стало |
|------|-------|
| `Cond` | `CD` |
| `WP` | `WD` |
| `LI` | `MOV Rd, #imm` |
| `LOAD` / `LOADI` | `LD` |
| `STORE` / `STOREI` | `ST` |
| `FTOI` | `FTI` |
| `ITOF` | `ITF` |
| `FCLASS` | `F.CLASS` |
