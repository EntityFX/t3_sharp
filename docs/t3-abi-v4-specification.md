## 1. Регистровая модель

### 1.1. Регистры общего назначения (GP)

```
┌────────┬──────┬─────────────────────┬──────────────┬──────────────────┐
│ Имя    │ Phys │ Назначение          │ Сохраняется  │ Категория        │
├────────┼──────┼─────────────────────┼──────────────┼──────────────────┤
│ RW     │  0   │ arg0 / scratch      │ Caller       │ Аргументный      │
│ RX     │  1   │ arg1 / scratch      │ Caller       │ Аргументный      │
│ RY     │  2   │ arg2 / scratch      │ Caller       │ Аргументный      │
│ RZ     │  3   │ Frame Pointer (FP)  │ Callee       │ Служебный        │
│ R0     │  4   │ arg3 / scratch      │ Caller       │ Аргументный      │
│ R1     │  5   │ Call target addr    │ Caller       │ Служебный        │
│ R2     │  6   │ Return value (lo)   │ Caller       │ Возврат          │
│ R3     │  7   │ Callee-saved / hi   │ Callee       │ Сохраняемый      │
│ R4     │  8   │ Callee-saved / addr │ Callee       │ Сохраняемый      │
└────────┴──────┴─────────────────────┴──────────────┴──────────────────┘
```

**Итоговая классификация:**

| Категория | Регистры | Кол-во |
|-----------|----------|--------|
| Аргументные (caller-saved, scratch) | RW, RX, RY, R0 | 4 |
| Служебные (caller-saved) | R1, R2 | 2 |
| Сохраняемые (callee-saved) | RZ (FP), R3, R4 | 3 |
| **Всего** | | **9** |

**Детальные правила:**

1. **RW, RX, RY, R0** — аргументы функции 0,1,2,3. Вызывающий код (caller) не должен предполагать их сохранность после CALL. Используются как scratch-регистры внутри функции.
2. **RZ** — Frame Pointer. Указывает на начало стекового фрейма текущей функции. Обязательно сохраняется и восстанавливается вызываемой функцией (callee). Устанавливается в прологе: `PUSH RZ; MOV RZ, SP`.
3. **R1** — адрес целевой функции для инструкции CALL. Загружается через LIMM. Не сохраняется callee.
4. **R2** — возвращаемое значение (младшая часть для многозначных возвратов). Не сохраняется callee. Вызывающий код должен прочитать R2 немедленно после CALL.
5. **R3** — callee-saved регистр общего назначения. При возврате tlong/tlong long содержит старшую часть возвращаемого значения (R2=lo, R3=hi).
6. **R4** — callee-saved регистр. Может использоваться как адресный регистр для LOAD/STORE внутри функции.

### 1.2. Регистры с плавающей точкой (FPU)

```
┌────────┬──────┬─────────────────────┬──────────────┬──────────────────┐
│ Имя    │ Phys │ Назначение           │ Сохраняется  │ Категория        │
├────────┼──────┼─────────────────────┼──────────────┼──────────────────┤
│ FW     │  0   │ farg0 / scratch      │ Caller       │ FP аргументный   │
│ FX     │  1   │ farg1 / scratch      │ Caller       │ FP аргументный   │
│ FY     │  2   │ farg2 / scratch      │ Caller       │ FP аргументный   │
│ FZ     │  3   │ farg3 / scratch      │ Caller       │ FP аргументный   │
│ F0     │  4   │ scratch              │ Caller       │ FP scratch       │
│ F1     │  5   │ scratch              │ Caller       │ FP scratch       │
│ F2     │  6   │ Return value (float) │ Caller       │ FP возврат       │
│ F3     │  7   │ Callee-saved         │ Callee       │ FP сохраняемый   │
│ F4     │  8   │ Callee-saved         │ Callee       │ FP сохраняемый   │
└────────┴──────┴─────────────────────┴──────────────┴──────────────────┘
```

**FPU правила:**

1. **FW, FX, FY, FZ** — float-аргументы 0..3. Caller-saved. При передаче float-аргументов целые регистры RW,RX,RY,RZ не используются как аргументные.
2. **F0, F1** — scratch для float-вычислений. Caller-saved.
3. **F2** — возвращаемое float-значение. Caller-saved.
4. **F3, F4** — callee-saved float-регистры. Для аккумуляторов в циклах.
5. **FTOI/ITOF** — при необходимости сохранить FPU-регистр на стеке используется последовательность `FTOI Rtmp, Fx; PUSH Rtmp` / `POP Rtmp; ITOF Fx, Rtmp`. Это bit-preserving round-trip.

### 1.3. Специальные регистры

| Регистр | Описание | Роль в ABI |
|---------|----------|------------|
| **SP** | Stack Pointer, растёт вниз от 1048575 | Указывает на вершину стека |
| **PC** | Program Counter | Адрес текущей инструкции |
| **Cond** | Condition flag: –1/0/+1 | Результат сравнения, не сохраняется при CALL |
| **PR** | Predicate Register (9 тритов = 3×3) | Предикатные флаги, не сохраняются при CALL |

## 2. Стековый фрейм

### 2.1. Структура фрейма

```
Высокие адреса (SP увеличивается вверх)
┌──────────────────────────────────────┐ ← SP при входе в функцию
│  Аргументы 4..N (зона вызывающего)   │   Размещены callER перед CALL
│  ...                                 │
├──────────────────────────────────────┤
│  Return Address                      │   Сохранён инструкцией CALL
├──────────────────────────────────────┤ ← FP (= RZ) после пролога
│  Saved FP (старый RZ)                │   PUSH RZ в прологе
├──────────────────────────────────────┤
│  Saved R3 (если используется)        │   PUSH R3 опционально
├──────────────────────────────────────┤
│  Saved R4 (если используется)        │   PUSH R4 опционально
├──────────────────────────────────────┤
│  Saved F3 (если используется)        │   FTOI; PUSH опционально
├──────────────────────────────────────┤
│  Saved F4 (если используется)        │   FTOI; PUSH опционально
├──────────────────────────────────────┤
│  Локальная переменная 0              │ ← FP – offset_0
│  Локальная переменная 1              │ ← FP – offset_1
│  ...                                 │
│  Локальная переменная N              │
├──────────────────────────────────────┤
│  Spill-зона для аргументов callee    │   Предвыделено для max args
│  arg[0] (если вызов внутри функции)  │
│  arg[1]                              │
│  ...                                 │
├──────────────────────────────────────┤ ← SP после аллокации фрейма
│  Свободное пространство стека        │
│  ...                                 │
└──────────────────────────────────────┘
Низкие адреса (дно стека, guard на 64)
```

### 2.2. Доступ к локальным переменным

Все локальные переменные адресуются относительно Frame Pointer (RZ):

```
LOAD  Rtmp, RZ[-offset]    ; чтение локальной переменной
STORE RZ[-offset], Rtmp    ; запись локальной переменной
```

Ассемблерный синтаксис (в T3 LOAD/STORE используется LOADI/STOREI):
```
LOADI R0, RZ, -3           ; R0 = local_var_0 (смещение -3 от FP)
STOREI RZ, -5, R0          ; local_var_1 = R0 (смещение -5 от FP)
```

### 2.3. Размер фрейма

Размер фрейма вычисляется компилятором:

```
frame_size = 1 (FP)                     // PUSH RZ
           + (use_R3 ? 1 : 0)           // callee-saved R3
           + (use_R4 ? 1 : 0)           // callee-saved R4
           + (use_F3 ? 1 : 0)           // callee-saved F3
           + (use_F4 ? 1 : 0)           // callee-saved F4
           + local_vars_count           // локальные переменные
           + max_call_args              // spill-зона для вызовов
```

## 3. Передача аргументов

### 3.1. Целочисленные аргументы

| Позиция | Регистр | Примечание |
|---------|---------|------------|
| arg0 | RW | Типы: trit, tryte, tshort, tint, указатель |
| arg1 | RX | |
| arg2 | RY | |
| arg3 | R0 | |
| arg4..N | Стек | Размещаются callER (над своим фреймом), доступ через FP+offset |

**Правила:**
- Аргументы 0..3 передаются в регистрах RW, RX, RY, R0
- Аргументы 4+ передаются через стек, размещаются вызывающим кодом ДО CALL
- Стековые аргументы размещаются по возрастающим адресам: arg4 → arg5 → ... → argN
- Каждый аргумент занимает ровно 1 слово (18 тритов) на стеке, независимо от типа
- Типы размером > 1 слова передаются по ссылке (указатель занимает 1 слово)

### 3.2. Float-аргументы

| Позиция | Регистр FPU | Примечание |
|---------|-------------|------------|
| farg0 | FW | tfloat |
| farg1 | FX | tfloat |
| farg2 | FY | tfloat |
| farg3 | FZ | tfloat |
| farg4..N | Стек | Через FTOI; PUSH (с сохранением в целых слотах) |

**Правила:**
- Float-аргументы используют ОТДЕЛЬНУЮ нумерацию: farg0 может быть передан в FW одновременно с целым arg0 в RW
- Float-аргументы 4+ передаются через стек (FTOI в целый регистр, затем PUSH)
- tdouble (36 тритов) всегда передаётся через стек (FTOI; PUSH для двух половин)

### 3.3. Смешанные аргументы (int + float)

Пример: `tint foo(tint a, tfloat b, tint c, tfloat d)`

```
arg0 (a, int)   → RW
farg0 (b, float) → FW
arg1 (c, int)   → RX
farg1 (d, float) → FX
```

Нумерация целых и float-аргументов независима.

### 3.4. Агрегатные типы (структуры, объединения)

| Размер агрегата | Способ передачи |
|-----------------|-----------------|
| ≤ 3 слов | В регистрах: RW, RX, RY (до 3 слов) |
| > 3 слов | По скрытому указателю: вызывающий аллоцирует копию на стеке, передаёт указатель в RW |

**Пример структуры ≤ 3 слов:**
```c
struct Point { tint x; tint y; };
tint bar(Point p);  // p.x → RW, p.y → RX
```

**Пример структуры > 3 слов:**
```c
struct Big { tint a,b,c,d; };
tint bar(Big b);    // Вызывающий: Big tmp = b; PUSH tmp; LI RW, SP; CALL bar
                    // Вызываемый: LOAD R4, RW[0] — читает поле
```

### 3.5. Порядок вычисления аргументов

Аргументы вычисляются **слева направо** (left-to-right evaluation). Результаты помещаются в регистры или на стек в соответствии с таблицами выше.

## 4. Возврат значений

### 4.1. Целочисленный возврат

| Тип | Регистр(ы) | Примечание |
|-----|-----------|------------|
| void | — | Нет возврата |
| trit, tryte, tshort, tint | R2 | |
| tlong (36 тритов) | R2 (lo), R3 (hi) | R2 = младшие 18 тритов, R3 = старшие 18 тритов |
| tlong long (54 трита) | R2 (lo), R3 (mid), ?? (hi) | Только младшие 36 тритов через R2:R3; старшие 18 — через скрытый указатель |
| Указатель | R2 | 1 слово |

### 4.2. Float-возврат

| Тип | Регистр(ы) | Примечание |
|-----|-----------|------------|
| tfloat | F2 | 18 тритов |
| tdouble | F2 (lo), F3 (hi) | 36 тритов через пару F2:F3 |

### 4.3. Агрегатный возврат

| Размер агрегата | Способ возврата |
|-----------------|-----------------|
| ≤ 2 слов | R2 (lo), R3 (hi) |
| > 2 слов | Скрытый указатель: вызывающий передаёт адрес буфера в RW (до всех явных аргументов), callee пишет результат по этому адресу |

**Пример скрытого указателя:**
```c
struct Big { tint a,b,c,d; };
Big make_big();  
// Компилируется как: void make_big(Big* result_ptr);  // result_ptr в RW
// Вызывающий: SUBI SP, SP, 4; MOV RW, SP; CALL make_big;  // результат на стеке
```

## 5. Последовательность вызова

### 5.1. Полный алгоритм Caller → Callee → Caller

```
=== ВЫЗЫВАЮЩИЙ (CALLER) ===

1. [Liveness] Определить живые caller-saved регистры, которые нужно сохранить
2. [Spill locals] Сохранить живые локальные переменные на стек (если в регистрах)
3. [Save caller-saved GP] PUSH только используемых caller-saved регистров:
   - Если RW жив и не содержит аргумент: PUSH RW
   - Если RX жив и не содержит аргумент: PUSH RX
   - Если RY жив и не содержит аргумент: PUSH RY
   - Если R0 жив и не содержит аргумент: PUSH R0
   - Если R1 жив: PUSH R1 (R1 всегда caller-saved)
   - Если R3 жив и используется как scratch: PUSH R3
   - Если R4 жив и используется как scratch: PUSH R4
4. [Save caller-saved FPU] Для каждого используемого caller-saved FPU регистра:
   - FTOI Rtmp, Fx; PUSH Rtmp
5. [Stack args] Для аргументов 4..N: PUSH arg[N-1]; ...; PUSH arg[4]
6. [Load arg regs] Загрузить аргументы 0..3 в RW, RX, RY, R0
7. [Load farg regs] Загрузить float-аргументы 0..3 в FW, FX, FY, FZ
8. [LIMM + CALL] LIMM R1, target; CALL R1

=== ВЫЗЫВАЕМЫЙ (CALLEE) — Пролог ===

1. PUSH RZ              ; сохранить старый FP
2. MOV RZ, SP           ; FP = SP (начало фрейма)
3. PUSH R3              ; если используется (callee-saved)
4. PUSH R4              ; если используется (callee-saved)
5. FTOI Rtmp, F3; PUSH Rtmp  ; если F3 используется
6. FTOI Rtmp, F4; PUSH Rtmp  ; если F4 используется
7. SUBI SP, SP, local_size  ; аллокация локальных переменных

=== ВЫЗЫВАЕМЫЙ (CALLEE) — Тело ===

... выполнение кода функции ...

=== ВЫЗЫВАЕМЫЙ (CALLEE) — Эпилог ===

1. ADDI SP, SP, local_size  ; освободить локальные переменные
2. POP Rtmp; ITOF F4, Rtmp  ; если F4 сохранялся
3. POP Rtmp; ITOF F3, Rtmp  ; если F3 сохранялся
4. POP R4                    ; если сохранялся
5. POP R3                    ; если сохранялся
6. POP RZ                    ; восстановить FP
7. RET

=== ВЫЗЫВАЮЩИЙ (CALLER) — После возврата ===

1. [Restore FPU] POP Rtmp; ITOF Fx, Rtmp (в обратном порядке)
2. [Restore GP] POP R4; POP R3; POP R1; POP R0; POP RY; POP RX; POP RW
3. [Restore locals] POP Rtmp; STORE local_slot, Rtmp
4. [Read return] MOV result, R2 (и R3 для tlong)
```

### 5.2. Краткий алгоритм (для простых функций)

Для функций без локальных переменных и без вызовов (leaf):

```
CALLER:
    LIMM R1, target
    CALL R1
    MOV result, R2

CALLEE:
    PUSH RZ
    MOV RZ, SP
    ... вычисления ...
    POP RZ
    RET
```

## 6. Пролог и эпилог

### 6.1. Шаблон пролога

```asm
func_name:
    ; Сохраняем старый Frame Pointer
    PUSH RZ
    MOV RZ, SP
    
    ; Сохраняем callee-saved GP (только если используются)
    ; PUSH R3
    ; PUSH R4
    
    ; Сохраняем callee-saved FPU (только если используются)
    ; FTOI R0, F3
    ; PUSH R0
    ; FTOI R0, F4
    ; PUSH R0
    
    ; Аллоцируем локальные переменные
    ; SUBI SP, SP, <local_size>
```

**Пример с 3 локальными переменными, используется R3, F4:**
```asm
my_func:
    PUSH RZ
    MOV RZ, SP
    PUSH R3
    FTOI R0, F4
    PUSH R0
    SUBI SP, SP, 3        ; 3 локальные переменные
```

Состояние стека после пролога:
```
FP (=RZ) → Saved FP (1 слово)
            Saved R3 (1 слово)
            Saved F4 (1 слово, bit-preserving)
            local[0]
            local[1]
            local[2]
SP ──────→ (вершина стека)
```

### 6.2. Шаблон эпилога

```asm
.func_epilogue:
    ; Освобождаем локальные переменные
    ADDI SP, SP, <local_size>
    
    ; Восстанавливаем callee-saved FPU (в обратном порядке)
    ; POP R0
    ; ITOF F4, R0
    ; POP R0
    ; ITOF F3, R0
    
    ; Восстанавливаем callee-saved GP
    ; POP R4
    ; POP R3
    
    ; Восстанавливаем Frame Pointer
    POP RZ
    RET
```

Для функции выше:
```asm
.my_func_epilogue:
    ADDI SP, SP, 3
    POP R0
    ITOF F4, R0
    POP R3
    POP RZ
    RET
```

### 6.3. Генерация return

`return expr;` компилируется в:

```asm
    ; Вычислить выражение, результат в R2
    LIMM R0, .func_epilogue
    JMP R0
```

Не используется RET напрямую — переход на метку эпилога, чтобы гарантировать восстановление регистров.

## 7. Листовые функции (Leaf Optimization)

**Определение:** Leaf-функция — функция, которая не вызывает другие функции (не содержит CALL).

### 7.1. Оптимизированный пролог/эпилог для leaf-функций

Leaf-функция может **не аллоцировать стековый фрейм вообще**, если:
- Не имеет локальных переменных (или все помещаются в scratch-регистры)
- Не использует callee-saved регистры (R3, R4, F3, F4)

```asm
leaf_func:
    ; Нет пролога!
    ... вычисления только в caller-saved регистрах ...
    ; Нет эпилога!
    RET
```

### 7.2. Leaf-функция с локальными переменными

Если leaf-функция имеет локальные переменные, но не вызывает другие функции:
- Аллоцируется минимальный фрейм (без spill-зоны для вызовов)
- Не сохраняются caller-saved регистры в вызывающем коде для этой функции

```asm
leaf_with_locals:
    PUSH RZ
    MOV RZ, SP
    SUBI SP, SP, 2      ; 2 локальные переменные
    ... вычисления ...
    ADDI SP, SP, 2
    POP RZ
    RET
```

### 7.3. Определение leaf-статуса

Компилятор определяет leaf-статус:
1. При парсинге тела функции ищет вызовы функций (CallExpr)
2. Если вызовов нет → leaf = true
3. Для leaf-функций:
   - Не генерируется spill-зона для аргументов callee
   - Вызывающий код не spill'ит регистры перед вызовом leaf-функции (но R1 и R2 всё ещё caller-saved)

## 8. FPU ABI

### 8.1. Сохранение FPU-регистров на стеке

FPU-регистры не имеют прямой инструкции PUSH/POP. Используется bit-preserving round-trip через FTOI/ITOF:

```
; Сохранение Fx на стеке:
FTOI Rtmp, Fx     ; копирует битовое представление T3Float в целый регистр
PUSH Rtmp         ; сохраняет на стеке

; Восстановление Fx со стека:
POP Rtmp          ; читает битовое представление со стека
ITOF Fx, Rtmp     ; восстанавливает T3Float из целого регистра
```

**Важно:** FTOI/ITOF реализованы как bit-preserving операции (без арифметического преобразования). Это гарантирует точное восстановление значений.

### 8.2. Float-аргументы через регистры

```
; Вызов: tfloat foo(tfloat a, tfloat b);
; a → FW, b → FX

; Caller:
FMOV FW, <a_value>     ; или результат вычисления
FMOV FX, <b_value>
LIMM R1, foo
CALL R1
; Результат: FMOV result, F2
```

### 8.3. Float-аргументы через стек

Для farg4 и далее:
```
; tfloat baz(tfloat a, tfloat b, tfloat c, tfloat d, tfloat e);
; farg0..3 в FW,FX,FY,FZ; farg4 (e) — через стек

; Caller:
FMOV FW, a
FMOV FX, b
FMOV FY, c
FMOV FZ, d
FTOI R0, e        ; float → int (bit-preserving)
PUSH R0           ; на стек
LIMM R1, baz
CALL R1
```

### 8.4. Float-возврат

```
; tfloat func():
; ... вычисления ...
FMOV F2, <result>   ; результат в F2 (float return register)
; ... эпилог ...
RET
```

## 9. Агрегатные типы (структуры/объединения)

### 9.1. Размещение в памяти

Поля структуры размещаются последовательно, без выравнивания (packed):

```c
struct Example {
    tryte a;    // 1 слово, смещение 0
    tint b;     // 1 слово, смещение 1
    tfloat c;   // 1 слово, смещение 2
};
// sizeof(Example) = 3 слова
```

### 9.2. Передача структур

**Структуры ≤ 3 слов:** передаются в регистрах RW, RX, RY (каждое поле в своём регистре)

```c
struct Point { tint x; tint y; };
tint dist(Point p);
// p.x → RW, p.y → RX
```

**Структуры > 3 слов:** передаются по скрытому указателю

```c
struct Rect { tint x, y, w, h; };
tint area(Rect r);
// Компилируется как: tint area(Rect* r);
// Вызывающий: аллоцирует Rect на стеке, передаёт указатель в RW
```

### 9.3. Возврат структур

**Структуры ≤ 2 слов:** возвращаются в R2:R3

```c
Point make_point(tint x, tint y) { Point p = {x, y}; return p; }
// p.x → R2, p.y → R3
```

**Структуры > 2 слов:** скрытый указатель в RW

```c
Rect make_rect() { Rect r; ... return r; }
// Компилируется как: void make_rect(Rect* result);
// result в RW — callee пишет по этому адресу
```

## 10. Функции с переменным числом аргументов

### 10.1. Объявление

```c
tint printf(tryte* format, ...);
```

### 10.2. Передача vararg

Для vararg-функций применяются специальные правила:

1. **Все float-аргументы дублируются в целые регистры**: farg0 также помещается в соответствующий целый слот
2. **Аргументы 0..3**: передаются в RW, RX, RY, R0 (и дублируются для float в FW, FX, FY, FZ)
3. **Аргументы 4+**: передаются через стек
4. **Callee НЕ знает типы** — читает аргументы в соответствии с format-строкой

### 10.3. Доступ к vararg в callee

Каждому параметру `...` соответствует слот в регистре или на стеке. Для доступа к vararg используется указатель на стек/регистры:

```c
// Упрощённый va_list: указатель на стековый слот
// va_start(ap, last_named)  — ap = адрес первого vararg
// va_arg(ap, type)          — чтение *ap; ap++
// va_end(ap)                — ничего
```

## 11. Глобальные переменные

### 11.1. Размещение

Глобальные переменные размещаются в секции данных, начиная с адреса, следующего за кодом (определяется `_nextAddr` после генерации кода).

### 11.2. Доступ

```asm
; Загрузка глобальной переменной:
LIMM R4, global_var_addr
LOAD R0, R4             ; R0 = *global_var

; Сохранение в глобальную переменную:
LIMM R4, global_var_addr
STORE R4, R0            ; *global_var = R0
```

### 11.3. Инициализация

Глобальные переменные инициализируются нулём (BSS-стиль). Инициализаторы с ненулевыми значениями не поддерживаются в текущей версии.

## 12. Указатели и адресация

### 12.1. Размер указателя

Указатели всегда занимают 1 слово (18 тритов). Этого достаточно для адресации 1M слов памяти.

### 12.2. Операции с указателями

```c
tint* ptr;
tint val = *ptr;       // LOAD R0, Rptr
*ptr = val;            // STORE Rptr, Rval
ptr++;                 // ADDI Rptr, Rptr, 1 (увеличивается на 1 слово)
ptr += n;              // ADDI Rptr, Rptr, n
tint* ptr2 = ptr + n;  // ADDI R2, Rptr, n
```

Арифметика указателей работает в единицах sizeof(тип). Для tint sizeof = 1 слово, поэтому инкремент указателя = +1.

### 12.3. Нулевой указатель

Нулевой указатель: `NULL = 0` (Word18 со значением 0).

---

## 13. Выравнивание

### 13.1. Выравнивание данных

Все данные выравниваются на границу 1 слова (18 тритов). Стек всегда выровнен на слово, так как PUSH/PUSH работает со словами.

### 13.2. Выравнивание кода

Инструкции размещаются последовательно. LIMM — 2-словная инструкция, занимает ровно 2 слота.

## 14. План реализации

### Фаза 1: Внедрение Frame Pointer (RZ) и изменение пролога/эпилога
- Изменить `CodeGenerator.cs`: `GenFunc()` генерирует новый пролог с `PUSH RZ; MOV RZ, SP`
- Эпилог: `POP RZ; RET`
- Доступ к локальным переменным через RZ-relative (LOADI/STOREI с RZ как база)
- Заменить `_nextAddr`-based абсолютную адресацию на FP-relative

### Фаза 2: Регистровая передача аргументов
- Реализовать передачу первых 4 аргументов через RW, RX, RY, R0
- Изменить `EmitCall()`: args 0..3 → регистры, args 4+ → стек
- Изменить пролог: читать аргументы из регистров (не POP со стека для первых 4)
- Адаптировать тесты

### Фаза 3: Liveness-анализ и выборочный spill
- Заменить полный spill всех caller-saved регистров на spill только живых
- Реализовать простой анализ liveness для регистров
- Сохранять caller-saved регистры только если они содержат живые переменные

### Фаза 4: Leaf-оптимизация
- Определять leaf-функции (без CALL)
- Для leaf-функций: минимальный фрейм (без spill-зоны для callee)
- Для leaf без локальных переменных: фрейм не аллоцируется

### Фаза 5: Multi-word return (tlong)
- Реализовать возврат tlong/tlong long через R2:R3
- Изменить `EmitReturn()` для поддержки парных возвратов

### Фаза 6: FPU ABI
- Float-аргументы через FW-FZ
- Float-возврат через F2
- Callee-saved F3, F4
- Bit-preserving save/restore через FTOI/ITOF

### Фаза 7: Агрегатные типы
- Передача структур ≤ 3 слов в регистрах
- Скрытый указатель для больших структур
- Возврат структур ≤ 2 слов через R2:R3

## 15. Сравнение с ABI v3

| Характеристика | ABI v3 (текущий) | ABI v4 (новый) |
|----------------|------------------|----------------|
| Frame Pointer | Отсутствует | RZ — обязательный FP |
| Аргументы 0..3 | Стек | Регистры RW, RX, RY, R0 |
| Аргументы 4+ | Стек | Стек (как и было) |
| Callee-saved GP | Нет | RZ (FP), R3, R4 |
| Callee-saved FPU | Нет | F3, F4 |
| Float аргументы 0..3 | Стек (FTOI;PUSH) | Регистры FW,FX,FY,FZ |
| Float возврат | R2 через FTOI | F2 |
| Caller save | Все 8 регистров всегда | Только живые регистры |
| Leaf-оптимизация | Нет | Да (без фрейма) |
| Агрегаты | Все через стек | ≤ 3 слов в регистрах |
| tlong возврат | Не определён | R2:R3 |
| Доступ к локалам | Абсолютный адрес (_nextAddr) | FP-relative (RZ ± offset) |
| Сложность реализации | Низкая | Средняя |
| Производительность | Базовая | +40–60% за счёт регистровых аргументов |
| Отлаживаемость | Низкая (нет FP) | Высокая (раскрутка стека) |

## Приложение A: Пример компиляции

### T-lang код:
```c
tint add(tint a, tint b) {
    return a + b;
}

tint main() {
    tint x = add(3, 5);
    return x;
}
```

### Ассемблер (ABI v4):
```asm
; === add (leaf-функция) ===
add:
    PUSH RZ
    MOV RZ, SP
    ; a в RW, b в RX
    ADD R2, RW, RX        ; R2 = a + b
    POP RZ
    RET

; === main ===
main:
    PUSH RZ
    MOV RZ, SP
    PUSH R3                ; callee-saved (будет исп. для x)
    SUBI SP, SP, 1         ; local x
    
    ; Вызов add(3, 5):
    LI RW, 3               ; arg0 = 3
    LI RX, 5               ; arg1 = 5
    LIMM R1, add
    CALL R1
    ; Результат в R2
    MOV R3, R2             ; x = результат
    
    ; return x:
    MOV R2, R3
    LIMM R0, .main_epilogue
    JMP R0

.main_epilogue:
    ADDI SP, SP, 1
    POP R3
    POP RZ
    RET
```
