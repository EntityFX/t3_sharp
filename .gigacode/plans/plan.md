# Полная спецификация троичного процессора T3 (обновлённая версия)

## 1. Введение

Процессор **T3** — семейство троичных вычислительных ядер с единой системой команд, работающих в сбалансированной троичной системе счисления.  \nПоддерживаются две конфигурации разрядности: **T3‑18** (18‑тритное слово) и **T3‑54** (54‑тритное слово).  \nДля T3‑54 реализована VLIW‑микроархитектура (три 18‑тритных слота в одном слове) с предикацией, спекулятивным выполнением и SIMD.

## 2. Базовые типы и форматы данных

### 2.1. Трит, трайт, слово

- **Трит** (`trit`) — минимальная единица информации, значения –1, 0, +1. Обозначается символами `-`, `0`, `+`.
- **Трайт** (`tryte`) — 6 тритов, минимальная адресуемая ячейка памяти. Диапазон: –364 … +364.
- **Слово**:
  - **T3‑18** — 18 тритов (3 трайта).
  - **T3‑54** — 54 трита (9 трайтов). В VLIW‑режиме слово вмещает три 18‑тритных слота.

### 2.2. Представление чисел

Числа хранятся в сбалансированной троичной системе. Отрицательные значения — естественным образом (старший трит `-`).  \nДиапазоны:
- T3‑18: ±(3¹⁸ – 1)/2 = **±193 710 244**
- T3‑54: ±(3⁵⁴ – 1)/2 ≈ **±2.9·10²⁵**

## 3. Регистровая модель

### 3.1. Регистры общего назначения

Девять логических регистров: **RW, RX, RY, RZ, R0, R1, R2, R3, R4** (номера 0–8).  \nКаждый регистр имеет разрядность слова (18 трит в T3‑18, 54 трита в T3‑54).

### 3.2. Специальные регистры

- `SP` — указатель стека (слово)
- `PC` — счётчик команд (слово)
- `Cond` — флаг условия (1 трит, хранится в младшем трите специального 18‑тритного регистра, остальные триты — 0)
- `PR` — предикатный регистр (9 тритов в T3‑18, 27 тритов в T3‑54). В T3‑18 содержит три флага (p0, p1, p2) по 3 трита, в T3‑54 — девять флагов (p0…p8).

## 4. Память и адресация

- Память адресуется словами. Объём физической памяти в симуляторе — 1М слов (1 048 576 слов).
- Адресное пространство — 18 трит (можно адресовать до 3¹⁸ слов ≈ 387 млн слов). Реально используемый объём ограничен настройками симулятора.
- Стек растёт вниз, `SP` указывает на вершину. При старте `SP = MemSize - 1`.
- Режимы адресации:
  - **Регистровая** – `ADD RW, RX`
  - **Непосредственная** – `LI RW, 100t`
  - **Косвенная** – `LOAD RW, RX` (адрес в RX)
  - **Длинная непосредственная** – `LIMM RW, 1000000t` (значение в следующем слове)

## 5. Система команд (ISA)

### 5.1. Формат инструкции (18‑тритное слово)

Инструкция всегда занимает ровно одно 18‑тритное слово. Различаются два подформата:

**R‑тип (регистр–регистр):**

```
[ opcode+pred (6) | op1 (3) | op2 (3) | op3 (3) | резерв (3) ]
```

**I‑тип (регистр–непосредственное значение):**

```
[ opcode+pred (6) | op1 (3) | op2 (3) | imm6 (6) ]
```

Поля:
- `opcode+pred` (6 трит) = базовый_опкод + индекс_предиката * 28.  \nДекодируется: `pred_index = поле / 28`, `базовый_опкод = поле % 28`.
- `op1`, `op2`, `op3` (3 трита каждое) — номер регистра (0–8 соответствует RW…R4) или малая константа (для некоторых инструкций).
- `imm6` (6 трит) — знаковое непосредственное значение в диапазоне –364…+364.
- `резерв` (3 трита) — не используется в текущей версии, должно быть нулевым.

Какая именно инструкция относится к R‑типу, а какая к I‑типу, определяется базовым опкодом. Для удобства ассемблера вводятся мнемоники, например `ADD R0, R1, R2` (R‑тип) и `ADDI R0, R1, 100` (I‑тип, где opcode = ADDI). В таблице опкодов приведены коды для R‑ и I‑типов.

### 5.2. Таблица опкодов (базовые инструкции)

| Код | Мнемоника | Описание | Тип |
|-----|-----------|----------|-----|
| 0 | `HALT` | Останов процессора | – |
| 1 | `LOAD` | `reg = mem[addr_reg]` | R |
| 2 | `STORE` | `mem[addr_reg] = reg` | R |
| 3 | `MOV` | `reg1 = reg2` (op3 игнорируется) | R |
| 4 | `LI` | `reg = imm6` (I‑тип) | I |
| 5 | `LIMM` | `reg = mem[PC]; PC += 1` | R |
| 6 | `ADD` | `reg1 = reg2 + reg3` | R |
| 7 | `SUB` | `reg1 = reg2 – reg3` | R |
| 8 | `MUL` | `reg1 = reg2 * reg3` (результат в слово) | R |
| 9 | `DIV` | `reg1 = reg2 / reg3` (округление к –∞) | R |
| 10 | `MOD` | `reg1 = reg2 % reg3` | R |
| 11 | `NEG` | `reg = -reg2` (op3 игнорируется) | R |
| 12 | `TRITAND` | `reg1 = reg2 & reg3` (потритовый минимум) | R |
| 13 | `TRITOR` | `reg1 = reg2 \| reg3` (потритовый максимум) | R |
| 14 | `TRITXOR` | `reg1 = reg2 ^ reg3` (потритовая сумма) | R |
| 15 | `SHL` | `reg1 = reg2 << reg3` (сдвиг влево на reg3 тритов) | R |
| 16 | `SHR` | `reg1 = reg2 >> reg3` (арифметический сдвиг вправо) | R |
| 17 | `CMP` | `Cond = sign(reg1 – reg2)` | R |
| 18 | `JMP` | `PC = reg1` | R |
| 19 | `JE` | if `Cond == 0` then `PC = reg1` | R |
| 20 | `JNE` | if `Cond != 0` then `PC = reg1` | R |
| 21 | `JL` | if `Cond < 0` then `PC = reg1` | R |
| 22 | `JG` | if `Cond > 0` then `PC = reg1` | R |
| 23 | `JM` | if `Cond == 0` then `PC = reg1` | R |
| 24 | `CALL` | `SP -= 1; mem[SP] = PC; PC = reg1` | R |
| 25 | `RET` | `PC = mem[SP]; SP += 1` | R |
| 26 | `PUSH` | `SP -= 1; mem[SP] = reg1` | R |
| 27 | `POP` | `reg1 = mem[SP]; SP += 1` | R |
| 28–44 | Заре��ервированы для VLIW‑расширений (спекуляция, SIMD, ввод‑вывод) в T3‑54 | |
| 63 | `NOP` | Нет операции | R |
| 65 | `LOADI` | `reg = mem[addr_reg + imm6]` | I |
| 66 | `STOREI` | `mem[addr_reg + imm6] = reg` | I |
| 67 | `MOVI` | `reg = imm6` (op2 игнорируется) | I |
| 68 | `LI_I` | `reg = imm6` (аналог LI, но с отдельным кодом) | I |
| 70 | `ADDI` | `reg1 = reg2 + imm6` | I |
| 71 | `SUBI` | `reg1 = reg2 – imm6` | I |
| 72 | `MULI` | `reg1 = reg2 * imm6` | I |
| 73 | `DIVI` | `reg1 = reg2 / imm6` (округление к –∞) | I |
| 74 | `MODI` | `reg1 = reg2 % imm6` | I |
| 75 | `NEGI` | `reg = -imm6` | I |
| 76 | `TRITANDI` | `reg1 = reg2 & imm6` | I |
| 77 | `TRITORI` | `reg1 = reg2 \| imm6` | I |
| 78 | `TRITXORI` | `reg1 = reg2 ^ imm6` | I |
| 79 | `SHLI` | `reg1 = reg2 << imm6` | I |
| 80 | `SHRI` | `reg1 = reg2 >> imm6` | I |
| 81 | `CMPI` | `Cond = sign(reg1 – imm6)` | I |
| 41 | `IN` | `reg = port[port_reg]` | R |
| 42 | `OUT` | `port[port_reg] = reg` | R |
| 43 | `INI` | `reg = port[imm6]` | I |
| 44 | `OUTI` | `port[imm6] = reg` | I |

**Предикация** – если индекс предиката p ≠ 0 и флаг PR[p‑1] не равен +1, инструкция не выполняется (NOP). Флаги PR размещаются в специальном предикатном регистре (3 флага по 3 трита в T3‑18, 9 флагов в T3‑54).

### 5.3. Векторные операции (только T3‑54)

В T3‑54 слово можно интерпретировать как три 18‑тритных поля. Соответствующие инструкции (VADD3, VSUB3, …) выполняют операцию над каждым полем независимо. Их опкоды начинаются с 28.

## 6. Микроархитектуры

### 6.1. In‑order (T3‑18 и T3‑54)

- Одно универсальное АЛУ, последовательное исполнение.
- Нет конвейера, спекуляции, SIMD.
- Предикация эмулируется.
- Инструкции 28–44 недопустимы.

**Задержки инструкций (такты) для T3‑18 / T3‑54:**

| Инструкция | T3‑18 | T3‑54 |
|------------|-------|-------|
| HALT, MOV, LI, NEG, TRITAND, TRITOR, TRITXOR, CMP | 1 | 1 |
| LOAD, STORE | 2 | 2 |
| ADD, SUB, SHL, SHR | 1 | 1 |
| MUL | 5 | 8 |
| DIV, MOD | 10 | 15 |
| JMP | 1 | 1 |
| JE, JNE, JL, JG, JM | 1 (не перех.) / 2 (перех.) | 1/2 |
| CALL, RET | 2 | 2 |
| PUSH, POP | 2 | 2 |
| LIMM | 2 | 2 |
| IN, OUT, INI, OUTI | 2 | 2 |

### 6.2. VLIW (только T3‑54)

- Три идентичных АЛУ.
- Бандл из трёх 18‑тритных слотов в одном 54‑тритном слове.
- Параллельное выполнение с ограничениями по памяти и переходам.
- Предикация, спекуляция, SIMD.

## 7. Модель времени и аппаратные счётчики

- Частота: 1 ГГц (1 такт = 1 нс).
- Счётчики отображаются на MMIO‑адреса:
  - `CYCLE_LOW` (адрес `0x3FFFF00`) – 18‑тритный счётчик тактов.
  - `INST_COUNT` (`0x3FFFF01`) – количество выполненных инструкций/бандлов.
  - `STALL_COUNT` (`0x3FFFF02`) – количество тактов остановов.
  - `TIMER_CTRL`, `TIMER_CMP` – управление таймером.
- Запись в `CYCLE_LOW` сбрасывает все счётчики.
- В T3‑54 счётчики 54‑тритные, адреса соответственно выше.

## 8. Подсистема ввода‑вывода

- Адресное пространство портов 18‑тритное (до 2¹⁸ = 262144 портов).
- Порты 0–2: stdin, stdout, stderr.
- При отсутствии готовности инструкция `IN` вызывает останов до появления данных.

## 9. Симулятор на C#: архитектура и API

Решение включает проекты:
- `TritTypes` – базовые троичные типы (`Trit`, `Tryte`, `Word18`, `Word54`).
- `T3Simulator.Common` – `IT3Processor`, `ProcessorBase`, `Opcode`, `Instruction`.
- `T3Simulator.InOrder` – Последовательный процессор (T3‑18, T3‑54).
- `T3Simulator.VLIW` – VLIW‑процессор (только T3‑54).
- `T3Assembler` – Ассемблер и компилятор.
- `T3Simulator.CLI` – Консольный симулятор.

API процессора одинаковый для всех конфигураций, типы инструкций и памяти используют 18‑ или 54‑тритные слова.

**Примечание:** FPU (сопроцессор с плавающей точкой) не реализован. Опкоды 92–108 зарезервированы для будущей реализации.

## 11. Примеры кода

Программы используют новые имена регистров RW…R4.

```asm
; сложение двух чисел
LI RW, 10
LI RX, 20
ADDI RY, RW, 30   ; I-тип: RY = RW + 30
ADD RZ, RW, RX    ; R-тип: RZ = RW + RX
HALT
```
