# Nanolib как отдельная библиотека: анализ возможности

**Дата:** 2026-07-01  
**Версия:** v1.0  
**Цель:** Оценить, можно ли вынести nanolib из builtins (C#/asm внутри компилятора/интерпретатора) в отдельную библиотеку на T-lang, которая компилируется в `.o` и линкуется.

## 2. Классификация функций по возможности реализации на T-lang

### 2.1 🟢 Могут быть написаны на чистом T-lang

Эти функции используют только арифметику, циклы, условия и указатели — всё это компилятор поддерживает.

| Функция | Сложность | Зависимости | Примечание |
|---------|-----------|-------------|------------|
| `t_abs(x)` | 🟢 Лёгкая | Нет | `if (x < 0) return -x; else return x;` |
| `t_min(a,b)` | 🟢 Лёгкая | Нет | `return a < b ? a : b;` |
| `t_max(a,b)` | 🟢 Лёгкая | Нет | `return a > b ? a : b;` |
| `clamp(v,lo,hi)` | 🟢 Лёгкая | Нет | `if (v < lo) return lo; ...` |
| `t_strlen(str)` | 🟢 Лёгкая | Указатели | Цикл до `\0` |
| `t_strcmp(a,b)` | 🟢 Лёгкая | Указатели | Цикл сравнения |
| `t_strncmp(a,b,n)` | 🟢 Лёгкая | Указатели | Цикл с лимитом |
| `t_strcpy(dest,src)` | 🟢 Лёгкая | Указатели | Цикл копирования |
| `t_strncpy(dest,src,n)` | 🟢 Лёгкая | Указатели | Цикл с лимитом |
| `t_strcat(dest,src)` | 🟡 Средняя | Указатели | Поиск конца + копирование |
| `t_strchr(str,c)` | 🟢 Лёгкая | Указатели | Поиск символа |

| `t_itoa(val,buf)` | 🟡 Средняя | Указатели | Форматирование числа |

**Итого: ~17 функций** могут быть написаны на чистом T-lang.

### 2.2 🟡 Могут быть написаны на T-lang + inline asm

Эти функции требуют I/O инструкций (`OUT`/`IN`), которые недоступны из T-lang.

| Функция | Что нужно | Примечание |
|---------|-----------|------------|
| `putchar(c)` / `print_char(c)` | `OUT Rx, 0` | Вывод символа на порт 0 |
| `get_char()` | `IN Rx, 0` | Ввод символа с порта 0 |
| `print_int(val)` | `OUT` + арифметика | Вывод десятичного числа |
| `print_str(str)` | `OUT` + цикл | Вывод строки |
| `puts(str)` | `OUT` + цикл | Вывод строки + `\n` |
| `print_long(val)` | `OUT` + арифметика | Вывод tlong (Int128) |
| `print_bal(val)` | `OUT` + BT conversion | Вывод balanced ternary |
| `print_tryte(c)` | `OUT` | Вывод tryte |
| `scan_int()` | `IN` + парсинг | Ввод числа |
| `scan_long()` | `IN` + парсинг | Ввод tlong |
| `print_float(val)` | `OUT` + FPU | Вывод float |
| `scan_float()` | `IN` + FPU + парсинг | Ввод float |
| `print_double(val)` | `OUT` + FPU | Вывод double |
| `scan_double()` | `IN` + FPU + парсинг | Ввод double |
| `t_ftoa(val,buf)` | FPU + строки | Float → строка |
| `t_atof(str)` | FPU + парсинг | Строка → float |

**Итого: ~16 функций** требуют I/O или FPU инструкций.

**Варианты реализации:**
1. **Написать на ассемблере T3** (`.asm`) → ассемблировать в `.o` → линковать
2. **Оставить как builtins** в компиляторе (текущий подход)
3. **Гибрид**: T-lang обёртка + asm-реализация

### 2.3 🔴 Требуют builtin-поддержки компилятора

Эти функции не могут быть реализованы на T-lang или ассемблере без изменений в компиляторе.

| `t_cos(x)` | Требует FPU + ряд Тейлора | 🔴 **Очень сложно** на asm |
| `t_tan(x)` | Требует FPU + ряд Тейлора | 🔴 **Очень сложно** на asm |
| `t_asin(x)` | Требует FPU + ряд Тейлора | 🔴 **Очень сложно** на asm |
| `t_acos(x)` | Требует FPU + ряд Тейлора | 🔴 **Очень сложно** на asm |

## 3. Ограничения компилятора, влияющие на библиотеку

### 3.1 Нет `tfloat` как first-class типа в компиляторе

[`CodeGenerator.cs`](src/T3Compiler/CodeGen/CodeGenerator.cs) поддерживает float через FPU-регистры, но:
- Float-литералы эмиттятся через `.word` + `FLW`
- Float-операции через `FADD`/`FSUB`/`FMUL`/`FDIV`
- Нет способа написать `tfloat sin(tfloat x)` на T-lang — компилятор не генерирует FPU-инструкции для вызовов функций

**Вывод:** Тригонометрические и экспоненциальные функции **невозможно** реализовать на T-lang без расширения компилятора.

### 3.2 Нет `tlong` (Int128) в компиляторе

`tlong` есть только в интерпретаторе. Компилятор не поддерживает 36-тритные целые.

**Вывод:** `t_atol`, `t_ltoa` **невозможно** реализовать на T-lang.

### 3.3 Нет `union` в компиляторе

Не влияет на nanolib напрямую.

### 3.4 Frame Pointer (RZ) не работает

Блокирует любые скомпилированные программы с локальными переменными. Без этого библиотечные функции с локальными переменными не будут работать.

## 4. Архитектура библиотеки

### 4.1 Предлагаемая структура файлов

```
src/T3Compiler/lib/
├── tio.th              # Заголовок (уже есть)
├── tmath.th            # Заголовок (уже есть)
├── tstring.th          # Заголовок (уже есть)
├── tlimits.th          # Заголовок (уже есть)
├── libtstring.t        # 🔄 NEW: строковые функции на T-lang
├── libtio.asm          # 🔄 NEW: I/O функции на ассемблере
├── libtmath.asm        # 🔄 NEW: математические функции на ассемблере
└── libtmath_fp.t       # 🔄 NEW: тригонометрия через ряды Тейлора (опционально)
```

### 4.2 Процесс сборки

```bash
# Шаг 1: Компиляция строковой библиотеки
t3cc -c libtstring.t -o libtstring.o

# Шаг 2: Ассемблирование I/O библиотеки
t3asm --emit-obj libtio.asm -o libtio.o

# Шаг 3: Ассемблирование математической библиотеки
t3asm --emit-obj libtmath.asm -o libtmath.o

# Шаг 4: Линковка с программой пользователя
t3cc -c myprogram.t -o myprogram.o
t3ld -o myprogram.bin myprogram.o libtstring.o libtio.o libtmath.o
```

### 4.3 Что останется builtins

Даже после выделения библиотеки, следующие функции **должны остаться** в компиляторе как builtins:

| Функция | Причина |
|---------|---------|
| `malloc(n)` | Использует HP-регистр, требует специальной codegen-логики |
| `free(ptr)` | Bump allocator no-op |
| `putchar(c)` | Может быть вынесена в asm, но проще оставить как builtin |
| `get_char()` | Может быть вынесена в asm, но проще оставить как builtin |

## 6. Рекомендация

### 6.1 Краткосрочно (сейчас) — текущий подход оптимален

Текущая архитектура (builtins в C# для интерпретатора + asm-эмиссия для компилятора) **является правильной** для текущего состояния проекта, потому что:

1. **Frame Pointer (RZ) сломан** — любые библиотечные функции с локальными переменными не будут работать
2. **Nested calls сломаны** — библиотечные функции не могут вызывать helper-функции
3. **Тригонометрия требует C# `Math.*`** — реализация sin/cos через ряды Тейлора на asm — это сотни строк сложного кода
4. **tlong не в компиляторе** — `t_atol`/`t_ltoa` нереализуемы на T-lang

### 6.2 Среднесрочно (после фикса RZ и nested calls)

1. Починить RZ и nested calls
2. Написать `libtstring.t` — 17 чистых T-lang функций (~400 LOC, ~6 ч)
3. Написать `libtio.asm` — I/O функции на ассемблере (~300 LOC, ~5 ч)
4. Интегрировать в процесс сборки: `t3cc -c` → `.o` → `t3ld` → `.bin`

### 6.3 Долгосрочно (после tlong в компиляторе)

1. Добавить `tlong` в компилятор
2. Написать `t_atol`/`t_ltoa` на T-lang
3. Рассмотреть тригонометрию через ряды Тейлора (или оставить как builtins)

## 7. Пример: как будет выглядеть `libtstring.t`

```c
#include <tstring.th>

// t_strlen — длина строки
tint t_strlen(tryte* str) {
    tint len = 0;
    while (*str != 0) {
        len = len + 1;
        str = str + 1;
    }
    return len;
}

// t_strcmp — сравнение строк
tint t_strcmp(tryte* a, tryte* b) {
    while (*a != 0 && *b != 0) {
        if (*a < *b) return -1;
        if (*a > *b) return 1;
        a = a + 1;
        b = b + 1;
    }
    if (*a < *b) return -1;
    if (*a > *b) return 1;
    return 0;
}

// t_abs — абсолютное значение
tint t_abs(tint x) {
    if (x < 0) return -x;
    return x;
}

// t_min — минимум
tint t_min(tint a, tint b) {
    if (a < b) return a;
    return b;
}

// t_max — максимум
tint t_max(tint a, tint b) {
    if (a > b) return a;
    return b;
}
```

**Проблема:** Этот код не скомпилируется, пока RZ и nested calls не работают. Функции используют локальные переменные (`len`, `a`, `b`) — это требует рабочего frame pointer.

## 8. Итоговый вывод

| Аспект | Оценка |
|--------|--------|
| **Техническая возможность** | ✅ **Да, возможно** — линкер готов, формат .o работает |
| **Когда делать** | ⏳ **После фикса RZ и nested calls** — иначе библиотека не будет работать |
| **Объём работ** | ~750 LOC, ~18 часов (без тригонометрии) |
| **Что останется builtins** | `malloc`, `free`, тригонометрия (sin/cos/tan/asin/acos/atan/exp/log/pow) |
| **Приоритет** | 🟡 Средний — текущий подход (inline asm) работает и не требует изменений |

**Рекомендация:** Зафиксировать текущее состояние как v2.3, починить RZ и nested calls (Priority 1), и только после этого выделять nanolib в отдельную библиотеку.
