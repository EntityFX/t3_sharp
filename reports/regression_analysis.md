# Анализ регрессий при переходе на ABI v4

Переход на новую спецификацию ABI v4 (внедрение полноценного стекового фрейма с использованием регистра `RZ` в качестве Frame Pointer) вызвал временный всплеск падений существующих тестов. Ниже приведено описание основных причин и исправлений.

## Основные причины регрессий

### 1. Ошибки смещения локальных переменных
**Проблема:** В ранних реализациях ABI v4 расчеты смещений в методах `LoadV` и `StoreV` не учитывали все элементы, помещаемые в стек во время пролога функции. 
**Детали:** Пролог функции теперь сохраняет:
1. Старый `RZ` (Old FP)
2. Регистр `R3`
3. Регистр `R4`
Это создает смещение в 3 слова перед началом области локальных переменных. Ошибочный расчет смещения приводил к тому, что компилятор пытался читать/писать данные в области сохраненных регистров, вызывая повреждение состояния процессора и некорректные результаты вычислений.

### 2. Ошибка "off-by-one" в доступе к аргументам
**Проблема:** Неверный расчет индекса при загрузке аргументов функции, передаваемых через стек (аргументы с 4-го и далее).
**Детали:** Поскольку `RZ` указывает на сохраненный `RZ` в стеке, аргументы, которые были пушнуты вызывающей стороной *до* вызова, находятся по положительным смещениям. Ошибка в расчете (`+1` вместо `+2`) приводила к тому, что функция читала адрес возврата или предыдущий `RZ` вместо фактического значения аргумента.

### 3. Коррупция регистров в `EmitCall` (Save/Restore Order)
**Проблема:** Порча регистра `R0` при сохранении FPU-регистров перед вызовом функции.
**Детали:** В `EmitCall` для сохранения FPU-регистров использовался `R0` как scratch-регистр (`FTOI R0, Fx` -> `PUSH R0`). Однако это происходило *до* того, как оригинальное значение `R0` (которое в ABI v4 используется для передачи 4-го аргумента) было сохранено в стек. В результате вызываемая функция получала в `R0` значение последнего сохраненного FPU-регистра вместо ожидаемого аргумента.

## Итоги исправлений
Все вышеуказанные проблемы были решены путем:
*   Корректировки формул смещения локальных переменных: `offset = -(3 + slotIndex)`.
*   Исправления базового смещения для стековых аргументов: `stackOff = (i - 4) + 2`.
*   Изменения порядка сохранения регистров в `EmitCall`: сначала сохраняются все General Purpose регистры (включая `R0`), и только затем используется `R0` для сохранения FPU-стека.
