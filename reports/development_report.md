# Отчет о разработке симулятора процессора T3Sharp
**Дата:** 23 июня 2026 г.
**Статус:** Стабилизирован (v2.0)

## 1. Введение
Проект T3Sharp представляет собой программную реализацию симулятора процессора с использованием сбалансированной тернарной логики (Trit-based computing). Архитектура процессора ориентирована на In-Order исполнение инструкций с поддержкой расширенного набора операций, включая FPU, механизм предикации, стековые фреймы и компилятор T-lang.

## 2. Техническая реализация

### 2.1. Типы данных и представление
Реализованы основные типы данных для тернарных вычислений:

- **Word18**: 18-тритный тип, хранящийся в `int` (32 бита). Диапазон: ±193,710,244. Поддерживает арифметические операции (+, -, *, /, %), сдвиги (<<, >>), потритовые операции (AND, OR, XOR), конвертацию в/из строки тритов.
- **Word54**: 54-тритный тип для повышенной точности, использующий `Int128`. Диапазон: ±2.9×10²⁵.
- **T3Float**: 18-тритный формат с плавающей точкой (6 тритов экспоненты + 12 тритов мантиссы). Смещение (bias) экспоненты: 182. Кодирование: линейное `value = exponent * 3^12 + mantissa`.
- **T3Double**: 36-тритный формат двойной точности (8 тритов экспоненты + 28 тритов мантиссы). Смещение: 3280.

**Важное замечание о кодировании T3Float**: 
- `ToWord18()` использует прямое линейное кодирование: `exponent * 3^12 + mantissa`. Это корректно, так как оба поля являются сбалансированными значениями, и операция умножения/сложения работает с целыми числами.
- `FromWord18()` использует деление и модуль: `exponent = raw / 3^12`, `mantissa = raw % 3^12`. Это корректно благодаря линейности кодирования — переносы в сбалансированном троичном представлении не влияют на целочисленное деление.
- **Не использовать строковое кодирование** (`ToTritString`/`FromTritString`) для T3Float — функция `ExtractBalancedTrit` имеет фундаментальную проблему с переносами (carry propagation) для значений, где переносы затрагивают старшие позиции.

### 2.2. Архитектура процессора
Реализован класс `T3InOrderProcessor<TWord>`, который моделирует интерпретатор с циклом Fetch-Decode-Execute:

1. **Fetch**: Извлечение инструкции из памяти по адресу PC.
2. **Decode**: Декодирование через `InstructionDecoder.Decode()` — извлекает Pred (3 трита, raw unsigned), Opcode (6 тритов, raw unsigned), и аргументы (9 тритов) с последующим разбором на Op1/Op2/Op3 (R-type), Op1/Imm (I-type) или Reg (J-type).
3. **Predicate Evaluation**: Проверка флагов в регистре `PR`. `GetPredicateFlag(predIndex)` читает триты 0, 1, 2 из PR (LSB-first). Если `pred > 0`, инструкция выполняется только если `PR[pred-1] == +1`.
4. **Execute**: Выполнение операции через `T3Alu` (целочисленные операции) или `T3Fpu` (FPU операции).
5. **Write-back**: Обновление регистров или памяти.

### 2.3. Кодирование инструкций (18 тритов)

```
[Pred (3)] [Opcode (6)] [Args (9)]
```

- **R-type**: Args = `[Op1(3)] [Op2(3)] [Op3(3)]` — три регистровых операнда
- **I-type**: Args = `[Op1(3)] [Imm(6)]` — регистр + непосредственное значение (±364)
- **J-type**: Args = `[Reg(3)] [000000]` — регистр для перехода, 6 тритов padding (всегда 0)

**Encoder** (`InstructionEncoder`):
- `EncodeR(pred, opcode, op1, op2, op3)` — кодирует R-type
- `EncodeI(pred, opcode, op1, imm)` — кодирует I-type
- `EncodeJ(pred, opcode, reg)` — кодирует J-type
- Все операнды преобразуются в unsigned через `ToUnsignedField(value, range, offset)`: `value + offset` где `offset = (3^width - 1) / 2`

**Decoder** (`InstructionDecoder`):
- `Decode(Word18 word)` — декодирует 18-тритное слово
- `Decode(Word54 word)` — декодирует 54-тритное слово (использует `Word18.FromWrappedLong()` для извлечения младших 18 тритов)
- Pred и Opcode извлекаются как raw unsigned через `ExtractRawField`
- Аргументы извлекаются как raw unsigned, затем sub-поля конвертируются в balanced через вычитание offset
- Для J-type: `imm = 0` (6 тритов padding)

### 2.4. Регистровая модель

| Имя | Trit | Phys | FPU | Назначение | Caller-saved |
|-----|------|------|-----|-----------|--------------|
| RW  | -4   | 0    | FW  | Временный | Да |
| RX  | -3   | 1    | FX  | Временный | Да |
| RY  | -2   | 2    | FY  | Временный | Да |
| RZ  | -1   | 3    | FZ  | Временный | Да |
| R0  | 0    | 4    | F0  | Временный | Да |
| R1  | +1   | 5    | F1  | Call temp | Да |
| R2  | +2   | 6    | F2  | Return value | Нет (не сохраняется) |
| R3  | +3   | 7    | F3  | Временный | Да |
| R4  | +4   | 8    | F4  | Address register | Да |

Специальные регистры: SP (стек), PC (счётчик команд), Cond (1 трит: -1/0/+1), PR (9 тритов = 3×3 флага предикации).

### 2.5. Предикация (Conditional Execution)

Механизм предикации позволяет условно выполнять инструкции на основе флагов в регистре PR.

- PR — 9-тритный регистр, разделённый на 3 группы по 3 трита (p0, p1, p2)
- Поле Pred в инструкции (3 трита) содержит номер группы предикации (1, 2, 3) или 0 (всегда выполнять)
- `GetPredicateFlag(predIndex)` читает триты 0, 1, 2 из PR (LSB-first):
  - `PR.GetTrit(0)` — флаг для predicate 1
  - `PR.GetTrit(1)` — флаг для predicate 2
  - `PR.GetTrit(2)` — флаг для predicate 3
- Если значение трита == +1, предикация истинна, инструкция выполняется
- Если значение трита == 0 или -1, инструкция пропускается

**Важно**: `Word18.GetTrit(index)` использует LSB-first индексацию (позиция 0 = LSB, позиция 17 = MSB). Для установки PR:
- Predicate 1 → `PR = Word18.FromLong(1)` (3^0 = trit 0)
- Predicate 2 → `PR = Word18.FromLong(3)` (3^1 = trit 1)
- Predicate 3 → `PR = Word18.FromLong(9)` (3^2 = trit 2)

### 2.6. FPU (T3Float)

FPU регистры (FW..F4) отображаются на те же физические слоты, что и целочисленные (RW..R4), но хранят `T3Float` значения.

**Формат T3Float**: 6 тритов экспоненты (bias=182), 12 тритов мантиссы.
- Значение: `mantissa * 3^(exponent - 182)`
- Диапазон экспоненты: ±364
- Диапазон мантиссы: ±88,573
- Кодирование в Word18: `value = exponent * 3^12 + mantissa` (линейное)

**Операции FPU**: FADD, FSUB, FMUL, FDIV, FSQRT, FABS, FNEG, FCMP, FTOI, ITOF, FLW, FSW, FMOV, FCLASS, FSWAP, FZERO.

**Важное замечание**: T3Float использует прямое арифметическое кодирование/декодирование, а не строковое. Строковое кодирование через `Word18.ToTritString()` не работает корректно для значений с переносами между полями экспоненты и мантиссы.

### 2.7. Память и стек

- 1M слов (1,048,576) Word18/Word54
- Стек растёт вниз, SP инициализируется значением MemSize-1
- PUSH: `SP--; Memory[SP] = value`
- POP: `value = Memory[SP]; SP++`
- CALL: `SP--; Memory[SP] = PC + 1; PC = target`
- RET: `PC = Memory[SP]; SP++`
- MMIO: CYCLE_LOW, CYCLE_HIGH, INST_COUNT, STALL_COUNT

### 2.8. Компилятор T-lang (ABI)

**Calling Convention**:
1. **Caller** (перед CALL):
   - Сохраняет caller-saved регистры (RW, RX, RY, RZ, R0, R1, R3, R4) через PUSH
   - Передаёт аргументы через PUSH в обратном порядке
   - Загружает адрес функции через LIMM и выполняет CALL
   - После возврата: POP аргументов, POP восстановление регистров
   - Копирует R2 (return value) в выделенный регистр

2. **Callee** (пролог):
   - Метка функции
   - PUSH всех регистров (кроме R2 — return value не сохраняется)
   - Выделение фрейма для локальных переменных

3. **Callee** (эпилог):
   - POP всех регистров (кроме R2)
   - RET

4. **R2** (return value register): Не сохраняется/восстанавливается в прологе/эпилоге. Caller копирует значение из R2 после возврата.

**Генерация кода**:
- `_nextAddr` начинается с 300 (данные), код размещается последовательно с адреса 0
- `return` генерирует `LIMM` + `JMP` на метку эпилога (не `RET` напрямую)
- Аллокатор регистров (round-robin) пропускает R1 (call temp), R2 (return value), R4 (address register)

## 4. История исправлений

### Phase 1: Предикация
- **Проблема**: Тесты устанавливали `PR = Word18.FromLong(531441)` (3^12, trit 12), но `GetPredicateFlag` читает триты 0, 1, 2.
- **Исправление**: Изменены PR значения в тестах на `Word18.FromLong(1)` (3^0 = trit 0 = predicate 1).

### Phase 2: Дизассемблер
- **Проблема**: J-type инструкции использовали `PhysOp2` вместо `PhysOp1`.
- **Исправление**: Изменено на `PhysOp1` в `T3Disassembler.FormatInstruction`.

### Phase 3: InstructionDecoder.Decode(Word54)
- **Проблема**: `Decode(Word54)` вызывал `Word18.FromLong()` который падал для значений вне 18-тритного диапазона.
- **Исправление**: Использован `Word18.FromWrappedLong()`.

### Phase 4: Ассемблер — silent error handling
- **Проблема**: `P9()`/`P27()` возвращали пустую строку для неизвестных символов.
- **Исправление**: Добавлен `throw new FormatException()` в default-case.

### Phase 5: Компилятор — silent fallback
- **Проблема**: Неизвестные выражения → `Imm(0)`, неизвестные идентификаторы → `LI r,0`, неизвестные операторы → `ADD`.
- **Исправление**: Заменено на `throw new NotSupportedException()`.

### Phase 6: ABI компилятора для рекурсии
- **Проблемы**: `_nextAddr = 200` в каждой функции (перезапись данных), регистры не сохранялись при вызовах, `return` генерировал `RET` напрямую (минуя эпилог), R2 сохранялся/восстанавливался (перезапись return value).
- **Исправления**:
  - `_nextAddr` изменён с 200 на 300 (предотвращение перекрытия кода и данных)
  - Добавлен пролог (PUSH всех регистров кроме R2) и эпилог (POP + RET)
  - `return` генерирует `LIMM` + `JMP` на метку эпилога
  - R2 исключён из save/restore (caller-saved, хранит return value)
  - Caller сохраняет caller-saved регистры перед CALL и восстанавливает после

### Phase 7: T3Float round-trip
- **Проблема**: `T3Float.ToWord18()` и `FromWord18()` использовали строковое кодирование через `Word18.ToTritString()`, которое вызывало `ExtractBalancedTrit` — функцию с ошибкой в обработке переносов (carry propagation).
- **Исправление**: Переход на прямое линейное арифметическое кодирование: `value = exponent * 3^12 + mantissa`.

### Phase 7b: ExtractBalancedTrit
- **Проблема**: Функция использовала `(value / power) % 3` что даёт стандартные троичные цифры, затем отображала 2→-1. Не обрабатывала переносы из младших позиций.
- **Исправление**: Переписана с использованием алгоритма сбалансированного троичного переноса — итерация от позиции 0 до запрошенной позиции с обработкой переносов на каждом шаге.

### Phase 8: T3ConversionService
- **Проблема 1**: `Hex = value.ToString("X")` выдавал `"2A"` без префикса `0x`.
- **Исправление 1**: Добавлены префиксы ко всем форматам вывода: `0x`, `0b`, `00`, `0t`, `0n`, `0y`.
- **Проблема 2**: `catch { value = 0; }` проглатывал все исключения, возвращая некорректный результат вместо проброса `FormatException`.
- **Исправление 2**: Заменён на корректную обработку исключений с пробросом `FormatException`.

## 5. Известные ограничения

1. **Round-robin аллокатор регистров**: Не учитывает liveness регистров, может переиспользовать регистр, который ещё нужен. Для сложных выражений с глубоким вложением может генерировать некорректный код.
2. **Параметры функций**: Передаются через стек, но текущая реализация не извлекает их в прологе функции (используются глобальные переменные).
3. **Word54 в FPU**: T3Double (36 тритов) не полностью интегрирован в конвейер процессора.
4. **Производительность**: Интерпретатор, не cycle-accurate. Timing-таблица в спецификации является справочной.
5. **Регистровое окно (Register Window)**: Запланированная архитектурная возможность, не интегрирована в модель исполнения.
